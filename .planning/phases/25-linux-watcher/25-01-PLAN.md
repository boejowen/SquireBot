<shutdown_seam_note>
CONFIRMED FROM SOURCE — do NOT assume "already covered":
`internal/system/shutdown_signal_other.go::WaitForShutdown(ctx)` on `!windows` spawns `go func(){ <-ctx.Done(); close(done) }()` and returns `done`. It watches ONLY `ctx.Done()` — it does NOT register any OS-signal handler. Therefore a SIGTERM from systemd's `systemctl --user stop` is NEVER observed by `WaitForShutdown` on Linux; without an explicit signal handler in `run_other.go`, the daemon is SIGKILL'd with no graceful unwind, and the body `go func(){ <-WaitForShutdown(ctx); cancel() }(); <-ctx.Done()` is a circular tautology that nothing external ever triggers. The signal handler below is therefore MANDATORY, not optional.
</shutdown_seam_note>

<go_stdlib_note>
`os.UserConfigDir()` (stdlib) returns `$XDG_CONFIG_HOME` or `~/.config` on Unix and `%AppData%` on Windows — so for config we still branch on `runtime.GOOS` to keep Windows on `%LOCALAPPDATA%` (NOT `%AppData%`, which is what UserConfigDir returns). `$XDG_STATE_HOME` has NO stdlib helper → hand-roll (`os.Getenv("XDG_STATE_HOME")`, fallback `filepath.Join(home, ".local/state")`). No new dependency (RESEARCH §6 / "Why no XDG library").
</go_stdlib_note>
