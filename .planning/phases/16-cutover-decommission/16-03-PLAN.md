## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| maintainer dev box → Hetzner VPS (deploy) | Cross-compiled server binary + frontend bundle cross into the live production host. |
| `mint-code` plaintext → Discord DM | A freshly minted bearer token (plaintext, shown once) crosses out-of-band to one guildie. |
| guildie watcher → backend (`/whoami`, ingest) | The pasted guild code authenticates the watcher to the live ingest API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-11 | Information disclosure | the minted plaintext codes | mitigate | Stored ONLY as SHA-256 hashes server-side (the existing `mint-code` path); plaintext is transient — held only long enough to DM 1:1, never logged, never committed, never broadcast (the Task 2/3 handling rules). A leaked code is per-guildie (blast radius = one owner), not a shared master. |
| T-16-12 | Spoofing | a guild code in transit | accept | Codes are DM'd over Discord (the same trust channel that is the P15 login gate). The guild is ~12 known people. Out-of-band distribution is the locked design (D-07); no lower-trust channel is used. |
| T-16-13 | Tampering | the live deploy | mitigate (inherited) | Standard `docs/backend-deploy.md` posture: the binary is cross-compiled from the verified tree, scp'd over SSH (key-auth), and the unit restarted; `goose up` is a no-op (no migration). The Caddy-no-duplicate-CORS deploy-time check prevents a broken cross-origin response. No new attack surface beyond the already-reviewed char-meta endpoint. |
| T-16-14 | Repudiation / accountability | who flipped whom | accept | Each guildie's first upload binds their code→owner server-side; the `mint-code` action is maintainer-initiated on the box. The audit trail of writes is the char-meta/coin audit_log (Plan 01). Sufficient for a ~12-person guild. |
| T-16-15 | DoS (stranded guildie) | the no-%%-gate flip | accept | D-08: no migration-percentage gate; stragglers onboard whenever and decommission strands no one (the frozen Sheet already offers nothing; the upgrade path is GitHub). Accepted thinner-coordination margin per the locked decision. |

**Net posture:** the flip rides entirely on proven infrastructure (the deploy runbook, the existing hashed-at-rest `mint-code`, the P13 auto-update + DPAPI onboarding). The one sensitive element — plaintext guild codes — is mitigated by hash-at-rest + transient 1:1 out-of-band distribution. No new code, no new secret class, no HIGH-severity unmitigated threat.
