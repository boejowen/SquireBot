## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17.01-01 | Information disclosure | guard.go widened SELECT | mitigate | Still SELECT only id/owner_id/token_hash; the presented token is sha256'd before compare and never logged (existing `auth_reject` records carry no token material — unchanged). |
| T-17.01-02 | Tampering | partial unique index | mitigate | `CREATE UNIQUE INDEX ... WHERE discord_user_id IS NOT NULL` is the backstop against a racing double-stamp of one Discord id onto two owners (surfaces as a constraint error, not silent corruption). |
| T-17.01-03 | Denial of service | ingest hot path | accept | last_seen stamp is a separate best-effort UPDATE outside the replace tx; a failed/slow stamp logs (no token) and does not fail or block the ingest. ~12-guildie volume — no write-amplification concern (RESEARCH A1). |
| T-17.01-04 | Tampering | 00005 on live DB | mitigate | Forward-only; 00001-00004 untouched; existing owner rows get NULL discord_user_id (NULL is FK-exempt, no retroactive scan); goose.Up idempotent on restart. |
