## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client officer gate → server | Settings→Admin section visibility is client UX; the Go `RequireOfficer` re-check on every admin endpoint is the real boundary |
| Discord identity / wantlist text → DOM | usernames + user-entered wantlist/notification content render in the rehomed surfaces |
| theme context → [data-theme] writer | the relocated picker mutates theme through a context bridge; only +layout writes the attribute |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-05 | Elevation of Privilege | Settings→Admin section gate | mitigate | `{#if isOfficer}` (from `SESSION_KEY` context) suppresses the Admin section + its search hits for non-officers — Layer-1 UX ONLY. The Go API (`webadmin`) re-checks officer on every admin write and `authGuard` collapses the gate on a 403; the hidden section is NEVER the boundary. The plan must not present the client gate as access control (acceptance asserts the gate wraps the panels; the server check is unchanged and untouched). No officer-only data is shipped to a non-officer's bundle beyond what `/admin` already shipped. |
| T-30-06 | Tampering/Elevation (XSS) | Wishlist + Settings rehomed surfaces + settings-search echo | mitigate | All rehomed panels are mounted 1:1 (already XSS-safe); the settings-search "No settings match \"{query}\"" echo renders `{query}` via plain `{}` (auto-escaped); acceptance greps `{@html` = 0 on both new route bodies |
| T-30-07 | Tampering | single [data-theme] writer | mitigate | The relocated ThemePicker writes through the THEME_KEY context to +layout's existing `theme` state; SettingsThemePicker contains NO `applyTheme` (asserted) → no second writer can drift the attribute |
| T-30-08 | Information Disclosure | settings-search over Admin keywords | accept | Admin keywords are only reachable when the Admin section renders (officer), so a non-officer typing "admin" matches nothing — no officer-surface disclosure; low risk, gated by the same isOfficer check |
</threat_model>
