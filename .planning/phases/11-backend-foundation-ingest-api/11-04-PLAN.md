<objective>
Build the bearer-token authentication layer (BACKEND-04): the `mint-code`/`revoke-code` CLI subcommands (mint a 32-byte `crypto/rand` opaque token, print the base64url plaintext ONCE, store only its SHA-256 hash; revoke by setting `disabled_at`), and the request-time guard `resolveToken` that hashes a presented `Authorization: Bearer <code>` and constant-time-compares it against active `guild_code` rows. This is **verdict-agnostic** crypto + DB logic - the guard function is imported unchanged by 11-05 whether the HTTP shell is PocketBase (a custom `func(*core.RequestEvent) error` guard) or net/http (middleware), and the mint/revoke CLI is wired into `cmd/squirebot-server` in 11-05.

Purpose: BACKEND-04 + the ASVS L1 V2/V6 controls (opaque high-entropy token, SHA-256 hash-at-rest, `crypto/subtle.ConstantTimeCompare`, 401-writes-nothing). This is the project's first authenticated network surface, so the crypto must be stdlib (never hand-rolled) and the plaintext must exist only at mint time (hash-only storage, mirroring the watcher's DPAPI hash-only discipline).

Output: `internal/backendsrv/auth/` (mint.go, guard.go, store.go) with crypto/round-trip/timing-table unit tests. Pure Go, deterministic - runs in CI on the Windows dev box.
</objective>

    const p = "Bearer "
    if !strings.HasPrefix(authHeader, p) { return 0, false }       // malformed -> 401

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client Authorization header -> auth layer | The presented Bearer token is untrusted attacker-controllable input; it must be hashed and constant-time-compared, never logged, and a non-match must reveal nothing. |
| mint CLI stdout -> maintainer | The plaintext code crosses to the maintainer exactly once via stdout; it is never persisted and never logged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.04-01 | Spoofing | Token brute-force / guessing | mitigate | 32-byte (256-bit) `crypto/rand` tokens are infeasible to brute-force; a non-match returns (0,false) revealing nothing (V2). Optional Caddy rate-limiting noted for 11-06 but unnecessary at 12 users. |
| T-11.04-02 | Information Disclosure | Timing attack on token comparison | mitigate | `crypto/subtle.ConstantTimeCompare` on the hash bytes (D-08 / Pattern 3); acceptance criteria grep-check enforces its presence. |
| T-11.04-03 | Information Disclosure | Token leakage in logs | mitigate | Store only `sha256(plaintext)` (never the plaintext); never pass the token or Authorization header to slog; the plaintext exists only at mint via explicit stdout (V6/V7). |
| T-11.04-04 | Elevation | Revoked code still authenticates | mitigate | `WHERE disabled_at IS NULL` excludes revoked rows from the candidate set; `RevokeCode` sets `disabled_at`; `TestResolveToken_Table` revoked case proves (0,false) (D-09). |
| T-11.04-05 | Tampering | SQL injection via the presented token in the lookup | mitigate | The token is SHA-256-hashed before any DB use and the query uses no user-supplied SQL fragment (the WHERE filters only on `disabled_at`); mint/revoke use `?` placeholders (V5). |
| T-11.04-06 | Spoofing | Weak/predictable token from a non-crypto RNG | mitigate | `crypto/rand` only (never `math/rand`); acceptance criteria grep-check forbids `math/rand` (V6; mirrors the watcher's pkce.go shape). |

The 401-writes-nothing wiring is completed in 11-05 (the handler returns before any store call when `ok==false`).
