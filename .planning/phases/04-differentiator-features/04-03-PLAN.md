### Task 1 — wiki-gear-tier-types.ts

```typescript
export type Tier = 'Velious Pre-Raid/Group' | 'Velious Raiding' | 'Iksar';

export interface WikiGearTierRow {
  tier: Tier;
  class: string;        // 3-letter abbrev
  slot: string;         // wiki vocab: Head, Chest, Primary, Ears, etc.
  item_id: number | null; // NULL — wiki transclusions don't expose IDs
  item_name: string;    // verbatim, parenthetical notes stripped
  rank: number;         // 1-based position in the slot's recommendation list
  last_refreshed: string;
}

export type GearTierParseResult =
  | { ok: true; rows: WikiGearTierRow[]; classCount: number; itemCount: number; unknownSlots: string[] }
  | { ok: false; reason: 'wikitext_too_short' | 'no_class_sections'; detail?: string };
```

### Task 2 — wiki-gear-tier-parser.ts

`parseGearTierPage(wikitext: string, tier: 'Velious Pre-Raid/Group' | 'Velious Raiding'): GearTierParseResult`

Algorithm per RESEARCH §2:
1. If wikitext.length < 200: return wikitext_too_short.
2. Split wikitext on `^==\s*\[\[([^\]]+)\]\]\s*==$` (multiline) — capture class display names + section bodies.
3. If 0 class headers found: return no_class_sections.
4. For each (className, sectionBody):
   a. Map className → 3-letter abbrev via `CLASS_DISPLAY_TO_ABBREV[className]`. Skip if not in map.
   b. Find all `<li>...</li>` blocks (regex `/<li[^>]*>([\s\S]*?)<\/li>/g` with non-greedy match).
   c. For each `<li>` block:
      - Extract slot via `/'''([^']+)'''/`. Trim.
      - Track unknown slots (not in WIKI_SLOT_TO_INV_SLOTS) for the warning collection.
      - Extract items via `/\{\{:([^}]+)\}\}/g`. For each: trim + strip parenthetical notes via `s.replace(/\s*\([^)]*\)\s*/g, '')`.
      - For each item with rank = position + 1:
        - **Iksar tagging:** if `tier === 'Velious Pre-Raid/Group'` AND `itemName.startsWith('Iksar ')`, override `effectiveTier = 'Iksar'`. Else `effectiveTier = tier`.
        - Emit `WikiGearTierRow { tier: effectiveTier, class: classAbbrev, slot, item_id: null, item_name, rank, last_refreshed: now }`.
5. Return `{ ok: true, rows, classCount, itemCount, unknownSlots }`.

**Tests** (`apps-script/src/__tests__/wiki-gear-tier-parser.test.ts`):
- Pre-Raid fixture: parses successfully; classCount=14; emits ~480+ rows; some rows have tier='Iksar' (count > 20); rest have tier='Velious Pre-Raid/Group'.
- Raiding fixture: parses successfully; classCount=14; ZERO Iksar-tier rows (all 'Velious Raiding'); rows count similar.
- Specific item check: a known Iksar item (e.g., "Iksar Hide Cap" from Monk Pre-Raid section) emits with `tier: 'Iksar'` AND `class: 'MNK'` AND `slot: 'Head'`.
- Specific non-Iksar item: "Cloak of Flames" (if present) emits with regular `tier: 'Velious Pre-Raid/Group'`.
- Parenthetical stripping: input `{{:Spirit Wracked Cord}} (Chardok 2.0)` emits `item_name: 'Spirit Wracked Cord'` (note that `(Chardok 2.0)` is OUTSIDE the {{:}} so it's not in the captured name — but if a name contains parens internally like `Whetstone (Worn)` the strip applies).
- Empty wikitext: wikitext_too_short.
- Wikitext with no `==` headers: no_class_sections.
- Unknown slot label tracking: synthetic input with `'''GreaterEars'''` produces `unknownSlots: ['GreaterEars']`.

**Replacement strategy** (different from refreshWikiSpells):
Since there are only 2 pages and they collectively define the entire `_wiki_gear_tier` content, do a full clear+rewrite at the end:
```typescript
function replaceAllWikiGearTier(allRows: WikiGearTierRow[]): void {
  const sheet = getActiveSpreadsheet().getSheetByName('_wiki_gear_tier');
  const lastRow = sheet.getLastRow();
  if (lastRow > 1) sheet.getRange(2, 1, lastRow - 1, 7).clearContent();
  if (allRows.length > 0) {
    const dataRows = allRows.map(r => [r.tier, r.class, r.slot, r.item_id ?? '', r.item_name, r.rank, r.last_refreshed]);
    sheet.getRange(2, 1, dataRows.length, 7).setValues(dataRows);
  }
}
```

This means the cursor pattern needs adjustment: only checkpoint AFTER both fetches succeed, not per-fetch (since partial writes would leave the table in an inconsistent state). For 2 fetches the cursor is overkill; use it for consistency but with a single end-of-run write.

### Task 4 — buildGearCheck builder

Clone buildSpellCheck.ts as template. Adapt:

```typescript
const GEAR_CHECK_TAB = 'gear_check';
const GEAR_CHECK_HEADERS = ['Char', 'Class', 'Tier', 'Slot', 'Have', 'Recommended', 'Status'];
const TIER_SORT_ORDER = { 'Velious Pre-Raid/Group': 1, 'Velious Raiding': 2, 'Iksar': 3 };
const GEAR_CHECK_LAST_BUILD_PROP = 'gear_check_last_build_ms';

export function buildGearCheck(): void { /* lock+debounce+runBuild */ }

function runBuild(startMs: number): void {
  const ss = getActiveSpreadsheet();
  const sheet = ss.getSheetByName(GEAR_CHECK_TAB);
  if (!sheet) return;

  const chars = readCharOwnerWithMetadata(ss);  // chars with class+race+level set
  const wikiGear = readWikiGearTier(ss);  // Map<tier, Map<class, WikiGearTierRow[]>>
  const charInventories = readInventoriesByChar(ss); // Map<char, InvRow[]>

  const rows: unknown[][] = [];
  for (const c of chars) {
    if (!c.class) continue;
    const tiersToShow = ['Velious Pre-Raid/Group', 'Velious Raiding'];
    if (c.race === 'IKS') tiersToShow.push('Iksar');
    for (const tier of tiersToShow) {
      const tierMap = wikiGear.get(tier) ?? new Map();
      const classGear = tierMap.get(c.class) ?? [];
      // Group by slot to determine OK/MISSING/OTHER per slot
      const bySlot = groupBy(classGear, g => g.slot);
      for (const [slot, recommendations] of bySlot) {
        const invSlots = WIKI_SLOT_TO_INV_SLOTS[slot] ?? [];
        const charItemsInSlots = (charInventories.get(c.char_name) ?? [])
          .filter(it => invSlots.includes(it.location));
        for (const rec of recommendations) {
          const matched = charItemsInSlots.find(it =>
            it.itemName.toLowerCase() === rec.item_name.toLowerCase()
          );
          let status: 'OK' | 'MISSING' | 'OTHER';
          let have = '';
          if (matched) { status = 'OK'; have = matched.itemName; }
          else if (charItemsInSlots.length > 0) { status = 'OTHER'; have = charItemsInSlots[0].itemName; }
          else { status = 'MISSING'; have = ''; }
          rows.push([c.char_name, c.class, tier, slot, have, rec.item_name, status]);
        }
      }
    }
  }
  rows.sort(/* char asc, tier (per TIER_SORT_ORDER) asc, slot asc */);
  // clear + setValues + applyTheme + writeMetaRow status
}
```

Helpers (in same file or shared):
- `readWikiGearTier(ss): Map<string, Map<string, WikiGearTierRow[]>>` — group by tier then by class.
- `readInventoriesByChar(ss): Map<string, Array<{location, itemName, itemId}>>` — iterate inv:* tabs.
- `readCharOwnerWithMetadata` shared with buildSpellCheck.

**Tests** (`apps-script/src/__tests__/buildGearCheck.test.ts`):

- Char with race=IKS: gets Iksar tier rows in addition to Pre-Raid + Raiding.
- Char with race=HUM: NO Iksar tier rows.
- OTHER status: char has an item in HEAD slot that doesn't match the recommended.
- MISSING status: char has nothing in HEAD slot.

- Char without metadata (no class): skipped entirely.
- Lock contention returns silently.
- Sort order verified: char asc, then tier-rank order, then slot.
- applyTheme called.
