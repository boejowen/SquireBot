## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → API | The frontend is never the gate; api.ts sends only character_id / assignee / request_id / mode and relies on the server (26-02) for all authorization. |
| non-officer → /admin (typed URL) | Layer-1 `{#if !isOfficer}` refusal + AuthGuard 403 collapse are UX; the server re-check is the real boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-15 | Elevation | non-officer reaching AssignmentAdminPanel via typed /admin URL | accept (UX) / mitigate (server) | The Layer-1 `{#if !isOfficer}` refusal + the AuthGuard 403 collapse are UX only; the server's RequireOfficer + in-tx IsOfficerTx (26-02) is the actual gate. The panel renders nothing useful to a non-officer because every fetch 403s. |
| T-26-16 | Tampering (XSS) | rendering character names / assignee / error codes | mitigate | Every interpolation uses plain `{}` (Svelte auto-escape) — NEVER the `{@html}` raw directive (the WatcherCodesPanel rule). A bogus character/owner name cannot inject markup. |
| T-26-17 | Spoofing | client supplying an actor identity | mitigate | api.ts member bodies carry ONLY character_id; the actor is the session cookie the server reads (26-02). No frontend path sends a discord_user_id actor. |
| T-26-18 | Information disclosure | a 401/403 leaking via an uncaught throw | mitigate | getJSON/postJSON throw typed Unauthenticated/Forbidden; the panels route 401→LoginScreen (AuthGuard) and 403→officers-only collapse — no stack/detail surfaces to the user. |
</threat_model>
