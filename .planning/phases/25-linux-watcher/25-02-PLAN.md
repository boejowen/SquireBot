## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stdin (terminal/SSH) → onboarding | The guildie pastes the bearer guild code over stdin; it must reach credstore without leaking to logs/journal |
| guild_code file → other local users | A static reusable bearer token at rest; must be 0600, per-user, never world-readable |
| WINE prefix tree → walk | Untrusted-shaped filesystem (symlinks into host fs, huge trees) walked during discovery |
| os.Args (--status output) → shared terminal/journal | --status output may land in a shared shell history / systemd journal |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-05 | Information disclosure | credstore guild_code file (LNX-02) | mitigate | 0600 file via atomic tmp+rename (fresh file → mode honored even over a pre-existing loose-perm file, RESEARCH Pitfall 4); 0700 dir; test asserts Mode().Perm()==0o600 |
| T-25-06 | Information disclosure | --status / onboarding logging the token (LNX-04, V7) | mitigate | --status prints "configured"/"not configured", never the code; dialog_other.go never slogs the code; acceptance greps enforce no slog in store_other.go and no token-print in --status |
| T-25-07 | Denial of service / traversal | eqfind WINE walk (LNX-03) | mitigate | Depth cap (5) + 30s context timeout + prune list + filepath.WalkDir (NO symlink follow) carried from heuristic_windows.go — a symlink loop or huge tree can't hang the walk |
| T-25-08 | Spoofing | attacker plants sentinel pair in a WINE prefix (LNX-03) | accept | Local-only watcher; the user owns their filesystem (carried T-04-05 from the Windows heuristic); the CLI prompt is the override |
