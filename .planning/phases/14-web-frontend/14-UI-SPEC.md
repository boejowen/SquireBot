# Phase 14 — UI Design Contract

> Visual and interaction contract for the SvelteKit web frontend (WEB-01..05 + BACKEND-05). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack is LOCKED (CONTEXT D-01..D-10):** SvelteKit (adapter-static) + TanStack Table + Tailwind CSS, Go read API. The shadcn gate is **N/A** (shadcn is React-centric). The app is **greenfield** — no `components.json` / `tailwind.config` / `svelte.config` / `.svelte` files exist yet (confirmed by codebase scout 2026-05-30); this phase creates them. All tokens below are derived from `docs/design/eq-aesthetic-theme.md` + `apps-script/src/lib/themes.ts` (the CLAUDE.md theme-derivation rule), not from a detected design system.
>
> **Multi-theme system (D-06):** this is a **5-theme** site (Vanilla / Kunark / Velious / Minimalist / Heavy), **default = `velious`**, selected per-user via `localStorage` and a picker in the site shell. The single-palette tables below use the **velious** default; the other four palettes are catalogued in [§ Theme Catalog](#theme-catalog-5-themes--web-05) and remain sourced from `eq-aesthetic-theme.md`. Tokens are emitted as CSS custom properties on a `[data-theme]` root so a theme swap is a single attribute change.
>
> **Phase scope:** P14 is **read-only — no login, no writes, no destructive actions.** Login (Discord) and admin write forms are P15; cutover is P16.

## Spacing Scale

Declared values (8-point scale, multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge inset, dense intra-cell spacing |
| sm | 8px | Grid cell vertical padding, chip gaps, filter-input inset |
| md | 16px | Default element spacing, grid cell horizontal padding, tooltip inner padding, search-box padding |
| lg | 24px | Card / panel padding, gap between toolbar and grid |
| xl | 32px | Section gaps, header/footer vertical padding, page gutters (desktop) |
| 2xl | 48px | Major section breaks, empty-state vertical centering block |
| 3xl | 64px | Page-level top/bottom whitespace on wide viewports |

**Grid density:** cells use `sm` (8px) vertical × `md` (16px) horizontal padding — compact enough that a ~150-row consolidated view stays scannable without feeling cramped. The sticky header reuses the same horizontal padding.

**Exceptions:**
- **Touch targets:** interactive controls on touch (theme picker option, item link / tooltip trigger, "did you mean?" suggestion, dismiss control) get a **44px minimum hit target** (W3C/Apple touch guidance) via padding even where the visible glyph is smaller. 44 is not on the 4-scale by coincidence with the tokens, but is an intentional, documented a11y exception.
- **Hairline borders:** 1px row/column separators and the sticky-header underline are sub-token by nature (borders, not spacing) and are exempt from the scale.

## Typography

Exactly **4 sizes, 2 weights** (regular 400 + semibold 600). `--font-body` and `--font-display` are theme-swapped CSS variables (see Theme Catalog); weights and the size ramp are theme-invariant.

| Role | Size | Weight | Line Height | Font var |
|------|------|--------|-------------|----------|
| Body | 16px | 400 | 1.5 | `--font-body` (grid cells, tooltip body, search results, form labels) |
| Label | 13px | 600 | 1.3 | `--font-display` (column headers, status badges, table-section labels, theme-picker label) — uppercase + ~0.08em letter-spacing for the EQ "engraved header" feel from the mockups |
| Heading | 20px | 600 | 1.2 | `--font-display` (view title, search panel title, empty/error-state heading) |
| Display | 28px | 600 | 1.2 | `--font-display` (site wordmark in the shell header only) |

**Notes:**
- The Minimalist theme intentionally renders `--font-display` at weight **400** for headers/labels (its registry value is `Inter`/`Cinzel` light-touch) — the executor MUST allow a per-theme `--weight-display` override (400 for minimalist, 600 elsewhere). This is the one sanctioned weight-variance and it stays within the 2-weight budget per theme.
- Heavy uses `MedievalSharp` as `--font-display`; it has no real weight axis, so 600 is approximated by the face itself — acceptable.
- Monospace is **not** used. Prices and counts render in `--font-body` tabular figures (`font-variant-numeric: tabular-nums`) so columns align.

## Color

Single-palette table uses the **velious default** (D-06). Values are the canonical `themes.ts` / mockup velious tokens. All colors are CSS custom properties; a theme swap re-points them (Theme Catalog has all five).

| Role | Value (velious) | Usage |
|------|-------|-------|
| Dominant (60%) | `#060b18` (page bg) / `#0f1729` (panel/grid surface) | App background + grid/panel/tooltip surfaces. The two-step dark base is the "60%". |
| Secondary (30%) | `#1a2438` (header-strip gradient top) / `#d4dee8` (body text) / `#4a6585` (borders, dividers, sticky-header rule) | Structural chrome: table header strip, row separators, panel borders, secondary text. |
| Accent (10%) | `#a8c5e0` (icy blue) | **Reserved-for list below — never "all interactive elements".** |
| Destructive | — (n/a in P14) | **No destructive actions in P14** (read-only). Token intentionally unset; do not introduce a red "danger" affordance this phase. |

**Accent (`#a8c5e0`) reserved for, and ONLY for:**
1. Column-header text + the 2px header underline (the "engraved header" accent).
2. Item links (`Item` cells) and the in-tooltip wiki `<a>` link — underline/`border-bottom` in accent.
3. Active/focused state of the search box and the active filter control (focus ring).
4. The selected theme indicator in the picker, and the active view tab.
5. The "did you mean?" suggestion (it is a clickable accent link).
6. Lucide icons (search, external-link, theme, sort caret) at small sizes.

Body text, counts, prices, inactive controls, row backgrounds, and zebra striping do **not** use accent.

**Status colors (semantic, OUTSIDE the 60/30/10 accent budget — they are data encoding, not chrome):**

These map the EQ HP/mana color language and match v1 conditional-formatting semantics exactly. Velious-default values from the mockup; each theme defines its own `--status-*` triple (Theme Catalog).

| Status | Token (velious) | Applies to |
|--------|-----------------|------------|
| OK / KNOWN (have it) | `--status-ok` `#6fc8b0` (teal-green) | `gear_check` Status = OK; `spell_check` Status = KNOWN |
| MISSING (don't have it) | `--status-missing` `#e88a8a` (rose-red) | `gear_check` Status = MISSING; `spell_check` Status = MISSING |
| OTHER (have something else in slot) | `--status-other` `#a8c5e0` (neutral accent) | `gear_check` Status = OTHER only |

Status renders as a **text badge**: the status word (`OK` / `MISSING` / `OTHER` / `KNOWN`) in `--status-*` color at Label type (13px/600), with a subtle (~8% alpha) tinted background pill. Color alone is not the only signal — the literal word is always present — so the encoding survives color-blindness and theme contrast variance.

**Last-Synced freshness (view + bank only):** v1 colored the `Last Synced` cell green/amber/red at <7d / <30d / ≥30d. Port this as a small freshness dot or cell tint reusing `--status-ok` (<7d) → `--status-other`/amber (<30d) → `--status-missing` (≥30d). This is data encoding, not chrome; keep it subtle (dot or faint tint, not a full-saturation fill).

**Contrast:** all five themes are dark-leaning except their parchment data rows (Heavy). The executor MUST verify body text vs surface meets WCAG AA (4.5:1) per theme; the velious `#d4dee8` on `#0f1729` and status words on their tinted pills already clear AA. Heavy's dark ink (`#3a2817`) on parchment (`#c9b072`) also clears AA — keep those pairings when porting.

## Grid Contract (WEB-01 / WEB-02) — TanStack Table

The "high-level grid behavior" the CONTEXT explicitly delegated to this step. One reusable `DataGrid` instantiated 4×. **Column order, names, and status semantics are load-bearing — they mirror the v1 builders exactly so WEB-02 parity is provable.**

**Universal grid behavior (all 4 views):**
- **Leading `Char` column is sticky** (frozen left) and the **header row is sticky** (frozen top) — together they reproduce what the Sheet froze for free.
- **Sorting:** every column sortable (click header → asc → desc → none; accent caret shows direction). Default sort matches v1: **Char asc**, then the view's secondary keys (below).
- **Filtering:** a **global filter** input (filters across all columns) **plus** per-column filter inputs (text contains; the Status/Tier/Class columns may use a faceted select of their distinct values). Filtering is client-side over the fetched rows (data is tiny — ~12 users).
- **No pagination** (data volume is small per D-01 discretion); the grid scrolls within a fixed-height region under the sticky header. If a single view ever exceeds ~2k rows, virtualize rows (TanStack virtual) — not expected in P14.
- Zebra striping via `:nth-child` at ~4–5% accent alpha (matches the mockups); row hover at the same tint.

**Per-view columns (exact, from the v1 builders):**

| View | Columns (in order) | Secondary sort | Special cells |
|------|--------------------|----|----|
| `view` | Char · Slot · Item · ID · Count · Wiki · Price · Last Synced | item asc, then location | `Item` = accent link + tooltip trigger; `Wiki` = external-link icon `<a>`; `Price` = `<n>pp` tabular; `Last Synced` = freshness dot/tint |
| `gear_check` | Char · Class · Tier · Slot · Have · Recommended · Status | tier rank (Pre-Raid→Raiding→Iksar), then slot, then recommended | `Status` = `StatusCell` (OK/MISSING/OTHER); `Recommended` = tooltip trigger |
| `spell_check` | Char · Class · Level · Spell · Status | level asc, then spell asc | `Status` = `StatusCell` (KNOWN/MISSING) |
| `bank` | Char · Slot · Item · ID · Count · Wiki · Price · Last Synced | item asc, then location | same as `view`; **coin is null/0 in P14** (ADMIN-05 populates it in P15) — render a "Coin: not yet recorded" affordance, do not fabricate zeros as real data |

**Status legend:** show a compact legend (OK / MISSING / OTHER swatches + words) near the `gear_check` and `spell_check` grids so a first-time viewer reads the color encoding without guessing.

**Responsive:** the grid is the one place horizontal scroll is acceptable on narrow viewports — keep `Char` sticky, let the rest scroll horizontally rather than reflowing columns. Toolbar (search/filter/global-filter) stacks above the grid on small screens.

## Item Tooltip Contract (WEB-04)

Rich-HTML popover composed by the **ported `composeNotes.ts`** (now real HTML — the 50KB plain-text cell-note cap is gone). Trigger: **hover on pointer devices, tap/click on touch.** Dismiss on **outside-tap or Esc**. Anchored to the `Item` / `Recommended` cell; flips to stay in viewport.

**Content order (mirrors `composeItemNote`):**
1. **Item name** (Label type) + a real wiki `<a href="…wiki.project1999.com…">` (accent, opens new tab, `rel="noopener"`), shown with the external-link icon.
2. **Wiki summary** paragraph (Body type) — from `item_master.wiki_summary`. Omit the block if absent.
3. **Price lines** — `Recent ask: <n>pp (30d avg, <t> transactions)` (WTS) and/or `Buy posts: <n>pp (30d avg, <t> transactions)` (WTB). If neither exists: `No recent transactions on PigParse.`
4. **Quest flag** — `Quest item: yes (in-game flag)` when `is_quest_item`.
5. **Quest links** — `Used in quests: <name>, <name>, …` (max 5).

**Safety:** the ported composer returns HTML built from server data; the executor MUST escape all interpolated strings (item/char/location/quest names, summary) before injecting — carry forward the v1 trust-boundary note (searchIndex.ts header) that user/wiki-controlled strings are escaped at the presentation layer. No `{@html}` on un-escaped content.

**Visuals:** tooltip surface = panel token (`--panel`), `md` (16px) padding, `lg` max-width ~360px, panel border in `--border`, subtle shadow. Body text at 16px/1.5. No animation beyond a fast fade (respect `prefers-reduced-motion`).

## Search Contract (WEB-03)

Cross-character fuzzy search, client-side over the already-fetched `view` rows (ported `searchIndex.ts`; data ~12 users so <2s is trivial). **Fix the two carried bugs during the port: 999.28 (`didYouMean('')` empty-query) and 999.30 (Levenshtein contract).**

**Behavior:**
- A single `SearchBox` (placeholder + search icon) in the site shell or atop the views. Case-insensitive substring match grouped by item name.
- **Results** show, per matched item: the item name (+ id, de-emphasized), then one line per holder — `↳ <Char>: <Location>, count <n>` — surfacing **which character(s) and location(s) hold it** (the core-value framing). Groups with >5 holders auto-collapse (v1 `COLLAPSE_THRESHOLD`).
- **"Did you mean?" (D-09):** only when a query returns **no exact match**, show a **single clickable inline suggestion** of the best fuzzy hit (`didYouMean` top result). Copy: `Did you mean <suggestion>?` where `<suggestion>` is the accent link; clicking it re-runs the search with that term.
- Each result item name is itself a tooltip trigger + wiki link (same `ItemTooltip`).

## Copywriting Contract

P14 has **no primary CTA in the marketing sense** and **no destructive actions** (read-only). The "primary action" is search; the meaningful copy is the empty / error / loading / no-results states. All copy is plain, guild-casual, and tells the viewer the next step.

| Element | Copy |
|---------|------|
| Primary action label | **Search items** (search box placeholder: `Search items across the guild…`) |
| Empty state heading (no data at all) | **No characters yet** |
| Empty state body | `No one's uploaded inventory yet. Once a guildie's watcher syncs, their characters show up here automatically.` |
| Empty state — single view has no rows | heading **Nothing to show here** · body `No <view> data for any character yet — it'll appear after the next sync.` (substitute the view's friendly name: "inventory" / "gear check" / "spell check" / "bank") |
| No search results (with suggestion) | **No matches for "<query>"** · body renders the `Did you mean <suggestion>?` accent link (D-09) |
| No search results (no suggestion) | **No matches for "<query>"** · body `Try a shorter or different spelling.` |
| Error state (read API fetch failed) | heading **Couldn't load the data** · body `The SquireBot server didn't respond. Check your connection and try again.` + a **Retry** button (re-fires the fetch) |
| Loading state | A skeleton/spinner with text `Loading…` (grid shows shimmer rows under the sticky header; keep it brief — payloads are small) |
| Bank coin not yet recorded | `Coin: not yet recorded` (P15's bank-coin form will fill this; never show a fabricated `0 pp`) |
| Footer attribution (required) | `Item & class data from the Project 1999 Wiki (CC-BY-SA) and PigParse.` |
| Destructive confirmation | **None — P14 has no destructive actions.** (Eviction/admin writes are P15.) |

**Tone rules:** sentence case for body copy, Title/short for headings; no exclamation-heavy marketing voice; the EQ flavor lives in the *visuals* (fonts/colors), not in jokey microcopy — keep copy clear so a non-EQ viewer still understands "what's missing, where is it."

## Accessibility & Interaction Notes

- **Keyboard:** grid headers sortable via Enter/Space; search box and "did you mean?" reachable by Tab; tooltip openable via keyboard focus on the trigger and dismissable with Esc; theme picker is a native control. Visible focus ring in `--accent`.
- **Touch:** 44px min targets (see Spacing exceptions); tooltips open on tap and dismiss on outside-tap.
- **Reduced motion:** honor `prefers-reduced-motion` for theme/tooltip/hover transitions.
- **noindex (D-05):** emit `<meta name="robots" content="noindex">` + a `robots.txt` disallow — "public" = anyone with the link, not search-indexed. (Frontend obligation, recorded here so the executor doesn't miss it.)
- **Color is never the only signal:** status words, freshness via position/text, and legends back every color encoding.
