<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser session → account endpoints | Authenticated guildie; identity is the session cookie (RequireSession), never request-body fields. |
| guildie A → guildie B's codes | Authorization boundary: A must never list/revoke B's codes (IDOR). |
| mint → credential | Plaintext code crosses to the page once; hash-only at rest; never logged/audited. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17.02-01 | Spoofing | owner derivation | mitigate | Owner is `ResolveOrCreateOwnerByDiscordTx(callerID)` where callerID = `caller(ctx)` (session); the request body carries NO owner/label (D-02). The v1 `mint-code --owner` free-text path is deleted. |
| T-17.02-02 | Elevation / IDOR | revoke + list | mitigate | `ListOwnCodes`/`RevokeOwnCodeTx` are owner-scoped (`WHERE owner_id = ?` resolved from the session). Cross-owner revoke is RowsAffected=0 no-op (never leaks existence). Do NOT reuse the owner-unscoped `auth.RevokeCode`. |
| T-17.02-03 | Tampering | owner mis-adoption | mitigate | D-04 guard: 2+ label matches OR a match already stamped with a different discord_user_id → ErrAmbiguousOwner + `slog.Warn`, never silent attach to another guildie's characters. |
| T-17.02-04 | Information disclosure | mint plaintext / audit | mitigate | Plaintext only in the HTTP body once; `MintCodeForOwnerTx` has no stdout/slog of the code; audit detail carries owner_id/code_id ONLY (V6/V7). |
| T-17.02-05 | Repudiation | mint/revoke | mitigate | `AppendAuditTx("code_mint"/"code_revoke", actor=callerID)` in the same tx as the write (atomic write+trail). |
| T-17.02-06 | Spoofing (CSRF) | state-changing POSTs | mitigate | New POSTs register under the same `RequireSession` + the existing CORS/credential wrap as the coin/char-meta login-only block (same mux, same protections — no new exposure). |
</threat_model>
