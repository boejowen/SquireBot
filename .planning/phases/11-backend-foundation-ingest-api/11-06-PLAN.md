## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet (HTTPS :443) -> Caddy | The public edge; Caddy terminates TLS and is the only externally-reachable app port. |
| Caddy -> Go server (loopback :8090) | Plain HTTP on loopback only; never exposed publicly. |
| Firewall (ufw, + optional Hetzner Cloud Firewall) -> host | Admits only 22/80/443; `ufw` works normally on Hetzner (no Oracle iptables trap). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.06-01 | Information Disclosure / Tampering | Plaintext HTTP (no/invalid TLS) exposes uploads + tokens in transit | mitigate | Caddy auto-HTTPS provisions a valid Let's Encrypt cert with modern TLS defaults (V6); the runbook verifies an external curl gets a valid cert. HTTP is redirected to HTTPS by Caddy default. |
| T-11.06-02 | Elevation | The Go server runs as root / with excess privilege | mitigate | systemd `User=squirebot` (a system user, no home) + `NoNewPrivileges=true`; the server binds loopback:8090 (no privileged port - Caddy fronts 443). |
| T-11.06-03 | Denial of Service | The backend vanishes (host gone) | mitigate | Hetzner is a paid, always-on VPS — the Oracle Always-Free idle-reclamation risk is ELIMINATED (no keep-alive cron needed). Restart-on-reboot is T-11.06-04. |
| T-11.06-04 | Denial of Service | A reboot leaves the backend down | mitigate | systemd `Restart=always` + `WantedBy=multi-user.target` + `enable`; reboot-survival is an explicit acceptance criterion. |
| T-11.06-05 | Spoofing / Tampering | The firewall is left wide open, or `ufw enable` locks out SSH | mitigate | `ufw` allows ONLY 22/80/443 (allow SSH BEFORE `ufw enable` to avoid lockout); optional Hetzner Cloud Firewall mirrors it.
