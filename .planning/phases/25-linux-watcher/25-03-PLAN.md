<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Release asset → auto-updater download | The Linux watcher downloads + executes a binary from the release; arch/integrity must be guaranteed |
| install.sh → user's home + systemd user manager | A script run with the guildie's own privileges that installs an autostart unit |
| latest.json (one manifest, all OSes) → per-OS selection | A Linux box must never apply the Windows .exe over its ELF |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-10 | Tampering | auto-update applies a wrong-arch/forged binary (LNX-05, RESEARCH Pitfall 3) | mitigate | OS-specific asset selection (binaryAsset by GOOS) so a Linux box only ever fetches the linux `squirebot`; the EXISTING mandatory SHA-256 verify in check.go (binSHA) + swap.go is unchanged and gates the swap — a hash mismatch aborts before Apply |
| T-25-11 | Integrity | tarball binary differs from the auto-update binary | accept | Both the tarball binary and the bare `squirebot` asset are built from the SAME `go build` output in the same job; the manifest hashes the bare binary (what the updater swaps). The tarball is install-only; the updater swaps the separately-hashed bare asset. |
| T-25-12 | Elevation | systemd unit runs with excess privilege (LNX-05) | mitigate | It is a USER unit (no root); `NoNewPrivileges=true`; no ProtectHome only because the EQ-folder read requires $HOME access (documented trade-off, RESEARCH §3) |
| T-25-13 | Tampering | install.sh enables linger unexpectedly (24/7 run) | mitigate | Linger is OFF by default and only enabled inside the explicit `--linger` flag branch (acceptance asserts enable-linger is conditional); README documents the trade-off |
| T-25-14 | Repudiation | re-tagged release drifts manifest hashes | accept | Carried known issue (release.yml comment lines ~248-255): latest.json is regenerated each run with current SHAs, so the auto-updater is always correct; only the human-readable release body can drift |
</threat_model>
