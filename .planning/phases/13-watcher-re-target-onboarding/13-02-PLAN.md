## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watcher process → backend over TLS | The new outbound authed client carries the bearer guild code in transit |
| guild code at rest (DPAPI wincred) | The plaintext code persists on the guildie's disk, DPAPI-encrypted |
| user → native input dialog | The pasted code crosses from the clipboard/keyboard into process memory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13.02-01 | Information Disclosure | Guild code intercepted in transit | mitigate | The client POSTs only to the configured `https://` base (TLS via Caddy/Let's Encrypt). Document/enforce HTTPS: the default base is HTTPS; a plain-http base is an advanced/self-host action. Never POST over plain HTTP for the canonical host. |
| T-13.02-02 | Information Disclosure | Guild code stolen from disk | mitigate | DPAPI encryption-at-rest keyed to the user profile (`wincred.PersistLocalMachine`); the code is NEVER in config.json (credstore SECURITY doc + the acceptance grep) or logs (V7). |
| T-13.02-03 | Information Disclosure | Guild code / raw content leaked via logs or a crash | mitigate | V7: the client logs only char/kind/status/err — never the `Authorization` value or `content`. Asserted by the no-secret-in-logs behavior. |
| T-13.02-04 | Denial of Service | A bad/revoked code hammering the backend in a retry loop | mitigate | 401/409/426 are TERMINAL — the client returns immediately, never retries (RESEARCH Pitfall 5; asserted "401 case made exactly 1 request"). Only network/5xx retry, bounded to 3 attempts with backoff. |
| T-13.02-05 | Tampering / Spoofing | A forged base URL (if config-overridable) redirecting uploads | mitigate | The base URL has a hardcoded HTTPS default (Plan 03 wires the config field with that fallback); document that overriding it is an advanced action and pin the scheme to HTTPS. (The override field itself is wired in Plan 03; this client just uses whatever base it's given — Plan 03 owns the HTTPS-pinning of the configured value.) |
| T-13.02-06 | Spoofing | A clipboard/shoulder-surf capture of the code at paste time | accept | The native dialog is a local, user-initiated action on the guildie's own machine; the code is single-purpose and revocable server-side (`revoke-code`). Local-machine capture is out of scope at this scale (ASVS L1, accepted; the v1 OAuth flow had the same local-trust assumption). |

Severity: all LOW. This plan ADDS one outbound TLS client + one DPAPI credential helper + one local native dialog — and removes (in Plan 03) the inbound loopback OAuth/picker listeners. Net attack-surface change is a REDUCTION. None trips block_on:high.
