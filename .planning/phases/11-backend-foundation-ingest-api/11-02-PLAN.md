<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go process ↔ SQLite file | The DB handle is the sole writer; single-writer discipline (SetMaxOpenConns(1)) prevents interleaved writes. No untrusted input crosses here in this plan (ingest is 11-05). |
| migration FS ↔ DB | Embedded SQL is trusted (compiled into the binary); goose applies it forward-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.02-01 | Tampering | FK actions (ON DELETE CASCADE) silently ignored because foreign_keys pragma not set per-connection | mitigate | `foreign_keys(ON)` is in the DSN (Pattern 5) so EVERY pooled conn gets it (it is NOT persistent); `TestOpen_ForeignKeysEnabled` proves it on a fresh connection. |
| T-11.02-02 | Denial of Service | SQLITE_BUSY under concurrent ingest+read corrupts or drops a write | mitigate | `busy_timeout(5000)` + `_txlock=immediate` + `SetMaxOpenConns(1)` (Pattern 5 / Pitfall 4) serialize writes and eliminate BUSY at 50–150 writes/day. |
| T-11.02-03 | Tampering | A partial migration run leaves the schema half-applied and unrecoverable | mitigate | goose wraps each migration version and tracks applied versions in `goose_db_version`; a fresh re-run resumes/no-ops. `TestRunMigrations_Idempotent` proves replay safety (BACKEND-02). |
| T-11.02-04 | Information Disclosure | DSN or DB path logged with future secrets | accept | The DSN contains no secret in P11 (just a file path + pragmas); CLAUDE.md/V7 habit of not logging connection strings is followed. Low risk. |

ASVS L1 V5 (Input Validation): parameterized SQL is enforced from 11-03 onward; this plan only runs trusted embedded DDL. No network surface is introduced here.
</threat_model>
