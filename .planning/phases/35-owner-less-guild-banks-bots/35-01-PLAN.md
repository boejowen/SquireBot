<objective>
Make a designated guild bank/bot GUILD-HELD rather than tied to whoever uploaded it first. Today `character.owner_id` is a `NOT NULL REFERENCES owner(id)` first-sighting steward marker; a bank like `Findom` is bound to an individual owner (e.g. owner 9), so (a) designating requires that the char already exist under some owner, and (b) the per-owner eviction cascade (`UPDATE character … WHERE owner_id = ?`) sweeps the bank away when that first-uploader is evicted.

This plan introduces a reserved "guild" sentinel owner row and repoints every designated bank/bot to it — at designation time (going forward) and via a one-time data backfill (existing banks). Because the sentinel owner id belongs to no guildie, it is never the target of an eviction, so banks/bots survive eviction by construction (OWN-02). Designation no longer needs the officer to own the char (OWN-01). Existing owner-bound banks migrate with no manual fixup (OWN-04).

**Resolved design decision — Option A (reserved "guild" sentinel owner), NOT Option B (nullable owner_id).** Rationale: `character.owner_id` is `NOT NULL` in 00001; Option B requires a SQLite table rebuild (the only way to drop a NOT NULL is a 12-table CASCADE-FK rebuild) AND every `owner_id` consumer must learn to handle NULL. Grep of production (non-test) consumers shows `character.owner_id` is read/written in exactly two places — `store/binding.go` (first-sighting bind) and `store/eviction.go` (the cascade + the evictable/restorable owner lists). (`mint.go`/`guard.go`/`linking.go`/`whoami.go`/`account.go` all use `guild_code.owner_id`, a different column — untouched by either option. The `00009` `JOIN owner o ON o.id = c.owner_id` is a one-time migration seed, not a live query.) Option A keeps the FK satisfied (the sentinel is a real owner row), keeps every existing `owner(id)` join working unchanged, and confines the change to: one additive migration, one new owner resolver, one line in DesignateCharTx, and two `o.id <> sentinel` exclusions in eviction's owner lists. Smallest blast radius by a wide margin.

Purpose: decouple bank/bot designation from upload-ownership and make guild banks eviction-proof.
Output: migration 00015 (sentinel seed + backfill), a sentinel-owner store helper, a DesignateCharTx repoint, eviction-list exclusions, and full tests.

This is a single focused plan (3 tasks). NO PHASE SPLIT is warranted — the change is small, all four sources (GOAL/REQ/RESEARCH-skipped/CONTEXT-none) point at the same three reqs, and nothing exceeds the context budget.
</objective>
