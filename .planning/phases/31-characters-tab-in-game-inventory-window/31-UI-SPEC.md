# Phase 31 — UI Design Contract

> Visual and interaction contract for the SquireBot web app's **Characters tab + in-game-style
> inventory window** (CHAR-01..03, INV-01..04).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a NEW data surface inside an existing SvelteKit app whose visual language is ALREADY
> LOCKED** — five EQ themes, `[data-theme]` single source of truth, established tokens and
> component idioms (Phase 14/30 UI-SPEC lineage). This spec does NOT invent a palette; it pins
> the precise paperdoll/grid geometry, the hover-preview-vs-pinned-panel interaction, slot/icon
> sizing, the bag inline-expand treatment, the character-list layout, responsive collapse,
> accessibility, and every empty/loading/error state so the planner and executor have an
> unambiguous contract. Every token, size, and copy string below is either (a) lifted verbatim
> from the live codebase / sketch 002, or (b) the smallest extension of an existing idiom, noted
> as such. Locked decisions **D-01..D-11** (31-CONTEXT), sketch 002 **Variant D**, and the sketch
> MANIFEST are encoded here, not re-litigated.

## Spacing Scale

The codebase uses a strict 4-based scale (verified in SiteShell, DataGrid, StateBlock, +page).
Reuse it exactly — do not introduce new spacing values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Inter-slot grid gap (`gap: 4px` — see slot-geometry note); icon inset edge; count-badge inset; examine line gap |
| sm | 8px | Slot icon inset (`inset: 6px`→round to 8px is acceptable; keep 6px from sketch where exact); examine internal padding rows; list-row inner padding |
| md | 16px | Section → section gap inside the window; examine panel padding; character-list row horizontal padding; grid → grid vertical gap |
| lg | 24px | Window column gap (paperdoll/grid column ↔ pinned-panel column); char-head → window gap; `<main>` content gap (inherited) |
| xl | 32px | Page horizontal gutters (desktop — inherited from `shell-main`) |
| 2xl | 48px | Empty-state vertical centering block ("no inventory synced yet" — reuses StateBlock `padding: 48px 16px`) |

**Slot grid gap exception (from sketch 002):** the sketch uses `gap: 6px` between 62px slot
tiles. `6px` is OFF the 4-scale. **Resolution: round the inter-slot gap to `8px` (sm)** for
4-grid compliance; the visual difference at 62px tiles is negligible and keeps the scale clean.
The slot ICON inset (`inset: 6px` in the sketch) MAY stay 6px as a within-tile detail (it is not
a layout gap), or round to `8px` — planner's discretion; prefer 8px.

**Touch-target exception (existing rule, non-negotiable):** every interactive affordance —
a **filled** slot tile, a bag-open control, the examine-panel wiki/PigParse links, a
character-list row, the per-tab search input — has an effective hit area `>= 44px`. The 62px
slot tile already exceeds 44px; a character-list ROW must be `min-height: 44px`. Icon-only
controls also get `min-width: 44px`. Gutters collapse to **16px** below 640px (existing
`shell-main`/SiteShell `@media (max-width: 640px)` rule — inherited, keep it).

Exceptions: the 6px→8px slot-gap rounding above; the within-tile 6px icon inset (detail, not
layout). No other exceptions.

## Typography

Roles are already declared across the live UI-SPEC lineage (14/30) and rendered in
SiteShell / DataGrid / StateBlock / ItemTooltip. Reuse verbatim — this phase adds NO new type
roles. (The sketch's tiny 7.5–10px slot-name/count micro-labels are SKETCH-ONLY and are
re-specified to legible production values below.)

| Role | Size | Weight | Line Height | Where in this phase |
|------|------|--------|-------------|---------------------|
| Body | 16px | 400 (`--font-body`) | 1.5 | Examine stat lines, character-list meta (level/race/class), search input text, hints, prose |
| Label | 13px | `--weight-display` | 1.2 | Section headings' eyebrow (`GENERAL INVENTORY`, `BANK — STORED ITEMS`), examine flags row, empty-slot label, character-list "yours" tag, the bag "N of M slots" subline |
| Heading | 20px | `--weight-display` | 1.2 | The examine panel item NAME; the character-list section sub-labels if used |
| Display | 28px → 24px | `--weight-display` | 1.2 | The selected character's NAME in the char-head (the sketch uses **24px** for `.charhead h1` — use 24px here, distinct from the 28px wordmark which stays the only 28px). |

**Examine-panel typography (locked, from sketch 002 `examineBody` + ItemTooltip):**
- Item name = **Heading-ish, 20px** display, `color: var(--accent)` (the sketch used 15px; bump
  to the 20px Heading role for the PINNED panel where space allows — the transient hover preview
  may render the name at the smaller 16px Body-display size to stay lightweight).
- Flags line (`MAGIC LORE NO DROP`) = Label 13px display, uppercase, `letter-spacing: 0.04–0.05em`,
  `color: var(--status-other)`.
- Stat/slot/DMG/AC/wt lines = Body 16px (sketch used 12.5px — bump to 16px Body for legibility per
  the live ItemTooltip, which renders its body at 16px). The single "highlighted stats" line uses
  `color: var(--status-ok)` (the green stat color), matching the sketch.
- Footer (PigParse price / wiki link / last-synced) = Body, dimmed (`opacity: 0.75–0.85`), with
  the wiki link in `var(--accent)` + 1px accent underline (the live `.tooltip-wiki-link` idiom).
- Price value uses `font-variant-numeric: tabular-nums`.

**Slot micro-labels (re-specified — the sketch's 7.5px is too small for production):**
- The in-tile item NAME overlay is OPTIONAL. **Recommendation: drop the in-tile name overlay**
  (the sketch's 7.5px bottom strip) — it is illegible at production zoom and the icon + hover/pin
  examine already names the item. If retained for the "no-icon, colored-tile" case, render it at the
  **13px Label role** with `line-height: 1.1`, truncated, in `var(--text)` over a `rgba(0,0,0,.55)`
  scrim. The empty-slot label (`data-slot`, e.g. "NECK") renders at **13px (Label)** uppercase, dimmed.
  (Both stay on the 4-role scale — no sub-13px micro-tier is introduced.)
- The stack-count badge renders at **13px** (Label), `font-variant-numeric: tabular-nums`,
  `color: #fff` (or `var(--text)`) with a dark text-shadow for contrast over any icon. (Sketch
  used 10px — bump to 13px.)

## Color

The five themes each redefine the same token set; values below are the **Velious default**
(`:root` / `[data-theme="velious"]`). The CONTRACT is the token NAME and its ROLE, which holds
across all five themes.

| Role | Token | Velious value | Usage in this phase |
|------|-------|---------------|---------------------|
| Dominant (~60%) | `--bg` | `#060b18` | Page background, the `.doll` silhouette field, empty-slot interior, examine-panel deep-fill if used |
| Secondary (~30%) | `--panel` | `#0f1729` | Slot tile fill, pinned examine panel, character-list rows/cards, bag-expand region, search-input fill, section backdrops |
| Accent (~10%) | `--accent` | `#a8c5e0` | **Reserved list below — never "all interactive elements"** |
| Status OK | `--status-ok` | `#6fc8b0` | The examine "highlighted stats" line ONLY (e.g. `STR +10 · HP +90`) |
| Status other | `--status-other` | `#a8c5e0` | The examine FLAGS line (`MAGIC LORE NO DROP`) + the PigParse price value |
| Border | `--border` (→ `--accent` fallback) | — | Slot-tile edge at rest, examine-panel border, list-row separators, section dividers, search-input border at rest |
| Text | `--text` | `#d4dee8` | All at-rest copy, slot count badge |
| Destructive | `--destructive` (= `--status-missing`) | `#e88a8a` | **Not used this phase** — there are NO destructive actions in Characters/Inventory-window (read-only surface). Declared for completeness only. |

**Accent reserved for (explicit, closed list):**
1. The selected **character name** in the char-head (`.charhead h1`).
2. **Section eyebrow headings** (`GENERAL INVENTORY`, `BANK — STORED ITEMS`, `WORN — WEAPONS & MISC`).
3. The **filled-slot hover/focus** treatment: `border-color: var(--accent)` + a 1px accent
   box-shadow + a subtle `scale(1.04)` lift (sketch `.slot.filled:hover`).
4. The **bag-open marker** (`⊞` / `Package` glyph) on container slots.
5. The examine panel item **NAME** + the **wiki link** (accent text + 1px accent underline).
6. The **focus-visible outline** on every focusable affordance (`outline: 2px solid var(--accent)`).
7. The **selected character-list row** indicator (a 2–3px accent left-border or accent name color
   — the master-detail "this is what's pinned in the window" signal), and the search-result match
   emphasis.
8. The character-list **"yours" tag** accent (small uppercase Label, the viewer-owned marker).

Accent is NOT used for: at-rest slot borders (those are `--border`), body copy, examine stat
lines beyond the name/link, empty-slot interiors, the silhouette, count badges, or any decorative
fill. The 60/30/10 budget holds: a window full of `--panel` tiles on a `--bg` page, with accent
appearing only on the section eyebrows, the active selection, hover/focus, the bag marker, and the
examine name/link.

**Sketch-token → registry-token mapping (LOCKED — the sketch's helper vars must NOT ship):**

| Sketch var | Production token | Notes |
|------------|------------------|-------|
| `--slot` (tile fill) | `var(--panel)` | slot tiles are panel surfaces |
| `--slot-edge` (tile border) | `var(--border, var(--accent))` | at-rest edge |
| `--bg-2` | `var(--panel)` | the sketch's secondary surface = panel |
| `--accent-2` (examine border) | `var(--accent)` or `var(--border)` | use `--border` at rest, `--accent` for the pinned-panel emphasis |
| `--text-dim` | `var(--text)` with `opacity: 0.7–0.85` | no separate dim token exists |
| `--status-ok` | `var(--status-ok)` | real token exists |
| `--status-other` | `var(--status-other)` | real token exists |
| the per-item `hsl(...)` colored-tile gradient | KEEP — see D-01/D-02 fallback note | this is the icon-load-error fallback, intentionally non-token (a deterministic per-item hue) |

**Colored-tile fallback (D-01/D-02 — locked):** when `https://wiki.project1999.com/images/Item_<iconId>.png`
fails to load (`onerror`) OR no `iconId` is known yet, the slot shows a deterministic colored
gradient tile (the sketch's `hsl(hue 45% 30%) → hsl(hue+40 40% 18%)`, hue derived from the item
name/id). This is the ONE sanctioned non-token color and exists precisely so icon coverage can
ship incrementally — the window is NEVER blocked on 100% icon coverage. The tile must remain a
recognizable filled slot (not a broken-image glyph), and the item name/hover must still identify
it. `image-rendering: pixelated` on the `<img>` keeps the 40px wiki icons crisp.

**Heavy-theme caveat (carry forward):** Heavy inverts DATA-GRID rows (`--row-bg`/`--row-text`),
but the inventory window's slot tiles and examine panel are CHROME-on-frame, not data rows — they
stay on the dark frame (`--panel`/`--bg`), NOT parchment. The character LIST, if built on
`DataGrid`, WILL take Heavy's parchment rows (that's correct — it's a data grid); if built bespoke
(see §J), keep it on `--panel` like the window. Verify the accent (`#f0d088`) slot-hover border +
focus ring read against Heavy's near-black `--panel` (`#1a0e05`) — they do. Verify minimalist's
low-chroma accent (`#b8915c`) focus ring is still visible — it is (spot-check at build).

## Layout & Interaction Contract

> This is the load-bearing section. The tables above are tokens; this is the structure the
> executor builds. The canonical visual reference is
> `.planning/sketches/002-character-inventory-window/index.html` (Variant D is the default tab).

### A. Route & page frame

- The Characters tab is the route `/characters` (replaces the Phase-30 "coming soon" placeholder
  in `web/src/routes/characters/+page.svelte`). It mounts inside the Phase-30 `SiteShell` (5-tab
  strip already present; `/characters` tab gets `aria-current="page"` automatically via
  `startsWith` matching, so a deep link like `/characters/<name>` keeps the tab active).
- **Master-detail on ONE route (no per-character route explosion).** The CLAUDE.md
  consolidated-views lock is RELAXED for exactly this pattern: ONE reusable inventory-window
  component rendered for the SELECTED character. Selection MAY be reflected in the URL
  (`/characters?c=<name>` or `/characters/<name>`) so a character is deep-linkable/shareable —
  **planner's discretion**; the contract is that selection renders the single reusable window, not
  N materialized routes/tabs.
- **Two-pane shape (desktop):** a **character list** (left or top) + the **inventory window** for
  the selected character. When no character is selected, the window column shows a friendly
  "Pick a character" prompt (see §K). On mobile the list and window stack (see §H).

### B. The character list (CHAR-01 / CHAR-02 / D-10)

**Data per row:** name, level, race, class. Ordering (D-10, spec-fixed): the **viewer's own
characters first (A-Z)**, then other guild characters (A-Z), then guild banks/bots (A-Z). "Yours"
= the viewer's `character_assignment` rows.

**Build decision — RECOMMENDATION: a bespoke list, NOT `DataGrid`.** Rationale (governing rule =
simplest end-user experience + the master-detail intent):
- `DataGrid` is the guild-wide consolidated grid idiom (sticky Char column, faceted filters, zebra,
  Heavy parchment rows) — overkill for a short, ordered, *selectable* roster and it carries no
  native "selected row → render detail" affordance.
- A bespoke list of selectable rows reads as the master pane of a master-detail and supports the
  D-10 grouping (a subtle group label/divider between "Yours" / "Guild" / "Banks & bots") far more
  cleanly than a flat sortable table.
- If the planner prefers `DataGrid` for consistency, that is ALLOWED — but it must (a) preserve the
  D-10 default order as the seeded sort, (b) make each row selection-capable (row click pins the
  window), and (c) not lose the viewer-first grouping. Bespoke is the recommended default.

**Row treatment (bespoke):**
- A selectable element (`<button>` or `<a>` if URL-reflected) per character, `min-height: 44px`,
  `--panel` background, `padding: 8px 16px` (sm × md), 1px `--border` bottom separator.
- Layout: character **name** (Body 16px, or display for emphasis) on the lead; a dimmed meta line
  `Level {N} {Race} {Class}` (Body 16px, `opacity: 0.85`); a small accent **"yours"** Label tag on
  the viewer's own rows; a subtle **"bank" / "bot"** Label tag on bank/bot rows.
- **Selected state:** a 2–3px accent **left border** + accent name color (the master-detail
  "currently shown in the window" signal). `aria-pressed="true"` (button) or `aria-current="true"`
  (link). Exactly one row selected when a character is shown.
- Hover: `background: color-mix(in srgb, var(--accent) 8%, transparent)` (the live DataGrid hover
  idiom). Focus-visible: `outline: 2px solid var(--accent)`.
- **Group labels (D-10):** a Label-13px accent eyebrow separates the three bands — "YOUR
  CHARACTERS", "GUILD", "BANKS & BOTS". A band with zero members is omitted (no empty headers).

**Missing meta (D-11):** a character missing level/race/class shows what's available; absent fields
render as a dimmed "—" or are simply omitted from the meta line — NEVER "null"/blank-broken. (e.g.
`Level 58 Half Elf Ranger` → if class unknown: `Level 58 Half Elf` or `Level 58 Half Elf —`.)

### C. Per-tab scoped search (CHAR-02 / NAV-02 / D-08)

The search bar lives at the **top of the tab body** (under the 5-tab strip), full content width —
the Variant A / 30-UI-SPEC §D placement. **It SHIPS WITH content this phase** (unlike the Phase-30
placeholder which correctly had no bar).

- **Visual (from 30-UI-SPEC §D + live tokens):** full-width, `background: var(--panel)`, `border:
  1px solid var(--border)`, `color: var(--text)`, Body 16px, `padding: 8px 12px`,
  `border-radius: 4px`, `min-height: 44px`, a leading `Search` lucide glyph (16px, `aria-hidden`),
  placeholder in dimmed `--text`. Focus: `border-color: var(--accent)` + focus-visible
  `outline: 2px solid var(--accent)`.
- **Behavior:** filters the character list by name. **Viewer-priority (D-10):** matches on the
  viewer's own characters rank/appear FIRST, then other guild chars, then banks/bots — i.e. the
  search preserves the D-10 ordering within the filtered set. Client-side filter (the roster is
  tiny — guild scale ~12 members × ~10 chars).
- **Search hint (one line, dimmed Body 13–14px) below the bar:** "Your characters match first."
- **No-results:** reuse `StateBlock kind="no-results"` → `No matches for "{query}"` (query
  auto-escaped via `{}` — never `{@html}`). Do not blank the list.

### D. The inventory window — overall structure (INV-01 / D-05)

For the selected character, the window renders top-to-bottom as ONE continuous scroll (NO
Inventory/Bank toggle — D-05), inside the left/main column of the master-detail (the examine panel
is the right column, §G). Order:

1. **Char-head:** `{Name}` (Display 24px, accent) + a dimmed meta line `Level {N} {Race} {Class} ·
   yours` (Body 16px). Breadcrumb optional (`Characters › {Name}`) — the sketch shows one;
   planner's discretion since the tab strip already conveys location.
2. **Paperdoll** (equipment) — §E.
3. **Section eyebrow `WORN — WEAPONS & MISC`** + the weapon/charm/range/ammo/waist row (the sketch's
   `PAPERDOLL_BOTTOM`) — may be folded into the paperdoll per §E.
4. **Section eyebrow `GENERAL INVENTORY`** + the general grid (§F).
5. **Section eyebrow `BANK — STORED ITEMS`** + the bank grid (§F, same renderer — D-05).
6. **Hint line (dimmed Body):** "Click any item to pin its details on the right. Click a ⊞ bag to
   open it. Item icons load from the P1999 wiki." (sketch copy; keep.)

The window is a **single reusable component** consumed here AND by Phase 33 (per bank toon) — so it
must accept a `CharacterInventory` (`{Char, Equipment[], General[], Bank[]}` from
`compute.StructuredInventory`) and render generically; no Phase-31-only assumptions.

### E. The EQ paperdoll (INV-01) — slot geometry & arrangement

**The canonical equipment slot set (authoritative — from `compute/slotconst.go`, 23 slots):**
`Charm, Head, Face, Ear1, Ear2, Neck, Shoulders, Arms, Back, Wrist1, Wrist2, Range, Hands,

> **23** (it splits Ear1/Ear2, Wrist1/Wrist2, Finger1/Finger2 and includes Power + Ammo). The
> **code is authoritative** — render all 23; the data foundation already keeps every slot
> (empty ones included, D-11). The sketch's `EAR/WRIST/FINGERS` pairs reflect this.

- **Right column slots (top→bottom):** Wrist1, Wrist2, Hands, Finger1, Finger2, Chest, Legs, Feet.
- **Bottom "weapons & misc" row:** Charm, Primary, Secondary, Range, Ammo, Waist, Power.
  (The sketch omitted Power; INCLUDE it here since the data foundation has it. Arrange the bottom
  row as `repeat(N, 62px)` wrapping as needed.)
- This is a faithful-but-pragmatic mapping of the sketch arrangement onto the full 23-slot set;
  the planner MAY refine exact slot-to-column placement to better mirror the in-game window, but
  MUST render all 23 slots and keep the flanking-columns + center-figure read.
- **Center figure (`.doll`):** a dashed-border panel, `min-height: ~260px`, centered silhouette
  glyph (the sketch uses `⚔`), and a derived `AC · ATK` line + `{Race} {Class}` line, all dimmed.
  The AC/ATK summary is OPTIONAL (only if the data foundation exposes it; otherwise show the
  silhouette + race/class only — never a fabricated stat).

**Slot tile (the `.slot` cell — locked from sketch 002, tokens swapped):**
- `width: 62px; height: 62px; background: var(--panel); border: 1px solid var(--border);
  border-radius: 3px; position: relative; overflow: hidden;`
- **Icon:** an inner `.ico` inset `~6–8px`, holding `<img src="…/Item_<iconId>.png"
  image-rendering: pixelated; object-fit: contain;>` over the deterministic colored-gradient
  fallback (D-01/D-02). `onerror` hides the `<img>` so the colored tile shows through.
- **Stack count (INV-01):** top-right `.count` badge, 13px tabular-nums, white + dark text-shadow.
  Shown only when count > 1.
- **Bag marker:** top-left `⊞` (or `Package` glyph) in `var(--accent)` on container slots
  (`Slots > 0`).
- **Empty slot (D-11):** `.slot.empty` — no icon, the slot LABEL centered (e.g. "NECK", 13px Label
  uppercase dimmed via `::after { content: attr(data-slot) }`). Empty slots are NON-interactive
  (`cursor: default`, not focusable, no hover lift).
- **Filled slot:** `cursor: pointer`; hover/focus → `border-color: var(--accent)` + 1px accent
  box-shadow + `transform: scale(1.04)` (honor reduced-motion: the transform/transition is instant
  under the global rule). Filled slots ARE focusable + keyboard-activatable (§I).

### F. General + Bank grids and the inline bag drill-down (INV-03 / D-04 / D-05)

- **General inventory** renders as a row/grid of `.slot` tiles (the sketch uses
  `grid-template-columns: repeat(8, 62px); gap` — i.e. up to General1..General10 from the data
  foundation). On narrow viewports the grid wraps (`repeat(auto-fill, 62px)`).
- **Bank** renders directly BELOW general (NO toggle — D-05) using the **SAME grid renderer + the
  SAME inline-drill-down** (Bank1..Bank8 + openable bank bags). One renderer, two data arrays — DRY.
- **Bag drill-down = INLINE EXPAND (D-04), NOT a modal.** This is the single biggest delta from the
  sketch (the sketch 002 HTML used a `#bagscrim` modal — explicitly rejected in D-04). Contract:
  - Clicking a container slot (`Slots > 0`) toggles an **inline expanded region** that appears
    **directly beneath the grid row containing that bag** (or immediately below the grid),
    revealing the bag's `Children[]` as a sub-grid of the SAME `.slot` tiles.
  - The expanded region reads as a nested, indented panel: a 1px `--border` top rule or a slightly
    inset `--panel` surface, a Label-13px sub-header `{Bag name} — {used} of {capacity} slots`, and
    the child-slot grid. It "behaves like the inventory grid" (INV-03 literal): child items hover/
    pin-examine identically; a child bag (rare) expands inline too.
  - The bag tile shows an **open/closed affordance**: the `⊞` marker rotates/changes (or a
    `Chevron` toggles) and the tile gets `aria-expanded`. Re-clicking collapses it.
  - Mobile-friendly by construction (no modal, no scrim, stays in the scroll flow).
- **Empty bag:** if a container has zero children, expanding shows a dimmed "Empty" Label line
  (not blank, not an error).

### G. Examine: hover preview + click/tap-to-pin (INV-02 / D-06 / D-07 / D-08 / D-09)

### I. Accessibility Contract (load-bearing)

1. **Filled slots are buttons.** Each filled `.slot` is a `<button type="button">` (or `role=
   "button"` + `tabindex="0"`) with an accessible name = the item name (e.g. `aria-label="Cloak of
   Flames, count 1"`). Empty slots are NON-interactive, NOT focusable, and labelled only visually
   (the slot name); they get `aria-hidden` or a plain non-interactive element. Bag slots add
   `aria-expanded` reflecting the inline-expand state and an accessible name like "Open Large
   Lambent Bag".
2. **Keyboard:** filled slots are reachable by Tab; Enter/Space activates (pin examine, or
   open/close a bag — same as click). The inline-expanded bag's children are in DOM order
   immediately after the bag, so tab order is logical. The pinned-panel wiki/PigParse links are
   normal focusable links.
3. **Examine preview a11y:** the hover preview is supplementary; the SAME content is reachable by
   pinning (click/Enter) into the persistent panel, so keyboard/screen-reader users are never
   hover-dependent. If `ItemTooltip` is reused for the preview, its existing `aria-haspopup`/
   `aria-expanded`/Esc/outside-dismiss contract holds.
4. **Focus-visible:** every focusable affordance (slot button, list row, search input, bag toggle,
   examine link) shows `outline: 2px solid var(--accent)` on `:focus-visible` (`outline-offset: 2px`,
   or `-2px` where it would clip a slot edge). Universal, already-shipped treatment.
5. **44px touch targets:** list rows `min-height: 44px`; the 62px slot tiles already exceed it;
   icon-only bag toggles `min-width: 44px` if rendered as a separate control (prefer making the
   whole tile the control).
6. **Color is never the sole signal:** the stack count is a NUMBER (not color); the bag affordance
   is a GLYPH + `aria-expanded` (not color); the selected list row carries `aria-pressed`/
   `aria-current` (not only the accent border); examine flags are TEXT.
7. **Selected character announced:** the selected list row has `aria-pressed="true"` /
   `aria-current="true"`; the window's char-head heading (`<h1>`/`<h2>` with the name) gives
   screen-reader context for what's shown.
8. **Reduced motion:** the slot hover `scale(1.04)`, the bag-expand reveal, and any theme/tooltip
   transition honor the global `@media (prefers-reduced-motion: reduce)` rule in app.css (instant).
9. **Theme-independence:** all of the above must hold under all 5 themes — verify the accent focus
   ring + slot-hover border read on Heavy (`#f0d088` on `#1a0e05`) and Minimalist (`#b8915c`); both
   pass; spot-check at build.
10. **Icon `alt`:** item-icon `<img>` carries `alt=""` (decorative — the slot button's `aria-label`
    names the item, so the image is redundant; an alt would double-announce). On colored-tile
    fallback the slot is still named by the button label.
