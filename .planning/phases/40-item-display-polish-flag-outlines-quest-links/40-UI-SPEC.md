# Phase 40 — UI Design Contract

> Visual and interaction contract for ITEMUI-01 (flag-coded tile/heading outlines) and ITEMUI-02 (named quest links on detail surfaces). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a CONFORM-to-existing-design-system phase.** SquireBot's SvelteKit web app (`web/`) is a mature, multi-theme EQ-aesthetic system shipped at v2.0 and iterated through v2.4/v2.5/v2.6. This phase adds NO new design system, NO new spacing/typography scale, and NO new component primitives. It (a) adds three per-theme flag-color tokens and (b) reuses the existing `PaperdollSlot` / `ExaminePanel` / `examine.ts` / `ItemTooltip` / `composeNotes.ts` surfaces. Every value below is sourced from the live token system (`web/src/app.css` + `web/src/lib/theme/themes.ts`), not invented.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (bespoke EQ-aesthetic CSS-custom-property theme system — no shadcn, no Tailwind component layer beyond utility import) |
| Preset | not applicable |
| Component library | none (hand-rolled Svelte 5 components; `web/src/lib/components/`) |
| Icon library | none — item icons are P1999 wiki PNGs (`Item_<iconId>.png`); flag/bag markers are inline glyphs (`⊞`) and CSS rings. Quest-link affordance is a text link (no icon). |
| Font | Per-theme display/body pair via `@fontsource` woff2 (self-hosted, no Google Fonts runtime). Display: Cinzel / Cinzel Decorative / MedievalSharp. Body: IM Fell English / Crimson Text / Inter. Resolved through `var(--font-display)` / `var(--font-body)`. |

**Theme model:** one `[data-theme="<key>"]` attribute on the shell root selects one of five themes (`velious` default · `vanilla` · `kunark` · `minimalist` · `heavy`). Every color in this spec is a `var(--token)` that resolves per theme. Source of truth: `web/src/app.css` (CSS blocks) mirrored by `web/src/lib/theme/themes.ts` (TS registry). Both MUST be updated in lockstep when adding the new flag tokens.

## Spacing Scale

The app already uses a 4-based scale (the source comments literally tag `/* sm */`, `/* md */`, `/* lg */`). This phase introduces **no new spacing** — the flag outline lives inside the existing 62px tile and the quest links are new text rows inside existing 16px-padded panels.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Examine field row margin (`.ex-*` `margin: 4px 0`); ring offset reasoning |
| sm | 8px | Examine heading bottom margin; quest-link list inter-item gap |
| md | 16px | Panel padding (`ExaminePanel` `padding: 16px`, tooltip `padding: 16px`) — unchanged |
| lg | 24px | Layout column gap — unchanged |
| xl | 32px | not used this phase |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

**Exceptions:**
- **62px** — the fixed in-game inventory tile (`PaperdollSlot .slot`). NOT a spacing token; it is a fixed component dimension carried from Phase 31 (31-UI-SPEC §E). The flag outline must fit entirely inside this 62px box.
- **44px** — existing min touch target on `ItemTooltip .tooltip-trigger` (carried from 14-UI-SPEC). Quest-link `<a>`s inside the tooltip inherit this; do not shrink it.
- **Flag ring width: 2px.** The outline ring is 2px (matches the existing `:focus-visible` `outline: 2px` weight so the two affordances are visually peers, not competing weights). NOT a spacing-scale value; it is a border weight.

## Typography

No new type scale. All four roles below already exist and are in active use across `PaperdollSlot`, `ExaminePanel`, `InventoryWindow`, and `ItemTooltip`. The phase reuses them verbatim.

| Role | Size | Weight | Line Height | Where this phase uses it |
|------|------|--------|-------------|--------------------------|
| Body | 16px | 400 (`--font-body`) | 1.5 | Quest-link rows in the examine panel (`.ex-quests`) and tooltip (`.tooltip-quests`); the "Used in:" label and each linked quest name |
| Label | 13px | `var(--weight-display)` (600; 400 in minimalist) | 1.1–1.2 | The examine flags line (`.ex-flags`) and the tooltip title — unchanged; flag heading-tint rides the existing `.ex-name` heading, not a new label |
| Heading | 20px | `var(--weight-display)` | 1.2 | The examine item-name heading (`.ex-name`) that carries the D-02 flag tint |
| Display | 24px | `var(--weight-display)` | 1.2 | Char-head name — NOT touched this phase (listed for completeness; the flag tint is on the 20px examine heading, not the 24px char name) |

**Weights:** exactly two in the system — `var(--weight-display)` (600, or 400 for minimalist) for display/label, and 400 for body. This phase adds none.

**Quest-link typography rule:** the linked quest name renders at Body (16px/400/1.5), distinguished from surrounding text ONLY by `color: var(--accent)` + a 1px accent underline — identical to the existing `.tooltip-wiki-link` / `.ex-wiki .tooltip-wiki-link` treatment. Do NOT bold, enlarge, or recolor quest links differently from the established wiki-link affordance; a quest link and a wiki link are the same kind of thing (a jump to the P1999 wiki) and must look the same.

## Color

The app is dark-leaning across all five themes; the 60/30/10 split is per-theme via tokens. Values below show the **velious default** (the shipped default theme) for concreteness; each resolves per theme.

| Role | Token (velious value) | Usage |
|------|-----------------------|-------|
| Dominant (60%) | `--bg` (`#060b18`) | Page background, shell |
| Secondary (30%) | `--panel` (`#0f1729`) | Tiles, examine panel, tooltip popover, cards |
| Accent (10%) | `--accent` (`#a8c5e0`) | See reserved-for list below |
| Destructive | `--destructive` = `--status-missing` (`#e88a8a`) | Destructive actions only — **none in this phase** |

**Accent (`--accent`) reserved for:** examine/char headings, the wiki link + (new) quest links, the tile hover/focus border + box-shadow ring, the `:focus-visible` outline, the bag-open `⊞` marker, eyebrow section labels, and active nav. This phase adds exactly ONE accent use: the **quest-link `<a>`** (color + underline), which is the same accent-link affordance the wiki link already uses. The flag outline does NOT use accent (accent is the hover/focus color — see D-03 coexistence below).

### New flag tokens (the load-bearing color decision)

The locked decision maps No-Drop→red, Lore→gold, Magic→blue, sourced as **theme tokens, never literal hex**. The live web token set is `--bg --panel --text --accent --status-ok --status-missing --status-other --destructive`. Auditing these against the three needed colors **across all five themes**:

- **Red (No-Drop):** `--status-missing` is a red in every theme (velious `#e88a8a`, vanilla `#c66666`, kunark `#c66666`, minimalist `#c87878`, heavy `#6b1a1a`). Reusable.
- **Gold (Lore):** `--status-other` is gold ONLY in vanilla (`#d4af37`) and kunark (`#d4a020`). In velious it is blue (`#a8c5e0`), in minimalist bronze (`#b8915c`), in heavy brown (`#5a3a1f`). **NOT a reliable gold.** No dedicated gold token exists.
- **Blue (Magic):** **NO blue/info token exists in any theme.** velious `--accent` is blue but the other four accents are warm.

**Therefore: this phase MUST add three dedicated, per-theme flag tokens** (the CONTEXT.md "if a needed semantic token is missing, spec adding it to the THEMES registry" branch). Reusing `--status-missing` / `--status-other` directly would break Lore and Magic on three of five themes and conflate flag meaning with status meaning. Add:

| New token | Semantic | Rule |
|-----------|----------|------|
| `--flag-nodrop` | No-Drop (red, highest priority) | A saturated danger-red, WCAG ≥ 3:1 against `--panel`. MAY alias `--status-missing` per theme where that red already clears 3:1 on the tile; otherwise a brighter red. |
| `--flag-lore` | Lore (gold, middle priority) | A warm gold/amber, ≥ 3:1 against `--panel`. |
| `--flag-magic` | Magic (blue, lowest priority) | A clear info-blue, ≥ 3:1 against `--panel`. |

**Per-theme values (prescriptive — derived from each theme's existing palette family, parchment-aware for heavy):**

| Theme | `--flag-nodrop` | `--flag-lore` | `--flag-magic` | Notes |
|-------|-----------------|---------------|----------------|-------|
| velious | `#e88a8a` (= status-missing) | `#e3c46b` | `#6db3e0` | icy palette; magic blue brighter than the blue accent so they don't collide |
| vanilla | `#d96b6b` | `#d4af37` (= status-other) | `#6fa0d4` | warm tavern; gold already its accent family |
| kunark | `#d96b6b` | `#d4a020` (= status-other) | `#5f9fd4` | jungle/copper; cooler blue reads against green panel |
| minimalist | `#d98a8a` | `#d4b15c` | `#7fa8d4` | muted across the board to match the theme's lower intensity |
| heavy | `#c0392b` | `#d4a017` | `#3f78c0` | tiles are dark-frame `--panel` `#1a0e05` (NOT the parchment rows) → use saturated, high-contrast flag colors; verify each ≥ 3:1 against `#1a0e05` |

> Implementer: add these three lines to EACH `[data-theme]` block in `web/src/app.css` AND to each `ThemeTokens` entry in `web/src/lib/theme/themes.ts` (add `flagNodrop` / `flagLore` / `flagMagic` to the `ThemeTokens` interface). Keep CSS and TS registry in lockstep (the existing `themeApply.test.ts` / `themes.test.ts` assert parity — extend them for the new keys). The `:root` fallback block (= velious) gets the velious values too.

### Priority resolution (D-01) → `--flag-color`

A single computed `--flag-color` rides each surface, resolved most-restrictive-first:

```
No-Drop  → --flag-color = var(--flag-nodrop)   (highest)
else Lore → --flag-color = var(--flag-lore)
else Magic → --flag-color = var(--flag-magic)
else (no flag) → no --flag-color set → existing var(--border) neutral border, no ring
```

The priority is computed in the component (Svelte `$derived`) from `is_no_drop` / `is_lore` / `is_magic`, NOT in CSS. The component sets `style="--flag-color: var(--flag-nodrop)"` (etc.) only when a flag is present; absence of the var = neutral tile (no ring rendered).

### WCAG / contrast contract

- Each flag ring color MUST clear **≥ 3:1** against the tile fill it sits on — `--panel` for general/bank/paperdoll tiles (and `#1a0e05` for heavy specifically, since heavy tiles are the dark frame, not the parchment rows). 3:1 is the WCAG 2.1 SC 1.4.11 non-text-contrast threshold for UI component boundaries.
- The ring is a **redundant** encoding: the examine panel always lists every flag in the stat block as text (MAGIC/LORE/NO-DROP), so color is never the sole carrier of the flag fact (WCAG 1.4.1 use-of-color). Color-blind users lose the tile glance but retain full information on the detail surface. The spec does NOT require a per-color shape/pattern on the tile (the 62px tile can't legibly carry one), and this is acceptable BECAUSE of that text redundancy — note this explicitly for the checker.

| Element | Copy |
|---------|------|

| Empty state heading | not applicable — no new surface. The existing examine empty prompt ("Click an item to see its details…") is unchanged. |

| Error state | not applicable — no fetch, no mutation. A quest row with a present `quest_name` but no/blocked `source_url` degrades to **plain (non-link) text** of the quest name (D-05 fallback), not an error. |

| String | Surface | Notes |
|--------|---------|-------|

Comma-join all `notes_link` quests on one line (Claude's-discretion item resolved: **comma-joined, single row** — the set is small in practice; no cap needed beyond the existing tooltip `MAX_QUEST_LINKS_IN_NOTE=5`). Each `{quest}` is a clickable `<a>` when its `source_url` passes `safeHttpUrl`, else plain text. Label `Used in:` is static (not a link). |
| `Used in quests: {quest1}, {quest2}` | Item tooltip (`composeNotes.ts` → `ItemTooltip`) | The tooltip ALREADY emits this exact string as plain text (`composeNotes.ts:160`). | `Quest item` / `QUEST ITEM` (fallback badge) | Tooltip / examine respectively | UNCHANGED. **Copy rules (for the checker):**
- The quest-link label uses sentence case (`Used in:`), matching the examine panel's prose register, NOT all-caps. The tooltip keeps its existing `Used in quests:` wording (do not "fix" it to match — two different surfaces, both already correct).
- Quest names are wiki-/user-sourced strings → rendered via Svelte auto-escaping (examine path) or `escapeHtml()` (tooltip `{@html}` path). Never interpolate a quest name raw.
- The `in_game_flag` pseudo-name `[in-game QUEST flag]` is sourcing jargon and MUST NOT reach the UI as a quest name (D-06) — the `notes_link` source filter already excludes it; preserve that filter on every new code path.

## Interaction & Visual Contract (phase-specific detail)

### ITEMUI-01 — Flag outline on the 62px tile (`PaperdollSlot.svelte`)

**Mechanism (D-03 resolved — Claude's discretion exercised): a `::before` inset ring keyed off `--flag-color`.**

Rationale for `::before` over alternatives:
- It does **not** touch `border-color`, so it survives the existing `:hover`/`:focus-visible` rule that flips `border-color` and adds `box-shadow: 0 0 0 1px var(--accent)`. Flag color and accent affordance coexist as two concentric rings (flag inset, accent on the border/box-shadow) — exactly the D-03 requirement.
- It does **not** collide with the corner markers: `.count` (top-right, `top:1px right:3px`) and `.bag-marker` (top-left, `top:1px left:3px`) sit ON the tile content above the icon; a perimeter inset ring sits at the tile edge and reads behind/around them. Confirm visually in browser-smoke that the ring does not visually clip the count/bag glyphs (it should not — markers are inset 1px and the ring is the outer 2px).
- It respects `border-radius` (the ring uses the same 3px radius as the tile).

**Prescriptive CSS shape (executor adapts to house style; values are the contract):**

```css
/* Only rendered when the component set --flag-color (a flagged item). */
.slot.filled::before {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: 3px;            /* match .slot */
  /* The 2px flag ring — inset box-shadow so it sits inside the tile and never
     fights the accent border/box-shadow that hover/focus adds on the border. */
  box-shadow: inset 0 0 0 2px var(--flag-color);
  pointer-events: none;          /* never steal hover/click from the tile button */
  z-index: 1;                     /* above the .ico gradient, below count/bag markers */
}
```

- The component sets `--flag-color` inline (alongside the existing `--tile-hue`) ONLY for a flagged item; unflagged items set no `--flag-color`, the `::before` either is not emitted or `box-shadow: inset 0 0 0 2px transparent` resolves to nothing (executor's choice; prefer gating the `::before` on a `class:flagged` so unflagged tiles emit no pseudo-element).
- The resting neutral tile is UNCHANGED: `border: 1px solid var(--border, var(--accent))`. Only flagged tiles add the ring.
- **Hover/focus coexistence (must verify in browser-smoke across all 5 themes):** on hover/focus a flagged tile shows BOTH the flag ring (inset, flag color) AND the accent border + accent box-shadow (the existing affordance). The `transform: scale(1.04)` and `:focus-visible outline: 2px solid var(--accent)` are unchanged and apply on top. The flag color remains visible the entire time.
- **Reduced motion:** UNCHANGED and preserved — the existing `@media (prefers-reduced-motion: reduce)` block kills the transform/transition; the static ring has no motion to suppress.
- **Surfaces (D-02):** every place `PaperdollSlot` renders — paperdoll equipment slots, the WORN row, GENERAL INVENTORY grid, BANK grid, inline bag-expand sub-grids (in `InventoryWindow.svelte`), AND the Banks tab grids (which reuse `InventoryWindow`). The outline rides the component, so all these inherit it for free. Empty equipment tiles (`.slot.empty`) never get a flag (no item) — confirmed: the `::before` is scoped to `.slot.filled`.
- **NOT outlined:** the dense item-centric DataGrid rows on the Inventory tab and the Wishlist DataGrid (D-02). Those are not `PaperdollSlot` tiles and get no ring.

**Data plumbing (D-07):** `InventorySlot` and `ItemRollup` gain `is_no_drop` / `is_lore` / `is_magic` booleans (`api.ts`), mirroring the Phase-39 `is_clicky`/`has_haste` precedent at `api.ts:250-251`. The component computes the priority `--flag-color` from these three.

### ITEMUI-01 — Flag tint on the examine name heading (D-02)

**Treatment (Claude's-discretion resolved): a small flag chip beside the name, NOT a full-color heading recolor.**

Rationale: `.ex-name` is already `color: var(--accent)` (the heading affordance). Recoloring the whole heading to the flag color would (a) fight the accent-heading convention used everywhere and (b) fail when the flag color is low-contrast as a large text fill. A small uppercase chip beside the name carries the flag color as a bounded swatch (easier to hit 3:1, doesn't disturb heading legibility) and reads as a peer to the existing `.ex-flags` line.

- Render a single chip for the **priority** flag (same D-01 most-restrictive-wins resolution as the tile) immediately after the item name in/under `.ex-name`.
- Chip copy: the flag word — `NO-DROP` / `LORE` / `MAGIC` (uppercase, Label type: 13px, `var(--weight-display)`, letter-spacing 0.05em — matching `.ex-flags`).
- Chip color: `color: var(--flag-color)` with a 1px `var(--flag-color)` border at ~`border-radius: 3px`, transparent fill (a bordered text chip, not a filled pill — filled pills risk the WCAG large-fill contrast problem and clash with the dark tile aesthetic).
- This chip is **additive** — the full stat block below still lists ALL flags (MAGIC/LORE/NO-DROP) as text. The chip is the at-a-glance priority echo of the tile ring; the stat block is the complete list. No information lost (D-01 rationale).
- This is a new `examine.ts` field (`kind: 'flagchip'` or carried on the `name` field's render) — keep the pure-helper testability: the priority resolution + chip label belong in `examine.ts` (node-tested), `ExaminePanel.svelte` does the render.

### ITEMUI-02 — Named quest links (D-04/D-05/D-06)

**Examine panel (`examine.ts` + `ExaminePanel.svelte`):**
- Add a new ordered field `kind: 'quests'` to `examine.ts`, positioned AFTER the wiki line and BEFORE `lastsynced` (so the detail flows name → flags → stats → notes → price → wiki → **quests** → last-synced). Omit entirely when there are zero `notes_link` quests (D-09).
- The field carries the list of `{ quest_name, source_url }` for `source === 'notes_link'` only. `examine.ts` is pure/DOM-free → it produces the data; `ExaminePanel.svelte` renders the row.
- Render: `Used in: ` (static label) followed by the comma-joined quest names. Each name is an `<a>` when `safeHttpUrl(source_url)` returns a URL, else plain escaped text.
- Reuse the EXISTING escaped-`{@html}` discipline: the wiki line is already the ONE sanctioned `{@html}` sink via `composeItemNote`. The quest links are the SAME class of escaped link. Two acceptable implementations (executor's choice, both honor the security contract):
  1. Extend `composeItemNote` (or a sibling pure composer) to emit the quest `<a>`s with `escapeHtml()` on names + `safeHttpUrl()` on hrefs, rendered through the same single `{@html}` sink. (Preferred — keeps one escaping chokepoint, vitest-provable.)
  2. Render the quest list with native Svelte `{#each}` + `<a href={safeHttpUrl(q.source_url)}>` and `{q.quest_name}` plain interpolation (Svelte auto-escapes the text; the href passes `safeHttpUrl` FIRST). No `{@html}` needed for this path.
- Link styling: identical to `.ex-wiki .tooltip-wiki-link` — `color: var(--accent)`, 1px accent underline, `text-decoration: none`, `target="_blank" rel="noopener"`.

**Item tooltip (`composeNotes.ts` + `ItemTooltip.svelte`):**
- The tooltip ALREADY composes `Used in quests: {names}` (`composeNotes.ts:154-161`) filtered to `notes_link`, capped at `MAX_QUEST_LINKS_IN_NOTE = 5`, escaped. This phase changes ONLY the rendering of each name from plain text to a clickable `<a>`:
  - `QuestLinkForNote` gains a `source_url` field (mirrors the backend `quest_links` carrying `SourceURL` per D-08).
  - For each `notes_link` quest, emit `<a class="tooltip-quest-link" href="${escapeHtml(safeHttpUrl(source_url))}" target="_blank" rel="noopener">${escapeHtml(quest_name)}</a>` when `safeHttpUrl` returns non-empty, else the escaped name as plain text.
  - Add a `.tooltip-popover :global(.tooltip-quest-link)` rule mirroring `.tooltip-wiki-link` (`color: var(--accent)`, 1px accent underline, `text-decoration:none`).
- The `Used in quests:` label, the `notes_link`-only filter, and the max-5 cap are all UNCHANGED.

**Fallback / pseudo-entry (D-06):** never render the `in_game_flag` row as a quest. When an item is a quest item with ONLY the `in_game_flag` entry, the existing generic `QUEST ITEM` (examine) / `Quest item` (tooltip) badge is the whole quest signal. The `notes_link` filter on every path enforces this — preserve it.

**Surfaces (D-04):** examine panel (Characters tab) + item tooltip (Inventory + Wishlist tabs). Dense DataGrid rows keep the compact yes/no QUEST-ITEM badge — no inline quest names in rows.
