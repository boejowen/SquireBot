<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parsed `content` -> SQLite rows | The parsed rows originate from watcher-supplied `content`; they cross into persistent storage here. Untrusted strings (character names, item names) must reach SQL only via parameterized placeholders. |
| uploading token's owner -> character ownership | The owner identity (resolved upstream in 11-04/11-05) governs which characters a write may touch; cross-owner writes must be rejected (V4). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.03-01 | Tampering | SQL injection via character name or item name in DELETE/INSERT | mitigate | Parameterized `?` placeholders everywhere in replace.go + binding.go; never build SQL by string concatenation (V5). Acceptance criteria grep-check for placeholder-only SQL. |
