# Phase 39 — UI Design Contract

> Visual and interaction contract for the Clicky/Haste facets + holdings↔catalog scope toggle. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Framing:** SquireBot has a MATURE, LOCKED design system (5 EQ themes, CSS-custom-property tokens, established master-detail + search idioms). This phase adds NO new aesthetic and NO new design primitive — it composes the NEW facet controls + scope toggle out of **existing idioms** (the `.seg`/`.seg-btn` segmented control from `guild-views`/WantlistPanel, the `aria-pressed` filter-button vocabulary, the reused `ExaminePanel`). Every new control reads the same `--bg`/`--panel`/`--text`/`--accent`/`--border`/`--font-display`/`--font-body`/`--weight-display` tokens, so all 5 themes are covered for free.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn — SvelteKit + Tailwind v4 + hand-authored components; `components.json` absent) |
| Preset | not applicable |
| Component library | none (bespoke Svelte 5 components; no Radix/Base-UI) |
| Icon library | `@lucide/svelte` (existing — `Search` glyph already used by SearchBox + inventory/wishlist search fields) |
| Font | Per-theme via `var(--font-display)` (Cinzel / Cinzel Decorative / MedievalSharp) + `var(--font-body)` (IM Fell English / Crimson Text / Inter). Self-hosted `@fontsource` (no Google Fonts runtime). |

**Theme contract (LOCKED — re-skin OUT OF SCOPE):** Source of truth `docs/design/eq-aesthetic-theme.md` → `web/src/lib/theme/themes.ts` (the `THEMES` registry) → `web/src/app.css` (`[data-theme="…"]` blocks emit the CSS custom properties). Every new control in this phase MUST style exclusively from those custom properties — **no literal hex, no new font, no new spacing scale**. A facet/toggle that hardcodes a color would break 4 of the 5 themes and violates the CLAUDE.md "derive from the theme doc" rule.

## Spacing Scale

Declared values (multiples of 4) — identical to the existing inventory/wishlist surfaces (`+page.svelte`), so the new controls sit on the same rhythm:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps inside a facet bar (chip↔chip is sm; icon↔label is xs) |
| sm | 8px | Facet chip ↔ chip gap; facet bar ↔ search field gap; segmented-control internal |
| md | 16px | Facet bar ↔ list gap; search field internal padding; `.seg-btn` horizontal padding |
| lg | 24px | Detail-column section gaps (header → examine → holders) — unchanged |
| xl | 32px | Shell gutters (inherited from shell-main) — unchanged |
| 2xl | 48px | Empty/no-results centering block (StateBlock) — unchanged |
| 3xl | 64px | Page-level — unchanged |

Exceptions: **44px minimum touch target** on every interactive control (facet chips, scope segments, search field, catalog rows). This is the established a11y exception already enforced across `.seg-btn`, `.row`, `.search`, and `Toggle.svelte` — the new controls inherit it (`min-height: 44px`).

## Typography

Unchanged from the locked system (3 sizes + 1 display tier, 1–2 weights per theme — `--weight-display` is 600 on four themes, 400 on minimalist). New controls reuse these exact roles:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | `var(--weight-display)` for names / 400 for prose (`--font-body`) | 1.5 |
| Label | 13px | `var(--weight-display)`, `letter-spacing: 0.05–0.08em`, `text-transform: uppercase` (`--font-display`) | 1.2–1.3 |
| Heading | 20px | `var(--weight-display)` (`--font-display`), `color: var(--accent)` | 1.2 |
| Display | 20px+ | `var(--weight-display)` (`--font-display`) | 1.2 |

Phase-specific role assignments:
- **Facet chip labels** ("Clicky", "Haste") → **Label** style (13px, `--font-display`, uppercase, 0.08em tracking) — matches `.seg-btn` so chips and the scope segments read as one control family.
- **Scope segment labels** ("Holdings", "Catalog") → **Label** style, verbatim `.seg-btn`.
- **Catalog-row item name** → **Body** name treatment (16px, `--font-display`, `--weight-display`) — identical to the holdings `.row-name`.
- **"not held in the guild" empty line** → **Body** prose (16px, `--font-body`, `opacity: 0.7`) — matches `.holders-empty`.

## Color

The 60/30/10 split is the theme contract, expressed as tokens (velious default values shown; the other 4 themes substitute via `[data-theme]`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` (`#060b18`) | Page background, the active-segment text color (on accent fill) |
| Secondary (30%) | `var(--panel)` (`#0f1729`) | Facet chips (inactive), scope segments (inactive), search field, catalog rows, the examine panel |
| Accent (10%) | `var(--accent)` (`#a8c5e0`) | **See reserved-for list below** |
| Destructive | `var(--destructive)` → `var(--status-missing)` | **Not used this phase** — no destructive action exists (D-04: no pin/no remove) |

**Accent reserved for** (this phase adds NO new accent surface beyond the established uses):
1. The **active** facet chip fill (`background: var(--accent)`, text flips to `var(--bg)`) and the **active** scope segment fill — identical to the existing `.seg-btn.active`.
2. Focus rings on every new control (`outline: 2px solid var(--accent)`) — the universal focus convention.
3. The selected-row left-border + selected item name (already the inventory `.row.selected` behavior — unchanged).
4. The catalog-row wiki link / price-other accent (reused via `ExaminePanel` + the existing `.row-wiki` / `.row-price` tokens — `--status-other` for price, `--accent` for the wiki link).

Color is **never the only signal** for facet/scope active-state (the inherited color-blindness obligation): an active facet chip ALSO carries `aria-pressed="true"`, and the active scope segment carries `aria-pressed="true"` — and the chip label text remains fully legible against the accent fill (the `--bg` text-color flip preserves contrast on all 5 themes, the same flip `.seg-btn.active` already ships). The active facet additionally shows a small filled-state affordance (a leading check/dot rendered in the current text color, never color-alone — see Component Inventory).

## Component Inventory (the load-bearing section for the executor)

Three new visual elements, all composed from existing idioms. No new shared component file is strictly required, but the planner MAY extract the facet bar into a small presentational component if both surfaces share it (recommended — see "Reuse note" at the end).

### 1. Facet bar — Clicky + Haste (SEARCH-04 / SEARCH-05, D-02)

**Idiom:** two independent **filter chips** (toggle-buttons), AND-combined. NOT the `Toggle.svelte` ON/OFF switch — that primitive is reserved for async server-write switches (notification prefs, kill-switches, the wishlist ping). A facet is a **client-side filter predicate** with no server write on the holdings path, so the lighter filter-button idiom (the `aria-pressed` + `class:active` vocabulary already used for `.tab` and `.seg-btn`) is the correct, established pattern.

**Markup contract (per chip):**
```
<button
  type="button"
  class="facet"
  class:active={clicky}
  aria-pressed={clicky}
  onclick={() => clicky = !clicky}
>Clicky</button>
```

**States:**
| State | Visual | Token |
|-------|--------|-------|
| Inactive (default) | `--panel` fill, `--text` label, 1px `--border` outline | matches `.seg-btn` inactive |
| Active | `--accent` fill, `--bg` label, plus a leading `✓`/dot in `--bg` (not color-alone) | matches `.seg-btn.active` |
| Hover (inactive) | `color-mix(in srgb, var(--accent) 8%, transparent)` background tint | the repo-wide row/btn hover |
| Focus-visible | `outline: 2px solid var(--accent); outline-offset: 2px;` | universal |
| Disabled | n/a — facets are never disabled (a facet with zero matches still toggles; the list shows the no-results state) | — |

**Behavior (D-02):**
- Neither chip active → **no facet filter** (today's behavior; full set shown).
- One chip active → that type only (Clicky → `is_clicky` items; Haste → `has_haste` items).
- Both active → items that are **both** Clicky AND Haste (AND-combined, the intersection).
- The two chips are **independent** — toggling one never clears the other.
- **Holdings scope = client-side filter** over the already-loaded `ItemRollup[]` (requires `is_clicky` / `has_haste` booleans on the rollup payload — Claude's-Discretion plumbing). **Catalog scope = server-side** facet params on `/api/v1/items/search` (`clicky` / `haste`). The UI control is IDENTICAL in both scopes; only the data source differs.

**Layout:** the facet bar sits **between** the search field and the result list, as a horizontal row: `[Clicky] [Haste]` with `gap: 8px`, left-aligned, wrapping on narrow viewports. On the Inventory tab the **scope segmented control sits in the same bar, to the LEFT of the facets** (scope is the coarser lens; facets refine within it) — `[ Holdings | Catalog ]   [Clicky] [Haste]`. A small `gap: 16px` separates the scope group from the facet group so they read as two distinct control clusters.

### 2. Scope segmented control — Holdings ↔ Catalog (SEARCH-06, D-03)

**Idiom:** the EXISTING `.seg` / `.seg-btn` segmented control (DUPLICATED verbatim into the inventory `+page.svelte` `<style>` — Svelte styles are component-scoped, so the class block must live locally; this is the sanctioned precedent from `guild-views` duplicating it from WantlistPanel). Two segments, mutually exclusive.

**Markup contract:**
```
<div class="seg" role="group" aria-label="Search scope">
  <button type="button" class="seg-btn" class:active={scope==='holdings'}
          aria-pressed={scope==='holdings'} onclick={() => setScope('holdings')}>Holdings</button>
  <button type="button" class="seg-btn" class:active={scope==='catalog'}
          aria-pressed={scope==='catalog'} onclick={() => setScope('catalog')}>Catalog</button>
</div>
```

**States:** identical to the locked `.seg-btn` (inactive `--panel`/`--text`; active `--accent` fill + `--bg` text; `border-left` rule between segments; 44px min-height; `outline-offset: -2px` focus ring).

**Behavior (D-03 — "a lens, not a reset"):**
- **Default = Holdings** ("who has one" — today's Inventory behavior + the guild's primary question).
- Flipping Holdings→Catalog (or back) **PERSISTS the typed query AND both active facet chips** — the toggle re-runs the same search/facets against the other data source. Switching scope MUST NOT clear `query` or the `clicky`/`haste` flags. Worked example (the §specifics test): type "cloak", activate Clicky, flip to Catalog → "clicky cloaks that exist" with no re-typing.
- A pinned/selected item: when flipping scope, the selection MAY clear if the selected item is absent in the new scope's result set (catalog is a superset of holdings, so Holdings→Catalog keeps any held selection; Catalog→Holdings clears a selection on an unheld item) — same stale-selection guard the inventory tab already runs on refetch.
- **Scope toggle appears ONLY on the Inventory tab.** The wishlist add-search is catalog-only (D-01) — it gets the facet chips but NO scope segmented control.

### 3. Catalog-scope result row + detail (SEARCH-06, D-04)

**Idiom:** REUSE the existing `ExaminePanel` UNCHANGED for the catalog-row detail (D-04). The catalog scope is a SUPERSET of holdings, so the Inventory tab's existing two-pane master-detail (list left, detail right) is reused as-is. The only catalog-scope deltas:

- **List rows in catalog scope** reuse the existing inventory `.row` shape (icon tile + name + headline + trailing price/wiki). The headline differs by held-ness:
  - **Held in catalog scope** → keep the existing `{summed_qty} · {N} holders` headline (the item is in holdings too; show its holders).
  - **Unheld (catalog-only)** → the headline reads the **empty line "not held in the guild"** (Body prose, `--text` @ 0.7 opacity, `--font-body`) in place of the holder count. The icon tile + name + price + wiki link still render.
- **Detail panel in catalog scope** → the same detail column: header (icon + name + meta) + the reused `<ExaminePanel slot={asSlot} charLastSeen="" />` + the HOLDERS section.
  - If the item **IS held** → the HOLDERS table renders its holders exactly as today (D-04: "a held item still shows its holders in catalog scope").
  - If the item is **unheld** → the HOLDERS section shows the empty line **"not held in the guild"** (replaces the `.holders-empty` "No holders" copy specifically for catalog scope — see Copywriting).
- **NO new action.** D-04 forbids a "pin to wishlist" affordance this phase — the catalog row carries ONLY the existing examine/wiki affordances (no Add, no Pin). The detail is read-only discovery.

**Graceful degradation (SC-4 / the deploy note):** catalog-scope facet coverage fills in after the next Sunday seed crawl; holdings facets work immediately. When the catalog scope is sparse/empty (coverage still filling), the result list shows the **standard no-results / empty state** (StateBlock `no-results` for a query with no catalog matches, or a phase-specific "catalog still filling in" hint — see Copywriting). The **holdings path NEVER blocks on catalog coverage** — Holdings scope + facets must work fully on day one regardless of catalog crawl state.

## Accessibility Contract

- Facet chips: `role` is the implicit `button`; **`aria-pressed`** carries the on/off state (the screen-reader-legible state, not color-alone). Each chip's accessible name is its visible label ("Clicky"/"Haste").
- Scope control: wrapped in `role="group"` with `aria-label="Search scope"`; each segment is a `button` with `aria-pressed`.
- All new controls: `min-height: 44px` touch target; `:focus-visible` ring `2px solid var(--accent)`; keyboard-operable (native `<button>` — Space/Enter activate).
- Reduced motion: no new animation is introduced; any hover transition inherits the global `prefers-reduced-motion` reset in `app.css`.
- Color-blind safety: active facet/scope state is conveyed by (a) `aria-pressed`, (b) the fill/label inversion, and (c) the leading filled-state mark on an active facet chip — three signals, never color alone.
