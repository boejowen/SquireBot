<objective>
Wire the NAME-KEYED catalog write into the weekly wiki items pass. The crawl already iterates the
widened held∪catalog union (Plan 01's `DistinctEnrichmentRefs`, now returning `EnrichmentRef` with a
`Held` flag); this plan BRANCHES the per-item write in `upsertItemAndQuests` on `ref.Held`:

- `ref.Held == true` → today's tx UNCHANGED: `item_master` (by EQ id) + `quest_items`.
- `ref.Held == false` → NEW tx: `catalog_enrichment` (by `norm_name`), NO `quest_items` write.

It also re-points the end-of-pass D-03 coverage slog line from the single-store `ItemMasterIconCoverage`
(removed in Plan 01) to the both-stores `CatalogIconCoverage`, so the maintainer's coverage diagnostic
reflects the whole ~4,343-item catalog, not just the ~953 held rows.

This REPLACES the Option-A behavior on master, where `upsertItemAndQuests` always upserted `item_master`
keyed by `ref.ItemID` (the PigParse id for catalog items) and the coverage read only `item_master`.

Purpose: an unheld catalog item now lands in `catalog_enrichment` by name (recovering the 43 the Option-A
collision guard dropped); the icon backfill (ENRICH-15) rides the existing 4-field freshness short-circuit
for free in BOTH stores.
Output: branched `enrich/jobs/wiki.go`, updated `enrich/jobs/wiki_test.go`.
</objective>
