# Phase 17 — UI Design Contract

> Visual and interaction contract for the **`/account`** page — the all-members "your account / watcher codes" area (LINK-04 / LINK-05) added to the live SquireBot SvelteKit site. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase EXTENDS the shipped P14/P15 design system — it does NOT reinvent it.** The site is live at https://squirebot.quest with a complete, checker-approved P14 contract (`.planning/phases/14-web-frontend/14-UI-SPEC.md`), the P15 forms+login contract (`.planning/phases/15-admin-web-forms-login/15-UI-SPEC.md`), and an implemented token system in `web/src/app.css`. Every new surface MUST reuse the existing CSS custom properties (`--bg --panel --text --accent --border --status-ok --status-missing --status-other --destructive --font-display --font-body --weight-display`), the 5-theme `[data-theme]` registry (velious default, WEB-05), the `SiteShell`, `StateBlock`, `FormField`, `ConfirmDialog` components, and the existing control styling (the `.field` select/input, the `.primary` button, the `.primary.destructive` button, the `.form-card`). All tokens below restate the shipped contract verbatim for the executor's convenience — they are NOT new values.
>
> **Decisions are LOCKED (17-CONTEXT D-06..D-10).** Route = `/account`, nav-visible-to-every-logged-in-member (NOT officer-gated), single combined page, auto-label `#N` + created date + last-seen, confirm-before-commit revoke leaning. No new design questions were opened; every visual/interaction choice below is either locked in 17-CONTEXT or inferred from the shipped system + the `/char-meta` member-page precedent.
>
> **Phase scope vs. siblings:** `/account` is the **login-only (all-members)** sibling of the officer-gated `/admin` forms. It mirrors `/char-meta` exactly (member-accessible plain nav link, `.form-card` shell, no officer check, `AuthGate`-gated at the layout). Its **genuinely new surface** is: (1) the **show-once plaintext code panel** (LINK-04 — the most security-sensitive element), (2) the **codes list with per-code `#N` / created / last-seen identity + a Revoke control** (LINK-05), and (3) the **confirm-before-commit Revoke flow** (mirrors `EvictionForm` + `ConfirmDialog`). Those three, plus the Copywriting Contract, are this spec's net-new contribution.

## Color

Restates the **velious default** P14/P15 palette (the single-palette table; all five themes ship via `[data-theme]`, see P14 § Theme Catalog — unchanged). All values are existing CSS custom properties. P17 introduces **no new color token** — it reuses `--destructive` (= per-theme `--status-missing`) for the Revoke affordance, exactly as P15's eviction/admin-remove do.

| Role | Value (velious) | Usage |
|------|-------|-------|
| Dominant (60%) | `#060b18` (`--bg`, page) / `#0f1729` (`--panel`, surfaces) | App background + the `.form-card` page surface + the code-row surfaces + the dialog. The two-step dark base. |
| Secondary (30%) | `#1a2438`→`#0f1729` (header gradient) / `#d4dee8` (`--text`) / `#4a6585` (`--border`, dividers, card/row borders) | Structural chrome: form-card border, code-row separators, section divider, secondary/meta text. |
| Accent (10%) | `#a8c5e0` (`--accent`, icy blue) | **Reserved-for list below — never "all interactive controls".** |
| Destructive | **`--destructive`** = `#e88a8a` (velious `--status-missing`) / per-theme | **Reuse the existing `--destructive` token** (do NOT hardcode a new red — keeps it theme-consistent across all five themes, identical to `EvictionForm`'s `.primary.destructive`). Reserved for the **Revoke confirm button + the revoke consequence callout in the dialog** only. |

**Accent (`--accent`) reserved for, and ONLY for (continues the P14/P15 list):**
1. The **primary action button** — **Generate a new code** — accent fill with `--bg` text, mirroring the shipped `.primary` / `.retry`.
2. **Focus rings** on every control (the generate button, copy button, revoke button, dialog) — `outline: 2px solid var(--accent)`, matching all shipped controls.
3. The **active "Account" nav entry** in the shell (same hover/active treatment as `.char-meta-nav` / `.tab`).
4. The **copy-to-clipboard** glyph + its **"Copied!"** success swap (the `check` glyph + label may use `--status-ok` for the success tick — see Status note below — while the resting `copy` glyph uses accent).
5. The **show-once panel's highlight border / accent rule** that marks it as the prominent, distinct credential reveal (a 2px accent left-border or top-rule + a faint `color-mix(var(--accent) ~6–10%)` tint fill — the same low-alpha accent wash the shipped zebra/shimmer use).
6. Lucide glyphs at small sizes (copy, key/plus, the resting state of icons).

Body text, the plaintext code itself (renders in `--text`, NOT accent — it must be high-contrast readable, not styled as a link), code-row meta, created/last-seen text, inactive controls, and row backgrounds do **NOT** use accent. **`--destructive` is the ONLY non-accent chrome color** and is confined to the Revoke confirm button + its consequence callout.

**Status / data-encoding colors (reused from P14):**
- The **"Copied!"** confirmation tick MAY use `--status-ok` (the existing success/positive token, e.g. as `EvictionForm`'s `.result.success` does) so the success feedback reads as "done" — paired with the literal word "Copied!" (color is never the only signal).
- The **last-seen freshness** MAY reuse the P14 freshness encoding subtly: a recent "last used" (e.g. <7d) is the default `--text`; a stale/never-seen code MAY carry a faint `--status-other` / muted tint or an explicit "never used" word — but **keep it text-first** ("last used 5 min ago" / "never used yet"), color is optional decoration only. Do NOT introduce a red "dead PC" alarm — a never-used code is normal (the guildie may not have pasted it yet).

**Contrast:** all five themes already clear WCAG AA for `--text`-on-`--panel` (P14). The new surfaces (show-once panel, code rows) use the same pairing, so they inherit AA. The plaintext code in `--text` on the accent-tinted panel must still clear AA — the tint is low-alpha (≤10%) over `--panel`, so it does; the executor MUST verify on **Heavy** (parchment/light-row theme) where the accent tint behaves differently, exactly as P14/P15 budgeted Heavy QA. The Revoke destructive button uses `--bg` text on `--destructive` fill (and `--accent` text on Heavy, mirroring `EvictionForm`'s `:global([data-theme='heavy']) .primary.destructive` rule).

## Page Layout & Information Architecture

The single `/account` page composition (D-09 / D-10). One member-accessible route, gated only by the layout's `AuthGate` (`RequireSession` on the backend; the page itself has **no officer check** — it is the login-only sibling of `/char-meta`).

**Where it sits (nav contract):**
- A new **"Account"** nav entry in `SiteShell`, rendered under `session?.authenticated` (every logged-in member), **alongside** the existing `char-meta-nav` "Character details" link and the `SessionIndicator` — **NOT** inside the `session?.isOfficer` Admin block. Styled identically to `.char-meta-nav` (plain `<a href="/account">`, 13px/600 display, uppercase, 0.08em, 44px min, accent-on-hover). Suggested label: **Account** (or "Watcher codes" — pick the shorter "Account" to leave room for the page to host future self-service per D-09; the page heading carries the fuller "Your watcher codes").
- Direct nav by an unauthenticated user is caught by the layout `AuthGate` → `LoginScreen` (no page-level gate needed). A non-member is caught by `NotMemberScreen`. The page assumes an authenticated member.

**Page composition (top → bottom), all inside one `.form-card` (24px `lg` padding, `--panel`, `--border`, 6px radius — matches `/char-meta`):**

1. **Page heading** (Heading 20px / `--font-display`): **"Your watcher codes"**. A one-line Body purpose sits under it (see Copywriting): what a watcher code is and that it links this PC to their account.
2. **Generate action** (`lg` gap below the heading): the **Generate a new code** primary button (accent fill). No inputs above it — owner is session-derived (D-02), and there is **no "name this device" field** (D-06). While the mint is in-flight the button shows an in-flight label ("Generating…", disabled, mirroring `EvictionForm`'s `{evicting ? 'Evicting…' : ...}` pattern).
3. **Show-once plaintext panel** (LINK-04 — appears **inline directly below the generate action** only after a successful mint; `md` 16px padding; visually distinct highlight — see § Show-Once Panel). It is **transient**: dismissible, and **never re-rendered after a reload or revisit** (hash-only at rest). On dismiss it collapses and the newly-minted code is already present in the list below as `#N`.
4. **Section divider** (`xl` top-margin + 1px `--border` top-rule, matching `EvictionForm`'s `.restore-section` separator).
5. **Codes-list section** (LINK-05): a section heading ("Your active codes (N)") + the list of the caller's active codes (`#N` + created + last-seen + Revoke per row), **or** the `no-codes` empty state when the list is empty.

**Visual hierarchy:** the **Generate** CTA is the single accent primary at rest. When a code has just been minted, the **show-once panel** becomes the most prominent element on the page (highlight border + the large selectable token) — it should visually dominate until dismissed, because missing it means the guildie loses the credential. The codes list is secondary, quiet chrome.

**Responsive:** the `.form-card` is `max-width: 720px` (matches `/char-meta`/`/admin`). Code rows lay out as a flex row (`#N` + meta on the left, Revoke on the right, matching `EvictionForm`'s `.restore-row` `space-between`); on narrow screens (<640px) the Revoke button may wrap below the meta. The show-once panel's token + copy button stack vertically on narrow screens so the long token never overflows.

## Show-Once Plaintext Panel (LINK-04)

The single most security-sensitive surface in the phase: the freshly-minted code's plaintext, shown **exactly once**. Hash-only at rest (`auth.MintCode`), so after dismissal / reload it is **gone forever** — the contract must make that unmissable.

**Appearance (prominent + visually distinct):**
- A highlighted callout, distinct from ordinary form chrome: `--panel` surface with a **2px `--accent` left-border (or top-rule)** + a faint `color-mix(in srgb, var(--accent) ~8%, transparent)` tint fill (the same low-alpha accent wash used by the shipped zebra/shimmer), `md` (16px) padding, 6px radius. This makes it read as "important, fresh, copy-me" without inventing a new color.
- **Heading** (Heading 20px): **"Copy your new watcher code now"**.
- **The token** on its own line: rendered in `--text` at Body 16px with `font-variant-numeric: tabular-nums`, ~0.04em letter-spacing, `user-select: all`, word-break enabled so a long base64 token wraps rather than overflows. **Not accent** (it is data to read, not a link).
- **Copy-to-clipboard button** immediately beside/below the token: a `.primary`-style accent button with a `copy` glyph + label **"Copy"**. On click → writes to clipboard (`navigator.clipboard.writeText`) → swaps to a **`check` glyph + "Copied!"** (in `--status-ok`) for ~2s, then reverts. If the Clipboard API is unavailable/denied, the token stays `user-select: all` so a manual select-copy still works (graceful fallback; never block on clipboard permission).
- **Paste-into-watcher instructions** (Body 16px) below the token — the exact steps, aligned with the v2.0 watcher "paste your guild code" onboarding copy (see Copywriting).
- **"You will not see this again" warning** (Body 16px) with a `triangle-alert` glyph in `--destructive`, in a consequence callout matching `EvictionForm`'s `.consequence` treatment (`--destructive` 1px border + ~8% destructive tint) — so the irreversibility reads as a real, theme-consistent warning.
- A **Dismiss** affordance (a quiet text/ghost button "Done" or an `x`) that collapses the panel. Dismiss is purely cosmetic — the code is already in the list as `#N`; dismissing does NOT revoke it.

**At rest / after reload (LINK-04 invariant):** the panel **never re-appears**. The list below shows the code as **`#N`** (created date + last-seen) — **never the plaintext** (it is not retrievable; hash-only at rest). The plaintext is held only in component state for the lifetime of the panel; **it is never persisted to `localStorage`, never logged, never re-fetched** (carries forward the V6/V7 "never slog/persist the plaintext" discipline from the watcher bearer token to the web reveal).

## Codes List & Per-Code Identity (LINK-05)

The caller's **own** active codes, scoped server-side to their owner (never another owner's codes, D-08). Loaded on mount (`loading` → `error`-with-Retry → list / empty), the same lifecycle as `EvictionForm`.

**Section heading:** **"Your active codes (N)"** (Heading 20px), N = count of active (non-revoked) codes.

**Row layout (per code — mirrors `EvictionForm`'s `.restore-row`):** a flex `space-between` row (`sm` 8px vertical × ~12px horizontal padding, 1px `--border`, 4px radius, `--panel`):
- **Left (identity):**
  - **`#N` ordinal** — a Label-styled chip / lead (13px/600 display), the auto-label per D-06 (no device-name field). N is the per-owner code ordinal (1-based, stable).
  - **Created date** (Body 16px or 13px meta, muted ~0.75 opacity): "Created <date>" in a human format (e.g. "Created May 12, 2026").
  - **Last-seen** (Body meta, muted): **"last used <relative>"** (D-07) — relative-time format ("last used 5 min ago" / "last used 3 days ago"). A code that has never authenticated shows **"never used yet"** (not an error — the guildie may not have pasted it). This is the "which PC is this / is it dead?" signal (the deliberate substitute for a device name).
- **Right (action):** a **Revoke** button (see § Revoke Interaction). On narrow screens it wraps below the identity block.

**Active vs just-revoked state:** revocation is **optimistic-collapse** — on a confirmed revoke commit, the row is removed from the list (matches `EvictionForm` dropping the evicted owner from `owners`), and a brief `--status-ok` success line confirms it ("Code #N revoked."). There is no persistent "revoked" row state on this page (revoked codes are simply gone from the active list; per-token revoke is one-way for the watcher — re-link is additive via a new code, LINK-03). If a revoke fails, the row stays and an inline `--status-missing` error appears (mirrors `EvictionForm`'s `.result.error`).

**Empty state (`no-codes`):** when the caller has zero active codes (e.g. a brand-new guildie before their first mint, or after revoking their last code), show a `StateBlock kind="no-codes"`: heading **"No watcher codes yet"** + body pointing at the Generate CTA above (copy below). The Generate button remains visible above the empty state so the next step is one click away.

## Revoke Interaction (LINK-05)

**Recommendation: confirm-before-commit, reusing the shipped `ConfirmDialog`** (D-10 leans this way; 17-CONTEXT § Discretion permits instant-with-toast given the additive/recoverable model, but the destructive framing — "this stops that PC from uploading" — and consistency with `EvictionForm`'s mandatory confirm make a confirm dialog the right call). **Lock: confirm-before-commit via `ConfirmDialog`.**

**Flow (mirrors `EvictionForm`'s `openRestoreConfirm` → `ConfirmDialog` → `doRevoke`):**
1. The per-row **Revoke** button opens `ConfirmDialog` (destructive variant) for that specific code, carrying `#N` into the heading/body.
2. The dialog states the consequence (that PC stops uploading) + that it does NOT affect the guildie's other codes (per-token, D-08) + that they can always generate a fresh code (LINK-03, so it's recoverable-by-re-mint). Confirm label: **"Revoke code #N"** (destructive-colored). Default focus on **Cancel** (destructive is never the default focus — matches P15's dialog rule).
3. Esc / backdrop-click / Cancel all dismiss with no side effect. Only the explicit destructive confirm fires the revoke (sets `guild_code.disabled_at` server-side).
4. On success: optimistic-collapse the row + a `--status-ok` confirmation line ("Code #N revoked. That watcher will stop uploading on its next attempt."). On failure: keep the row + a `--status-missing` inline error ("Couldn't revoke code #N. No change was made.").

**Button styling:** the per-row Revoke button is the **destructive** variant (`--destructive` fill / `--bg` text; `--accent` text on Heavy) **only inside the confirm dialog**; the **resting per-row button** may be a quieter destructive-text/ghost treatment (`--destructive` text on `--panel`, like a subdued "Remove") so the active list isn't a wall of red fills — the full destructive fill is reserved for the dialog's confirm, exactly as P15 keeps the destructive fill on the dialog confirm rather than the trigger. (Executor discretion within: resting Revoke = destructive-text ghost; dialog confirm = destructive fill.)

## Accessibility & Interaction Notes

- **Keyboard:** the Generate button, the Copy button, each Revoke button, and the dialog are Tab-reachable in source order; `ConfirmDialog` (reused) traps focus and restores it to the Revoke trigger on close; Esc dismisses the dialog. Visible focus ring in `--accent` everywhere (matches shipped controls). The plaintext token is selectable via keyboard (`user-select: all` + it is in normal flow text).
- **Touch:** 44px min targets on the Generate / Copy / Revoke buttons and dialog actions (see Spacing exceptions). The dialog dismisses on outside-tap.
- **Screen readers:** the show-once panel announces via `aria-live="polite"` when it appears (so a SR user knows the one-time code is now present); the **"Copied!"** swap announces via `aria-live="polite"`; the codes list is a real `<ul>`/`<li>`; the `#N` chip and dates are plain text; the revoke success/error lines are `aria-live="polite"` (matches `EvictionForm`'s `.result`); the dialog is `role="dialog" aria-modal="true"` labelled by its heading (reused from `ConfirmDialog`). The `triangle-alert` warning glyph is decorative (`aria-hidden`) — the warning text carries the meaning.
- **Color is never the only signal:** the show-once warning pairs the destructive tint with the explicit "only time you'll see this" copy + the triangle glyph; "Copied!" pairs the `--status-ok` tick with the literal word; last-seen is always text ("last used …" / "never used yet"), never color-only.
- **Reduced motion:** the global `prefers-reduced-motion` rule in `app.css` already makes transitions instant; the show-once panel reveal, the "Copied!" swap, and the dialog open/close MUST honor it (no entrance animation under reduced motion).
- **Auth state is server-truth:** the page treats a `401` (no/invalid session) by bubbling to `AuthGate` → `LoginScreen` (reuse the existing `AUTH_GUARD_KEY` router pattern from `EvictionForm`); a generate/list/revoke that returns a not-authorized/error code routes to the matching inline message — never assume the hidden-from-non-members nav is the boundary (the backend `RequireSession` + owner-scoping is the gate, D-02/D-08).
