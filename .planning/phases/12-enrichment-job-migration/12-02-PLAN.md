<objective>
Port the four pure, host-agnostic enrichment parsers from TypeScript to Go — `parseToRows` (PigParse), `parseItempage` (wiki item summary + SHA-1), `parseClassPage` (per-class spell list), `parseGearTierPage` (Velious gear tiers) — plus the `eq-constants.ts` lookup tables, into a new `internal/backendsrv/enrich` package. They transliterate 1:1; the only Apps Script API any of them touches is `Utilities.computeDigest` (SHA-1), which becomes `crypto/sha1`. Reuse the existing JSON fixtures (copied into `testdata/`) so parity with the TS output is byte-checkable.

Purpose: These parsers are the I/O-free heart of both jobs. Keeping them pure (no net/http, no DB) makes their tests fast + deterministic and makes byte-for-byte parity with the Sheet (the D-7 acceptance proof) trivial. They are independent of the schema (Plan 01) and the HTTP client (Plan 03), so this plan runs in parallel with both.
Output: 5 parser/const Go files + their fixture-driven tests + the copied `testdata/` fixtures.
</objective>

<!-- The pure-parser Go analog + the SHA-1 idiom. The TS sources are the port spec; read them in full per task. -->

Pure-parser shape to mirror — internal/parse/inventory.go Parse (lines 53-81): I/O-free, returns typed error, SILENTLY SKIPS malformed rows (never aborts the whole parse on one bad row), package-level doc-comment style.

SHA-1 idiom (replaces Utilities.computeDigest) — Go gives UNSIGNED bytes, so the TS signed-byte fix-up (`b < 0 ? b + 256`) is DROPPED:
```go
import ("crypto/sha1"; "encoding/hex")
func sha1Hex(s string) string { h := sha1.Sum([]byte(s)); return hex.EncodeToString(h[:]) }
```
Output is byte-identical lowercase hex to the TS computeSha1Hex → the D-7 SHA-1 parity check holds. (crypto/sha1 here is a content fingerprint, NOT a security hash — acceptable per RESEARCH Security V6.)

Fixture shapes (RESEARCH §"Fixture Reuse"):
- Shape A (PigParse) — `pigparse-getall-1.json` is a flat `[{i,t,n,l,tc,ta,t30,a30,t60,a60,t6m,a6m,t90,a90,ty,ay}]` array; `os.ReadFile` → pass bytes straight into ParseToRows. Contains item 19450 twice (t=0 AND t=1) — the duplicate-id case.
- Shape B (wiki) — `wiki-parse-*.json` / `wiki-class-*.json` / `wiki-velious-*.json` are the full MediaWiki `action=parse` envelope `{"parse":{"title":"…","wikitext":{"*":"<wikitext>"}}}`. Tests must `json.Unmarshal` and pull `parse.wikitext["*"]` (+ `parse.title`) THEN call the parser.

Package naming: `enrich` (short; avoids colliding with the watcher's internal/parse). eqconst must stay dependency-free (imported by wikispell/wikigear) to avoid an import cycle.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external response bytes → parser structs | The PigParse JSON and the P1999 wikitext are UNTRUSTED input the parsers consume. The parsers are pure (no SQL, no network) — the only risk is a malformed/oversized input crashing the parser or producing garbage structs. No SQL boundary here (that is Plan 01); no network boundary here (that is Plan 03). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.02-01 | Denial of Service | ParseToRows / ParseItempage / ParseClassPage / ParseGearTierPage | mitigate | Parsers tolerate malformation rather than panic: ParseToRows skips invalid rows and errors only past the 1% threshold (ported verbatim); the wiki parsers guard `MIN_WIKITEXT_LENGTH` and return `ok=false` on too-short/redirect input (V5 input validation). A bad page yields zero rows / a typed reason, never a panic. (The byte-size cap that bounds memory lives upstream in politefetch — Plan 03 `io.LimitReader`.) |
| T-12.02-02 | Tampering | sha1Hex content fingerprint | accept | crypto/sha1 is used ONLY as a change-detection fingerprint over wikitext (not a security hash; no integrity/authentication claim) — acceptable per RESEARCH Security V6. Collision-resistance is not relied upon. |
| T-12.02-03 | Information Disclosure | parser code paths | mitigate | The parsers themselves do no logging of raw content; if any debug log is added it logs counts/keys only (V7). No secrets exist in this path (public API responses). |

Spoofing / Repudiation / Elevation of Privilege: N/A — pure functions, no identity, no auth, no privilege boundary. SSRF / secret-leak: N/A — no network calls (Plan 03), no secrets. SQL injection: N/A — no SQL in this plan (Plan 01 owns the parameterized writes; the structs these parsers emit are bound as `?` placeholders there). None is severity `high`.
