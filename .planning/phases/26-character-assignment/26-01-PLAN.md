<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request body → store mutator | character_id (and officer-path target assignee) is untrusted input; identity is NEVER from the body (enforced in 26-02; the store takes callerID as a param). |
| caller (member) → another member's row | release/cancel are owner-scoped; a foreign row must be a silent no-op, never an error/leak. |
| caller (just-demoted officer) → officer mutator | TOCTOU window between route gate and tx. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Elevation | OfficerAssignTx/RemoveAssignTx/Approve/Deny/DesignateCharTx | mitigate | `IsOfficerTx(ctx, tx, callerID)` is the FIRST in-tx statement (authorize-under-tx, WR-04); returns ErrNotAuthorized when !ok. A just-demoted officer cannot land a final mutation. |
| T-26-02 | Tampering | ApproveRequestTx (contested-claim race) | mitigate | Approving a request denies ALL other pending requests for that character_id in the same tx; the partial-unique pending index prevents single-member double-filing (Pitfall 3). |
| T-26-03 | Tampering | character_assignment single-assignee | mitigate | `character_id PRIMARY KEY` makes two-members-one-char structurally impossible; reassign is ON CONFLICT upsert, never a second row. |
| T-26-04 | Elevation/Tampering | claim/assign a shared char | mitigate | ClaimCharTx/OfficerAssignTx reject is_bank_toon=1 OR is_guild_bot=1 (ErrCharShared); DesignateCharTx clears assignment + denies pending requests — the exemption is enforced bidirectionally in the store (Pitfall 6). |
| T-26-05 | Spoofing | release/cancel on a foreign row | mitigate | DELETE/UPDATE scoped `AND discord_user_id=caller` (release) / `AND requester=caller` (cancel) → affects 0 rows → silent no-op (returns false), never leaks existence. |
| T-26-06 | Tampering | SQL injection via character_id / assignee | mitigate | Parameterized `?` placeholders only (codebase-wide V5 rule); no string concatenation. |
| T-26-07 | Tampering | bank-view merge after relaxing single-bank | accept | Multiple guild banks are now INTENTIONAL + officer-only; the consolidated Char-column grid disambiguates. The 2-bank bank_test proves no merge (Pitfall 5). Risk: an officer mis-designates — low, recoverable, audited (in 26-02). |
</threat_model>
