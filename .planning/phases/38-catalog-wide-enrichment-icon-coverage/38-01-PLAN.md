<objective>
Lay the NAME-KEYED foundation for catalog-wide enrichment (D-04 reversed → name-keyed). This plan
adds the new `catalog_enrichment` table (migration 00017), its store layer (upsert + freshness getter
mirroring `item_master`'s, re-keyed on `norm_name`), and reworks `store/itemids.go` so the enrichment
ref union (a) DROPS the Option-A id-collision guard, (b) carries a `Held` flag per ref, and (c) the
icon-coverage diagnostic reads BOTH stores.

This REPLACES the Option-A code currently on master (`DistinctEnrichmentRefs` with its
`item_id NOT IN (SELECT item_id FROM item_master)` guard, and the single-store `ItemMasterIconCoverage`).
`item_master` and its held write path (`UpsertItemMasterTx` / `GetItemMasterFreshnessTx`) stay
BYTE-FOR-BYTE unchanged — held readers (Phases 31/32/37) have zero blast radius.

Purpose: a catalog-only (unheld) item has NO EQ-inventory item_id, so it cannot key an `item_master`
row without colliding; name-keying in a separate table covers ALL ~4,343 catalog items with no drop
(recovering the 43 the Option-A guard silently dropped — Cured Silk Gi, Ancient Tarnished Breastplate,
Etched Velium Brawl Stick, …).
Output: migration 00017, `store/catalogenrich.go` (+ test), reworked `store/itemids.go` (+ test),
extended `migrations/migrate_test.go`. No job change yet — Plan 02 (Wave 2) branches the write onto
these methods.
