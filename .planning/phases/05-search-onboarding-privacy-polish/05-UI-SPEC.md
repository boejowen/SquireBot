## Spacing Scale

Declared values (4-point scale; multiples of 4 only):

| Token | Value | CSS variable | Usage in sidebar |
|-------|-------|--------------|------------------|
| xs | 4px | `--space-xs` | Icon gaps, tight inline padding, gap between item name and meta on result row |
| sm | 8px | `--space-sm` | Form-row vertical rhythm, padding inside input/select, gap between filter controls |
| md | 12px | `--space-md` | Padding between major sections (search input → results), group header inset |
| lg | 16px | `--space-lg` | Outer sidebar padding, panel padding, gap above "Recent:" footer |
| xl | 24px | `--space-xl` | Empty-state vertical padding, error-state vertical padding |

**Sidebar outer width:** 300px (locked by SEARCH-01). Outer padding 16px on left/right; 12px top, 16px bottom. No horizontal scroll permitted — content wraps or truncates with ellipsis at 268px content width.

**Touch / click targets:** Result-group expand/collapse header and "Recent:" query links require minimum 32px height (Apps Script sidebar is mouse-driven, not touch — 32px is the click-comfort target).

**Exceptions:**
- 1px borders are allowed (CSS `border: 1px solid …`) — not on the 4-point scale but required for visual separation
- Inline 2px focus-ring outline (browser accessibility default) — preserved, not overridden

## Typography

All sidebar typography is theme-driven via `var(--font-body)` / `var(--font-header)` injected at template render time. Sizes and weights are LOCKED across themes; only the font family varies.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label (small/meta) | 11px | 400 | 1.4 | Sidebar description text, second-line meta (wiki link, price), "Recent:" prefix, group-collapsed-count text |
| Body | 13px | 400 | 1.5 | Item names on result rows, char/location/count, input/select text, button text |
| Heading (group) | 13px | 600 | 1.4 | Group header (item name + char-count badge), section headings inside sidebar |
| Display (sidebar title) | 16px | 600 | 1.3 | "Search" sidebar title (h3 in the header) — uses `var(--font-header)` instead of `var(--font-body)` |

**Rationale for tight scale:** Apps Script sidebar is 300px wide. Any size above 16px crowds the panel. The 11/13/16 scale gives clear hierarchy (label vs body vs title) without forcing more than 4 sizes — matches the 3-4-size design-system rule.

**Truncation:** Long item names exceeding row width truncate with CSS `text-overflow: ellipsis; white-space: nowrap; overflow: hidden`. Full name available via `title` attribute (browser tooltip) and via the existing wiki-summary hover (D-05).

**No italics, no underline except for hyperlinks** (wiki links on line 2 of result row, "Recent:" query buttons styled as link-like).

## Color

**Source-of-truth: `apps-script/src/lib/themes.ts` `THEMES` registry.** Do NOT hardcode hex values in the sidebar HTML/CSS. The Phase 5 sidebar template MUST inject the active theme's tokens as CSS custom properties at server-render time:

```html
<style>
  :root {
    --bg: <%= theme.headerBg %>;       /* sidebar panel header background */
    --bg-row: <%= theme.rowAltBg %>;   /* result row & body background */
    --fg: <%= theme.rowFg %>;          /* primary text */
    --fg-header: <%= theme.headerFg %>;/* header text + accent */
    --accent-bg: <%= theme.accentBg %>;/* button background, group-header background */
    --accent-fg: <%= theme.accentFg %>;/* button text */
    --font-header: <%= theme.fontFamily %>;
    --font-body: <%= theme.fontFamily %>;  /* same family — themes are font-coherent */
  }
</style>
```

For `sheets-default` (theme = `null`), the template emits NO `<style>` token block — the sidebar renders with browser defaults plus the structural CSS below. This keeps the `sheets-default` opt-out promise intact for the sidebar.

**60/30/10 split (mapped onto sidebar surfaces):**

| Role | CSS variable | Source token | Usage |
|------|--------------|--------------|-------|
| Dominant (60%) | `--bg-row` | `theme.rowAltBg` | Main sidebar panel background, body area, where result rows live |
| Secondary (30%) | `--bg` | `theme.headerBg` | Sidebar title strip, group-header background strip, footer strip |
| Accent (10%) | `--accent-bg` + `--accent-fg` | `theme.accentBg` / `theme.accentFg` | **Reserved for: primary Search button, focused input/select border, group-count badge (e.g. "9 chars"), "Recent:" query-button hover state.** Never on result-row text. Never on body text. |
| Destructive | `#c00` | hardcoded (theme-agnostic) | Error message text (`#msg.error`), eviction confirmation "Evict <email>" button |

**Accent reserved for (explicit list — NOT "all interactive elements"):**

1. Primary Search submit button background + text
2. Focused state of the search input and Char/Slot filter dropdowns (1px border)
3. Group-count badge on auto-collapsed groups (`Bone Chips · 9 chars [expand]`)
4. "Recent:" footer query-button hover/active state
5. Eviction sidebar's primary "Evict" button (same accent — destructive uses red text only, on the same accent panel)

**NOT accent-colored (LOCKED to prevent accent inflation):**

- Wiki hyperlinks on result row line 2 — use `--fg` with `text-decoration: underline`. Avoids two accent colors fighting.
- Result row hover state — use a subtle 4% lightness shift on `--bg-row` (CSS `filter: brightness(0.96)`), not an accent fill.
- Section dividers — 1px solid `--bg` (the secondary token, already in palette).

**Sheets-default fallback colors** (when theme = `null`, no `:root` tokens emitted):

| Role | Hex |
|------|-----|
| Background | `#ffffff` (browser default) |
| Text | `#222222` |
| Accent (button) | `#1a73e8` (Google Sheets-native blue) |
| Border / divider | `#dadce0` |
| Error | `#c00` |

These five hexes are the ONLY hardcoded colors in the sidebar; everything else flows through CSS custom properties.

## Interaction Contract

### Search sidebar — keyboard behavior

| Key | Action |
|-----|--------|
| `Enter` (in search input) | Submit search |
| `Esc` (anywhere in sidebar) | Clear search input + reset result list to empty state |
| `Tab` | Standard tab order: input → Char filter → Slot filter → Search button → result group headers → Recent buttons |
| `Space` or `Enter` (on focused group header) | Toggle expand/collapse |

Focus management: on sidebar open, focus jumps to the search input (`autofocus` attribute is enough — Apps Script sidebars are reliable here).

### Search sidebar — states

State machine (each state has a visual treatment driven by CSS class on the `<body>` or root `<div>`):

| State | Trigger | Visual treatment |
|-------|---------|------------------|
| `idle` | Sidebar just opened, no query yet | Empty-state heading + body copy centered in the result area; "Recent:" footer shown if history exists |
| `loading` | `Searching…` between submit and result | Search button disabled + label changes to "Searching…"; result area shows a 1-line skeleton (3 grey rectangles, 8px tall, 80%/60%/70% width, no animation needed — keep CSS minimal per perf budget); no spinner |
| `results` | Results returned (≥1 match) | Groups rendered; first group auto-expanded if it's the only one; auto-collapse groups with >5 chars |
| `no-results` | Substring returned zero AND fuzzy fallback ran | "No matches for …" heading + did-you-mean line; clickable suggestions |
| `error` | `google.script.run` failure | Red error text below search button; search button re-enables; previous results (if any) stay visible |

Progressive rendering: result rows render incrementally as groups complete (don't wait for the full 12-tab scan to finish before painting the first group). Aligns with the <2s budget — first paint should land within ~500ms even if total scan takes 2s.

### Search sidebar — result row component

```
┌─────────────────────────────────────────┐  ← group-header strip (--bg)
│ Bone Chips                              │     13px / weight 600 / --fg
├─────────────────────────────────────────┤
│ Findom: General-1, count 4              │     13px / weight 400 / --fg
│ Wiki · 1 pp                             │     11px / weight 400 / --fg, wiki underlined
├─────────────────────────────────────────┤
│ Slampeach: Bank-12, count 23            │
│ Wiki · 1 pp                             │
└─────────────────────────────────────────┘
```

Padding: 8px vertical, 16px horizontal inside each row. Group header: 8px vertical, 16px horizontal, background `--bg`. Row dividers: 1px solid `--bg` (the secondary color, 30% role).

Collapsed group:

```
┌─────────────────────────────────────────┐  ← clickable, --bg
│ Bone Chips · 9 chars  [expand]          │     accent-fg color on the count badge
└─────────────────────────────────────────┘
```

### Eviction sidebar — flow

1. Sidebar opens, email dropdown populated from `_char_owner.owner_email` distinct list.
2. User picks email → affected-chars preview renders (read-only list of `char_name`s).
3. User clicks `Evict` button → native browser `confirm()` modal appears with confirmation copy (above).
4. On confirm → server-side cascade writes `is_removed=TRUE` for all matching rows + writes `_meta.eviction_log` JSON entry.
5. Success state renders inline; sidebar stays open so user can verify.

### Range.protect prompt

User-initiated only — Google renders the modal on edit attempt. We own only the description string. Confirms via the standard `OK` button. No app-side logic.

## Performance Contract

These are LOAD-BEARING constraints — the sidebar's visual treatment must not violate them.

| Metric | Budget | How visual treatment honors it |
|--------|--------|--------------------------------|
| Cold-load first paint | ≤500ms after `Search` click | No external font load (system + Google Fonts already loaded for view tabs); no images; no SVGs; no animations |
| End-to-end query | ≤2s (SEARCH-01) | Progressive rendering of groups; no all-or-nothing render barrier |
| CSS size in sidebar HTML | ≤8 KB inline | Single `<style>` block; no external stylesheets; no reset CSS; rely on browser defaults where possible |
| JS size in sidebar HTML | ≤12 KB inline | Vanilla JS only (no jQuery, no React, no build step); the `escapeHtml` + `render` + `save` pattern from `showCharInfoSidebar.ts` is the ceiling |
| DOM node count at peak | ≤500 nodes | Auto-collapse groups at >5 chars (D-07) keeps a single-letter "a" typo from blowing up the DOM |

**Animation policy:** NONE. No CSS transitions, no spinners, no loading bars. The state machine swaps content instantly. Reasoning: animations cost first-paint time we can't spare in the <2s budget.

**Image policy:** NONE in the search sidebar. The eviction sidebar may use one inline SVG checkmark for the success state (≤200 bytes inline). The Pages site uses PNG screenshots and one GIF — that's a different surface with no perf budget.

## Accessibility Contract

| Concern | Treatment |
|---------|-----------|
| Color contrast | Each theme's `--fg` on `--bg-row` MUST be ≥4.5:1 (WCAG AA body text). Checker verifies via the existing palette in `themes.ts` — if a theme fails, contrast is fixed in `themes.ts`, not patched in the sidebar. `minimalist` (`#222` on `#fafafa`) and `velious` (`#0e2230` on `#e8eef5`) clearly pass; the deep-bg themes (`vanilla`, `kunark`, `heavy`) use light row backgrounds (`#fdf6e3`, `#f1ede0`, `#f4ead0`) for the same reason — already passing. |
| Focus visibility | Browser-default 2px outline preserved. NEVER `outline: none` without a replacement. Accent-colored 1px border on the focused input is ADDITIVE, not a replacement for the outline. |
| Semantic HTML | `<input>` for text, `<select>` for dropdowns, `<button>` for actions (NEVER `<div onclick>`), `<ul>`/`<li>` for the result-group structure, `<h3>` for sidebar title, `<h4>` for group headers |
| ARIA | `aria-expanded` on group headers; `aria-live="polite"` on the message div for state changes (loading/error/results count); `aria-label="Search items"` on the search input (since the visible label is the placeholder, which doesn't survive blur) |
| Keyboard-only operation | Every action reachable via Tab + Enter/Space. Tested per the state-machine table above. |
| Screen-reader copy | Result row line 1 reads naturally ("Findom: General-1, count 4"); line 2 wiki link has `aria-label="Open <ItemName> on the P1999 wiki"` to disambiguate when multiple "Wiki" links exist in the result list |

No autoplay, no autofocus traps, no modal stacking beyond the single native `confirm()` for eviction.

## Onboarding Site Visual Contract (GitHub Pages)

The Pages site is a separate visual surface from the sidebars. It uses a stock Jekyll theme; we own only the content structure.

| Property | Value |
|----------|-------|
| Platform | GitHub Pages with Jekyll (D-09) |
| Source | `/docs/` in the repo, picked up automatically when Pages is enabled |

| Typography | Theme defaults (Helvetica/Arial system stack for Cayman). No web-font loads — page must render fast on a guildie's first visit. |
| Spacing | Theme defaults. We add only paragraph-level structure (headings, paragraphs, lists, fenced code blocks). |
| Image format | PNG for static screenshots (lossless on UI chrome); single annotated GIF for SmartScreen walkthrough (≤5 MB per D-10). NO autoplay video, NO YouTube embed (D-10). |
| Image dimensions | Screenshots at 1× resolution, max 1200px wide, hosted in `/docs/assets/`. GIF at native screen-recording resolution, scaled with `max-width: 100%` in CSS. |
| Image alt text | EVERY image has descriptive alt text. SmartScreen GIF alt: `Animated walkthrough of the Windows SmartScreen prompt — click "More info", then "Run anyway".` |
| Navigation | Top nav links: `Install`, `Troubleshooting`, `Developer notes`, `GitHub`. Footer: license + attribution line. |
| Mobile | Cayman theme is responsive out of the box; verify the GIF doesn't overflow on a 360px-wide viewport. |
| External links | Open in the same tab (no `target="_blank"`) — guildies will be in their default browser already; popping new tabs is user-hostile. |

Content boundaries:

- `install.md` — chronological. Each step is an `<h2>` with a screenshot/GIF below if visual confirmation matters. No marketing language. Numbered steps.
- `troubleshooting.md` — symptom-keyed. Each `<h2>` is the symptom ("Tray icon is red", "Workbook isn't updating", "First install showed a SmartScreen warning"); body is cause → fix. Cross-link to `install.md` where re-running install fixes the issue.
- `dev.md` — flat list of links into existing repo docs (`docs/oauth-setup.md`, `docs/apps-script-deploy.md`, `docs/build-and-install.md`). No content duplication.
- `index.md` — 1 paragraph + 2 links: `Install →`, `GitHub →`. Nothing else.
