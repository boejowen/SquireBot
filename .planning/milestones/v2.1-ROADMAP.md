## Milestone Goal

Let any guildie link their own watcher from `squirebot.quest` via the existing Phase-15 Discord login — no maintainer hand-minting + DMing codes — while keeping the watcher credential a static, reusable bearer token (the v2.0 model; **no watcher change** for the core feature). Composes existing infrastructure (P15 Discord-login + sessions, `auth.MintCode` hashed-token minting, the `web_user`/`owner`/`guild_code` tables).

**Goal MET:** self-service `/account` linking is live; the `mint-code` CLI is gone; the watcher credential model is unchanged; all three carried-forward watcher cleanups confirmed live-correct.

## Locked Decisions

- **Link code = the bearer token itself (v2.0 model, reusable).** Plaintext shown once at mint (hash-only at rest); watcher pastes and reuses forever. No expiry. **No watcher change.**
- **Re-link = additive.** Minting issues an *additional* valid token (multiple PCs per guildie); revocation is per-token.
- **Manual `mint-code` CLI removed** — self-service is the sole minting path (`revoke-code` retained as an ops backstop).
- **HARD CONSTRAINT:** Discord identity captured at link-time only; **never** Discord OAuth *in the watcher* (avoids the ~7-day-expiry / public-secret / loopback fragility v2.0 escaped).
