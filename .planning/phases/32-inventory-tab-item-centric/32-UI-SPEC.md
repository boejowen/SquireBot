# Phase 32 — UI Design Contract

> Visual and interaction contract for the SquireBot web app's **item-centric Inventory tab**
> (ITEM-01/02/03) — the guild-wide answer to *"which characters have item X?"*.
> Generated by gsd-ui-researcher; verified by gsd-ui-checker.
>
> **This is a NEW data surface inside an existing SvelteKit app whose visual language is ALREADY
> LOCKED** — five EQ themes, `[data-theme]` single source of truth, established tokens and
> component idioms (Phase 14/30/31 UI-SPEC lineage). This spec does NOT invent a palette; it
> reuses the **Phase-31 master-detail shape verbatim** (the `/characters` two-pane grid, the
> scoped viewer-first search, the `StateBlock` states, the `ExaminePanel` examine block, the
> small wiki-icon tile) and pins the precise structure of the item LIST (one row per normalized
> name + summed-qty/holder-count + inline price/wiki), the item DETAIL (the reused
> `ExaminePanel` PLUS a holders table whose rows deep-link into `/characters?c=<name>`), the
> ordering, responsive collapse, accessibility, and every empty/loading/error state. Every
> token, size, and copy string is either (a) lifted verbatim from the live codebase / 31-UI-SPEC,
> or (b) the smallest extension of an existing idiom, noted as such. **This is a structure/data
> revamp, NOT a re-skin** — the live 5 EQ themes are reused unchanged. Locked decisions
> **D-01..D-04** (32-CONTEXT) + the P31 carry-forwards + sketch 003 **Variant B** are encoded
> here, not re-litigated.

## Spacing Scale

The codebase uses a strict 4-based scale (verified in SiteShell, DataGrid, StateBlock,
`/characters/+page.svelte`, ExaminePanel). Reuse it exactly — do not introduce new spacing values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Inline gap inside a list row's headline (icon ↔ name ↔ count); holders-table cell vertical rhythm |
| sm | 8px | Item-list row inner gap; search ↔ hint gap; detail-header icon ↔ name gap; holders-table cell padding |
| md | 16px | Item-list row horizontal padding (`8px 16px` row); detail panel padding (16px — matches ExaminePanel); search input inner padding; section → section gap |
| lg | 24px | The two-pane column gap (list column ↔ detail column) — **identical to `/characters` `gap: 24px`**; detail header → holders-table gap |
| xl | 32px | Page horizontal gutters (desktop — inherited from `shell-main`) |
| 2xl | 48px | Empty/no-results vertical centering block (reuses `StateBlock` `padding: 48px 16px`); the "pick an item" detail prompt |

**Small item-icon tile (the list-row + detail-header icon):** the sketch uses a **30px** tile in
the list row and a **42px** tile in the detail header. Both are off the 4-scale at exactly those
sizes; **resolution: round the list-row tile to `32px` and the detail-header tile to `40px`**
(both 4-grid clean; the visual difference is negligible). The 1px icon inset / `border-radius: 3px`
MAY stay as within-tile details (not layout gaps), matching the live `PaperdollSlot` `.ico`
treatment. These small tiles reuse the SAME colored-gradient + `<img>`-onerror fallback as
`PaperdollSlot` (see §Color); they are NOT the 62px paperdoll tile (that one is touch-target-sized;
these inline list icons are decorative-adjacent — the row itself is the 44px touch target).

**Touch-target exception (existing rule, non-negotiable):** every interactive affordance — an
item-LIST row, the search input, the PigParse/wiki inline links, a HOLDER row in the detail table
— has an effective hit area `>= 44px`. An item-list ROW is `min-height: 44px` (same as the
`/characters` `.row`). A holder-table ROW (the deep-link to `/characters?c=`) is `min-height: 44px`.
Inline `↗` links inside a row sit within the 44px row height. Gutters collapse to **16px** below
640px (inherited `shell-main`/SiteShell `@media (max-width: 640px)` rule — keep it).

Exceptions: the 30→32px list-icon and 42→40px detail-icon roundings above; the within-tile 1px
icon inset (detail, not layout). No other exceptions.

## Typography

Roles are already declared across the live UI-SPEC lineage (14/30/31) and rendered in
SiteShell / DataGrid / StateBlock / ExaminePanel. Reuse verbatim — this phase adds NO new type
roles. (The sketch's tiny 10–13.5px micro-labels are SKETCH-ONLY and are re-specified to the
legible production roles below — the same correction the 31-UI-SPEC checker enforced.)

| Role | Size | Weight | Line Height | Where in this phase |
|------|------|--------|-------------|---------------------|
| Body | 16px | 400 (`--font-body`) | 1.5 | Item name in a list row, holders-table cells (character/slot/qty/last-synced), search input text, hints, the detail meta line, all prose |
| Label | 13px | `--weight-display` | 1.2 | The holders-table column headers (eyebrow), the row "you"/"bank"/"bot" tag, the summed-qty/holder-count headline's unit words ("guild-wide" / "holders"), the search hint |
| Heading | 20px | `--weight-display` | 1.2 | The detail panel item NAME (matches `ExaminePanel` `.ex-name` = 20px accent); the "pick an item" / "no holders" prompt headings |
| Display | 28px → reuse | `--weight-display` | 1.2 | Not introduced this phase — the only 28px in the app is the wordmark (SiteShell). No new Display use here. |

**Item-list row headline (D-04 — re-specified from sketch micro-sizes to legible roles):**
- Item **name** = Body 16px in `var(--text)` (the sketch used 15px display — render at 16px Body
  for legibility; MAY use `--font-display` for the name to echo the EQ item-name feel, matching
  the sketch's `font-family:var(--font-display)` on the item name — planner's discretion, stay on
  the 16px size either way).
- **Quantity + holder count** (D-04): rendered as `{summed-qty} · {holder-count} holders` — the
  NUMBERS in `var(--accent)` (the "your stuff scannable" emphasis), the unit words ("guild-wide",
  "holders") at **Label 13px** dimmed `var(--text)` `opacity: 0.7`. `font-variant-numeric:
  tabular-nums` on the numbers. (Sketch rendered the count at 13px — bump the words to the 13px
  Label role; the number rides the Body line.)
- **Inline PigParse price** (D-04) = Body-ish, `color: var(--status-other)`, `tabular-nums`, with
  a trailing `↗` when it links to PigParse; the price text itself is NOT a link unless a PigParse
  URL applies (D-09 — when no price resolves the price slot is OMITTED entirely, never "—"/"null").
- **Inline wiki link** (D-04) = `var(--accent)` + 1px accent underline + trailing `↗` (the live
  `.tooltip-wiki-link` idiom). Links to `https://wiki.project1999.com/<wikiSlug>`.

**Detail panel typography (D-03):**
- The **examine block** reuses `ExaminePanel.svelte` UNCHANGED — its typography is already locked
  (name 20px accent, flags 13px `--status-other`, stats 16px `--status-ok`, price 16px
  `--status-other` tabular-nums, wiki accent+underline, footer 13px dimmed). Do not re-specify it.
- The **holders-table** column headers = Label 13px `--weight-display`, uppercase,
  `letter-spacing: 0.05em`, `color: var(--accent)` (the sketch `.htable th` idiom).
- Holders-table **cells**: character name = Body 16px `var(--text)` (MAY use `--font-display` to
  echo the char-name feel — match the sketch; stay 16px); slot label = Body 16px dimmed
  (`opacity: 0.7`); quantity = Body 16px `var(--accent)` (`×{n}`, tabular-nums); last-synced =
  Body 16px dimmed (`opacity: 0.7`).

## Color

The five themes each redefine the same token set; values below are the **Velious default**
(`:root` / `[data-theme="velious"]`, verified in `web/src/app.css`). The CONTRACT is the token
NAME and its ROLE, which holds across all five themes.

| Role | Token | Velious value | Usage in this phase |
|------|-------|---------------|---------------------|
| Dominant (~60%) | `--bg` | `#060b18` | Page background, the list column's deep field, the small icon-tile fallback under-fill |
| Secondary (~30%) | `--panel` | `#0f1729` | Item-list rows + container, the detail panel, the holders-table surface, the search-input fill, the small icon tile |
| Accent (~10%) | `--accent` | `#a8c5e0` | **Reserved list below — never "all interactive elements"** |
| Status OK | `--status-ok` | `#6fc8b0` | The examine "highlighted stats" line ONLY (inside `ExaminePanel`, already locked) |
| Status other | `--status-other` | `#a8c5e0` | The inline PigParse price value (list row + examine) |
| Border | `--border` (→ `--accent` fallback) | — | Item-list row separators, list/detail panel border, holders-table row rules, search-input border at rest |
| Text | `--text` | `#d4dee8` | All at-rest copy, item names, holders-table cells |
| Destructive | `--destructive` (= `--status-missing`) | `#e88a8a` | **Not used this phase** — the Inventory tab is a read-only browse/select surface; there are NO destructive actions. Declared for completeness only. |

**Accent reserved for (explicit, closed list):**
1. The **selected item-list row** indicator (a 2–3px accent **left-border** + accent item-name —
   the master-detail "this is what's pinned in the detail" signal, identical to the `/characters`
   `.row.selected` treatment).
2. The summed-quantity + holder-count **numbers** in the list-row headline (D-04 — the "your stuff
   scannable" emphasis).
3. The **inline wiki link** (accent text + 1px accent underline) on each list row + in the detail.
4. The examine panel item **NAME** + the holders-table **quantity** values + the holders-table
   **column headers** (eyebrow).
5. The **"you" tag** (the viewer-owned marker on a list row + on a holder row) — a small accent
   uppercase Label, identical to the `/characters` `.tag` treatment.
6. The **focus-visible outline** on every focusable affordance (`outline: 2px solid var(--accent)`).
7. The search-input **focus** border (`border-color: var(--accent)` on `:focus-within`).
8. The **search-result match emphasis** / the row hover wash
   (`color-mix(in srgb, var(--accent) 8%, transparent)` — the live row-hover idiom).

Accent is NOT used for: at-rest row borders/separators (those are `--border`), body copy, the
slot labels in the holders table, the small icon-tile fallback, the PigParse price (that is
`--status-other`), or any decorative fill. The 60/30/10 budget holds: a column of `--panel` rows
on a `--bg` page, with accent appearing only on the active selection, the qty/holder numbers, the
wiki link, the "you" tag, hover/focus, and the detail header/holders-headers.

**Sketch-token → registry-token mapping (LOCKED — the sketch's helper vars must NOT ship):**

| Sketch var | Production token | Notes |
|------------|------------------|-------|
| `--slot` (search-input + icon-tile fill) | `var(--panel)` | inputs + icon tiles are panel surfaces |
| `--panel-2` (row hover) | `color-mix(in srgb, var(--accent) 8%, transparent)` | the live `/characters` `.row:hover` idiom — NOT a new token |
| `--bg-2` | `var(--bg)` (or `var(--panel)` for a banded header) | the sketch's secondary surface |
| `--accent-2` (detail/card border) | `var(--border, var(--accent))` at rest, `var(--accent)` for selected/hover emphasis | matches ExaminePanel's border treatment |
| `--text-dim` | `var(--text)` with `opacity: 0.7` | no separate dim token exists (mirrors `/characters` `.row-meta`) |
| `--status-other` | `var(--status-other)` | real token exists (PigParse price) |
| `--radius` | a fixed `4px` (rows/inputs) / `6px` (detail panel) | matches `/characters` + ExaminePanel literals; do not introduce a `--radius` global |
| the small icon-tile `linear-gradient(...)` fallback | KEEP — the `PaperdollSlot` deterministic per-item hue (see fallback note) | the icon-load-error fallback, intentionally non-token |

**Colored-tile fallback (D-02 / P31 carry-forward — locked):** the small item-icon tile (list row
+ detail header) REUSES the exact `PaperdollSlot` mechanic — `<img
src="https://wiki.project1999.com/images/Item_<iconId>.png" image-rendering: pixelated;
object-fit: contain;>` over a deterministic colored gradient (`linear-gradient(135deg, hsl(hue 45%
30%), hsl(hue+40 40% 18%))`, hue derived from the item name/id). When `icon_id === 0` the `<img>`
is skipped; an `onerror` hides the `<img>` so the colored tile shows through. This is the ONE
sanctioned non-token color and exists so icon coverage can ship incrementally — the list is NEVER
blocked on 100% icon coverage. **Recommendation: extract the tile into a small shared component
(or a thin variant of `PaperdollSlot`'s `.ico` markup) so the list/detail icons and the paperdoll
never drift** (planner's discretion; the contract is "same fallback behavior, same hue function").

**Heavy-theme caveat (carry forward from 31-UI-SPEC):** the item list + detail panel are
CHROME-on-frame (like the inventory window), NOT data-grid rows — they stay on `--panel`/`--bg`,
NOT Heavy's inverting parchment (`--row-bg`/`--row-text`). If the planner builds the list on
`DataGrid` instead (allowed — see §C), it WILL take Heavy's parchment rows (correct for a data
grid); the bespoke list stays on `--panel`. Verify the accent (`#f0d088`) selected-border + focus
ring + the qty/holder numbers + wiki link read against Heavy's near-black `--panel` (`#1a0e05`) —
they do. Verify minimalist's low-chroma accent (`#b8915c`) focus ring + selected border are
visible — they are; spot-check at build.

## Layout & Interaction Contract

> This is the load-bearing section. The tables above are tokens; this is the structure the
> executor builds. The canonical visual reference is **sketch 003 Variant B (master-detail)**
> (`.planning/sketches/003-inventory-and-banks-lists/index.html`) and the **already-shipped
> `/characters` master-detail** (`web/src/routes/characters/+page.svelte`) — this tab MIRRORS
> that approved two-pane shape so Characters + Inventory feel identical.

### A. Route & page frame

- The Inventory tab is the route `/inventory` (replaces the Phase-30 "coming soon" placeholder in
  `web/src/routes/inventory/+page.svelte`). It mounts inside the Phase-30 `SiteShell` (5-tab strip
  already present; `/inventory` tab gets `aria-current="page"` automatically via `startsWith`
  matching).
- **Master-detail on ONE route (no per-item route explosion).** The CLAUDE.md consolidated-views
  lock is RELAXED for exactly this pattern: ONE reusable detail panel rendered for the SELECTED
  item. Selection MAY be reflected in the URL (`/inventory?i=<normalizedName>` or similar) so an
  item is deep-linkable/shareable — **planner's discretion** (mirror the `/characters` `?c=` seam
  via `history.replaceState`); the contract is that selection renders the single reusable detail,
  not N materialized routes.
- **Two-pane shape (desktop):** an **item list** (left) + the selected item's **detail panel**
  (right). When no item is selected, the detail column shows a friendly "Pick an item" prompt
  (§F). On mobile the list and detail stack (§E). This is the IDENTICAL grid to `/characters`:
  `grid-template-columns: minmax(280px, 360px) 1fr; gap: 24px; align-items: start;` (the list
  column MAY be a touch wider — `minmax(300px, 380px)` — since item names run longer than char
  names; planner's discretion, keep it within the same idiom).

### B. The item list (ITEM-01 / D-01 / D-02 / D-04)

**One row per NORMALIZED ITEM NAME (D-01).** The list aggregates ALL holdings — equipped + general
+ bag contents + bank — across every character, bank toon, and guild bot. Identity + group key is
the **normalized name** (NOT `item_id` — the EQ-inventory vs PigParse-catalog id-namespace caveat;
matches the Phase-29 DATA-01 name join). Nothing is hidden (no exclude-equipped, no junk filter).
Coin/platinum rows are NOT items and are excluded (32-CONTEXT discretion — confirmed).

**Ordering (D-02, spec-fixed):** at rest (no search) the **viewer's items first** (items held on
any of the viewer's `character_assignment` characters), then **A-Z** by name. The search (§D)
preserves this viewer-first priority among the matched set. (This mirrors the `/characters` D-10
ordering — "your stuff is always on top.") A pure node-tested helper `items.ts` owns the
sort/filter (the `roster.ts` precedent — `viewerFirstItems(rows)` + `filterItems(rows, query)`),
NOT inlined in the `.svelte`.

**Data per row:** the small item icon (32px tile, §Spacing + §Color fallback), the item NAME, the
**summed stack count + holder count** headline (D-04: e.g. `142 · 3 holders` — the sum of stack
`Count` across all holdings AND the count of distinct holding characters), the **inline PigParse
price** (D-04 — `pickPrice` buy/sell selection; OMITTED when no price resolves, D-09), and the
**inline wiki link** (D-04).

**Build decision — RECOMMENDATION: a bespoke list, NOT `DataGrid`** (the same call the 31-UI-SPEC
made for the character list, same rationale):
- `DataGrid` is the guild-wide consolidated grid idiom (sticky Char column, faceted filters, zebra,
  Heavy parchment) — overkill for an ordered, *selectable* item list, and it carries no native
  "selected row → render detail" affordance.
- A bespoke list of selectable rows reads as the master pane of a master-detail and matches the
  approved `/characters` list 1:1, so the two tabs feel identical.
- If the planner prefers `DataGrid` for consistency with the legacy guild-views grids, that is
  ALLOWED — but it must (a) seed the D-02 viewer-first-then-A-Z order, (b) make each row
  selection-capable (row click pins the detail), and (c) keep the headline columns
  (qty/holder/price/wiki) legible. Bespoke is the recommended default.

**Row treatment (bespoke — mirror `/characters` `.row`):**
- A selectable `<button type="button">` per item, `min-height: 44px`, `--panel` background,
  `padding: 8px 16px` (sm × md), a 1px `--border` bottom separator, a `3px transparent` left border
  that turns `--accent` when selected.
- Layout (the sketch B `md-item` grid, tokens swapped): `[32px icon] [name + headline (1fr)] [price
  · wiki (auto)]`. The name on the lead; the `{qty} · {N} holders` headline (D-04) below or beside
  the name; the inline price + wiki on the trailing edge. On a narrow list column the price/wiki
  MAY wrap under the name (planner's discretion; keep the qty/holder headline always visible).
- A small accent **"you" tag** (Label) on rows where the viewer holds at least one copy (the D-02
  viewer-owned marker — matches `/characters` `.tag` "yours"; copy is "you" per sketch 003).
- **Selected state:** the accent left-border + accent item-name + `aria-pressed="true"`. Exactly
  one row selected when an item is shown.
- Hover: `background: color-mix(in srgb, var(--accent) 8%, transparent)` (the live row-hover idiom).
  Focus-visible: `outline: 2px solid var(--accent); outline-offset: -2px`.
- **No band group-labels here** (unlike the character list's YOUR/GUILD/BANKS bands) — the item
  list is a single viewer-first-then-A-Z run (D-02). A subtle one-line divider/label after the
  viewer's items is OPTIONAL (planner's discretion); the default is a single ordered run.

**Missing data (D-09 — carried):** a row with no resolved PigParse price OMITS the price slot
entirely (no "—"/"null"/blank-broken cell). A row whose item has no `icon_id` yet shows the colored
fallback tile (never a broken-image glyph). A row ALWAYS renders at least the name + the qty/holder
headline.

### C. The item-rollup data shape (Claude's-discretion item, resolved for the contract)

The list + detail are driven by a NEW session-gated read route (32-CONTEXT discretion — e.g. `GET
/api/v1/items`; name TBD in planning, do NOT reuse the P19 `/items/search` catalog route) returning,
per normalized item name: `{ name, summed_qty, holder_count, is_mine, price, wiki_url, icon_id,
statsblock, wiki_summary, is_quest_item, prices[], holders[] }` where each `holders[]` entry is
`{ char, slot_label, qty, last_synced, is_mine, is_bank }`. A pure `items.ts` adds `fetchItems()`
(the `fetchCharacters` twin) + the viewer-first sort/filter.

**Examine reuse seam (load-bearing for D-03):** `ExaminePanel.svelte` takes an `InventorySlot |
null` + `charLastSeen`. The item-rollup MUST therefore expose a representative **`InventorySlot`-
shaped** object per item (name → `item`, plus `icon_id`, `statsblock`, `wiki_summary`,
`is_quest_item`, `price`, `prices`, `wiki_url`; `count/slots/children/canonical_slot/location` are
list-context-irrelevant and may be zero/empty). The detail then renders `<ExaminePanel
slot={selectedItemAsSlot} charLastSeen="" />` UNCHANGED. **`charLastSeen` is passed as `""`** for
the item-centric examine — "last synced" is a PER-HOLDER fact (it lives in the holders table, per
ITEM-03), not a single per-item value, so the examine's footer "Last synced" line is correctly
OMITTED here (D-09 omits an empty `charLastSeen`). This is the cleanest reuse with zero
`ExaminePanel` change.

### D. Per-tab scoped search (ITEM-02 / NAV-02 / D-02)

The search bar lives at the **top of the list column** (the sketch B layout puts it above the
`md-list`), reusing the `/characters` search visual VERBATIM:

- **Visual (from `/characters/+page.svelte` `.search`):** a flex row, `background: var(--panel)`,
  `border: 1px solid var(--border, var(--accent))`, `border-radius: 4px`, `min-height: 44px`,
  `padding: 8px 12px`, a leading `Search` lucide glyph (16px, `aria-hidden`), Body 16px text,
  placeholder in dimmed `--text`. Focus: `:focus-within` → `border-color: var(--accent)`;
  `:focus-visible` → `outline: 2px solid var(--accent)`.
- **Behavior:** filters the item list by name. **Viewer-priority (D-02):** items the viewer holds
  rank/appear FIRST among matches, then A-Z — i.e. the search preserves the D-02 ordering within
  the filtered set (the `filterItems` helper mirrors `filterRoster`). Client-side filter (the
  rollup is guild-scale — bounded).
- **Search hint (one line, dimmed Body 13px below the bar):** "Items on your characters match
  first." (the sketch's "Items on your characters are listed first.").
- **No-results:** reuse `StateBlock kind="no-results"` → `No matches for "{query}"` (query
  auto-escaped via `{}` — never `{@html}`). Do not blank the list.

### E. Responsive / mobile (mirror `/characters` §H)

- **Desktop (≥ ~900px):** two-pane — item list (left, `minmax(280–380px)`) + the detail panel
  (right, `1fr`), `gap: 24px`, the detail panel `position: sticky; top: ~60px` (the ExaminePanel
  already sets `position: sticky`).
- **Tablet/narrow (~640–900px):** the panes MAY stay side-by-side if width allows, else the detail
  drops below the list (`grid-template-columns: 1fr`).
- **Mobile (< 640px):** the list and detail **stack** (list first; selecting an item reveals/scrolls
  to the detail — or the list collapses to a compact selected-item header with a "change item"
  affordance — planner's discretion, simplest path wins, matching `/characters`). The holders table
  reflows: on a very narrow viewport the four columns may wrap to a stacked `character — slot ×qty ·
  last-synced` line per holder (the sketch A `.holder` already demonstrates this compact form);
  keep all four facts. Gutters collapse to 16px (inherited).
- The two-pane grid collapses to one column at the SAME `@media (max-width: 640px)` breakpoint
  `/characters` uses (`grid-template-columns: 1fr`).

### F. The item detail panel (ITEM-03 / D-03 / D-03a)

For the selected item, the right column renders, top-to-bottom:

1. **Detail header:** the 40px item icon (§Color fallback) + the item NAME (Heading 20px accent —
   matches `ExaminePanel` `.ex-name`) + a meta line `{summed-qty} guild-wide across {holder-count}

### G. Accessibility Contract (load-bearing — mirror `/characters` §I)

1. **Item-list rows are buttons.** Each row is a `<button type="button">` with an accessible name =
   the item name + the qty/holder summary (e.g. `aria-label="Cloak of Flames, 142 guild-wide, 3
   holders"`). `aria-pressed` reflects selection; exactly one pressed when an item is shown.
2. **Holder rows are links/buttons** with an accessible name naming the destination (e.g. "Open
   Bashley's inventory" / `aria-label="View Bashley"`); they navigate to `/characters?c=<name>`.
3. **Keyboard:** every list row + holder row + the search input + the inline wiki/PigParse links
   are Tab-reachable; Enter/Space activates (pin the detail / follow the deep-link). The detail's
   examine links are normal focusable links.
4. **Focus-visible:** every focusable affordance shows `outline: 2px solid var(--accent)` on
   `:focus-visible` (`outline-offset: 2px`, or `-2px` where it would clip a row edge). The
   already-shipped universal treatment.
5. **44px touch targets:** list rows `min-height: 44px`; holder rows `min-height: 44px`; the search
   input `min-height: 44px`; inline `↗` links sit inside the row height.
6. **Color is never the sole signal:** the qty/holder summary is NUMBERS + words (not color); the
   "you"/"bank"/"bot" markers are TEXT tags (not color); the selected row carries `aria-pressed`
   (not only the accent border); the price is labelled "PigParse" in the examine.
7. **Selected item announced:** the selected list row has `aria-pressed="true"`; the detail header's
   item-name heading (`<h2>`/`<h3>`) gives screen-reader context for what's shown.
8. **Reduced motion:** any row-hover/transition + the detail-swap honor the global `@media
   (prefers-reduced-motion: reduce)` rule in app.css (instant).
9. **Theme-independence:** all of the above must hold under all 5 themes — verify the accent focus
   ring + selected border + qty/holder numbers read on Heavy (`#f0d088` on `#1a0e05`) and
   Minimalist (`#b8915c`); both pass; spot-check at build.
10. **Icon `alt`:** the small item-icon `<img>` carries `alt=""` (decorative — the row button's
    `aria-label` names the item, the icon is redundant). On colored-tile fallback the row is still
    named by the button label.
11. **The single `{@html}` sink rule (carried, T-31-14):** the ONLY raw-HTML in the detail is
    `ExaminePanel`'s `composeItemNote` wiki body (already escaped + scheme-allow-listed). Item names
    and character names (both guildie-controllable) render via plain `{}` interpolation (Svelte
    auto-escapes) in the list rows, the detail header, and the holders table — **NEVER** the
    raw-HTML directive. This phase adds NO new `{@html}` sink.

### H. Loading / error states (the NEW data fetch this phase introduces)

This phase adds ONE read-API call — the item rollup (`fetchItems()`). Reuse `StateBlock` verbatim;
do NOT invent new copy. Mirror the `/characters` state machine (`onMount` one-shot load; a 401/403
routes to the `AuthGate` guard; any other failure → the generic error StateBlock + Retry):

- **List loading** → `StateBlock kind="loading"` ("Loading…").
- **List empty (nothing held by anyone yet)** → `StateBlock kind="empty"` (reuses "No characters
  yet" copy — see §Copywriting for the slight re-word recommendation).
- **List fetch error** → `StateBlock kind="error"` ("Couldn't load the data" + Retry).
- **Search no-results** → `StateBlock kind="no-results"` (`No matches for "{query}"`).
- **No item selected** → see §F (a "Pick an item" prompt, NOT an error).
- **401/403** → handed to the `AuthGate` guard (server-truth re-route) — never a stale view.
