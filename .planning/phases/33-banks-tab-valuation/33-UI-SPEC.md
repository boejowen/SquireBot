# Phase 33 — UI Design Contract

> Visual and interaction contract for the SquireBot web app's **Banks tab + Valuation**
> (BANK-01/02/03) — the guild-wide answer to *"what's in the guild banks, and what's it worth?"*.
> Generated by gsd-ui-researcher.
>
> **This is a NEW data surface inside an existing, already-LOCKED visual language** — five EQ
> themes, `[data-theme]` single source of truth, established tokens and component idioms
> (Phase 14/30/31/32 UI-SPEC lineage). This spec **invents no palette and no new pattern**. The
> Banks tab is, structurally, **the Phase-32 Inventory tab reskinned to banks + a valuation
> header**: it reuses the P32 `/inventory` master-detail shape **verbatim** (the two-pane grid,
> the scoped search visual, `StateBlock` states, the bespoke selectable-row list) and the P31
> `InventoryWindow` **verbatim** (the per-bank detail). The only genuinely new pieces are (a) a
> guild-wide **valuation summary header** spanning the tab (D-02), (b) the bank list scoped to
> `IsBankToon || IsGuildBot`, A-Z (D-01), (c) a per-bank **value/platinum header** above the
> reused window (D-04), and (d) the **item-search → holders → bank-window** deep-link scoped to
> bank holders (D-03). Locked decisions **D-01..D-04** (33-CONTEXT) + the carried-forward P31/P32
> idioms are encoded here, not re-litigated. **This is a structure/data revamp, NOT a re-skin** —
> the live 5 EQ themes render unchanged.

## Spacing Scale

The codebase uses a strict 4-based scale (verified in `SiteShell`, `StateBlock`, `/inventory`,
`/characters`, `InventoryWindow`). Reuse it **exactly** — introduce no new spacing values. Values
below are **lifted verbatim from `/inventory/+page.svelte`** (the direct analog) so the two tabs are
pixel-identical.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Inline gap inside the summary-header value group; bank-list row `gap: 2px` body lines; holders-table cell vertical rhythm |
| sm | 8px | Bank-list row inner gap; search ↔ hint gap; per-bank detail-header gap; summary-header inner pill gap |
| md | 16px | Bank-list row horizontal padding (`8px 16px`); search input inner padding; summary-header vertical padding; section → section gap; mobile gutters |
| lg | 24px | The two-pane column gap (list column ↔ detail column) — **identical to `/inventory` + `/characters` `gap: 24px`**; summary-header bottom margin into the two-pane grid |
| xl | 32px | Page horizontal gutters (desktop — inherited from `shell-main`) |
| 2xl | 48px | Empty/no-results vertical centering block (reuses `StateBlock` `padding: 48px 16px`); the "pick a bank" detail prompt |

**Touch-target exception (existing rule, non-negotiable):** every interactive affordance — a
bank-LIST row, the search input, an item-search **result holder row**, the inline wiki/PigParse
links, and (inside the reused window) every paperdoll/grid tile — has an effective hit area
`>= 44px`. A bank-list ROW is `min-height: 44px` (same as `/inventory` `.row`). An item-search
holder ROW (the deep-link that pins a bank's window) is `min-height: 44px`. Gutters collapse to
**16px** below 640px (inherited `shell-main`/SiteShell `@media (max-width: 640px)` rule — keep it).

**No icon tiles in the bank list.** Unlike the P32 item list (which carries a 32px item-icon tile),
the bank-list rows show a **character name + item count only** (D-01 — "clean rows"). No 32px tile,
no per-row value. The only item icons in this tab live **inside the reused `InventoryWindow`** (62px
paperdoll/grid tiles, untouched) and **inside the item-search results** if the planner chooses to
mirror the P32 list-row icon there (optional — see §F.2; default is text-only result rows for a
tighter results panel).

Exceptions: none beyond the inherited mobile gutter collapse.

## Typography

Roles are already declared across the live UI-SPEC lineage (14/30/31/32) and rendered in
`SiteShell` / `StateBlock` / `ExaminePanel` / `/inventory`. **Reuse verbatim — this phase adds NO
new type roles.** The reused `InventoryWindow` carries its own already-locked typography (char-head
24px display, eyebrows 13px, etc.) — do not re-specify it.

| Role | Size | Weight | Line Height | Where in this phase |
|------|------|--------|-------------|---------------------|
| Body | 16px | 400 (`--font-body`) | 1.5 | Bank name in a list row, item-count text, search input text, hints, the per-bank detail-header meta, item-search result rows, all prose |
| Label | 13px | `--weight-display` | 1.2 | Bank-list row count unit ("items"), the `bank`/`bot` row tag, the search hint, the item-search result eyebrow/columns, the summary-header eyebrow word |
| Heading | 20px | `--weight-display` | 1.2 | The per-bank detail-header bank NAME (matches `/inventory` `.detail-name` = 20px accent); the "pick a bank" prompt heading |
| Display | 24px / 28px → reuse | `--weight-display` | 1.2 | **Reused only.** The `InventoryWindow` char-head renders the bank name at 24px (its own locked role); the 28px wordmark stays in `SiteShell`. The **valuation summary header** uses the 20px Heading role for its number line (see below) — NOT a new Display size. |

**Valuation summary header typography (D-02 — re-specified to legible production roles):**
- The header is **one banded line** spanning the tab (§B): a small eyebrow + a number line.
- **Eyebrow** = Label 13px `--weight-display`, uppercase, `letter-spacing: 0.05em`, `color:
  var(--accent)` — text "GUILD BANKS" (the live eyebrow idiom from the window's `.eyebrow`).
- **Number line** = the two totals at **Heading 20px** (`--font-display`, `line-height: 1.2`): the
  **value number + "pp"** and the **platinum number + "plat"**, the NUMBERS in `var(--accent)`,
  `font-variant-numeric: tabular-nums`; the unit words ("pp", "plat") and the joining "·" in
  `var(--text)` at `opacity: 0.7`. (Numbers ride accent for the "scannable headline" emphasis,
  matching the P32 row-headline number treatment.)

**Bank-list row typography (D-01):**
- Bank **name** = Body 16px in `var(--text)` (MAY use `--font-display` to echo the EQ char-name
  feel, matching `/inventory` `.row-name` and `/characters` — stay on 16px either way).
- **Item count** = `{n} items` — the NUMBER in `var(--accent)` `tabular-nums` (Body 16px), the unit
  word "items" at Label 13px dimmed `var(--text)` `opacity: 0.7` (the P32 `.num` + `.unit` idiom,
  reused). Singular `1 item`. **No price, no platinum on a list row** (D-02 — those live in the
  summary header and the per-bank detail header only).

**Per-bank detail-header typography (D-04):**
- The bank **NAME** = Heading 20px accent (`/inventory` `.detail-name` verbatim).
- The **meta line** = `{bank's item value} pp · {bank's platinum} plat` at Body 16px, the NUMBERS
  in `var(--accent)` `tabular-nums`, unit words + "·" dimmed `var(--text)` `opacity: 0.85` (the
  `/inventory` `.detail-meta` idiom). Missing/zero value or platinum is handled per §G (render a
  clean `0 pp` / `0 plat`, never "null"/"—" — the totals are real integers/sums, not nullable
  lookups).

**Item-search results typography (D-03):** mirrors the P32 holders-table cell roles —
result-row character name = Body 16px (`--font-display` ok), slot label = Body 16px dimmed
(`opacity: 0.7`), qty = Body 16px `var(--accent)` (`×{n}`, tabular-nums); the per-item group
heading = Heading 20px accent (the item name) or Label eyebrow per §F.2.

## Layout & Interaction Contract

> This is the load-bearing section. The tables above are tokens; this is the structure the executor
> builds. The canonical visual reference is the **already-shipped `/inventory` master-detail**
> (`web/src/routes/inventory/+page.svelte`) and the **already-shipped `InventoryWindow`** — this tab
> MIRRORS the approved P32 two-pane shape (plus a valuation header) so Banks + Inventory +
> Characters feel identical. Sketch `003-inventory-and-banks-lists/` covers BOTH lists; the banks
> case = banks-only list + the valuation summary.

### A. Route & page frame

- The Banks tab is the route `/banks` (replaces the Phase-30 "coming soon" placeholder in
  `web/src/routes/banks/+page.svelte`). It mounts inside the Phase-30 `SiteShell` (5-tab strip
  already present; `/banks` tab gets `aria-current="page"` automatically via `startsWith` matching).
- **Master-detail on ONE route (no per-bank route explosion).** The CLAUDE.md consolidated-views
  lock is RELAXED for exactly this pattern (ratified 2026-06-17): ONE reusable detail (the per-bank
  header + the reused `InventoryWindow`) rendered for the SELECTED bank. Selection MAY be reflected
  in the URL (`/banks?b=<bankName>`) so a bank is deep-linkable/shareable — **planner's discretion**;
  mirror the `/inventory` `?i=` / `/characters` `?c=` seam via `history.replaceState`. The contract
  is that selection renders the single reusable detail, not N materialized routes.
- **Page vertical order (top → bottom):**
  1. The **valuation summary header** (§B) — spans the full content width, ABOVE the two-pane grid.
  2. The **two-pane grid** (§C/§E): the bank list (left) + the selected bank's detail (right).
- **Two-pane shape (desktop):** `grid-template-columns: minmax(280px, 360px) 1fr; gap: 24px;
  align-items: start;` — **identical to `/characters`** (bank names are short like char names, so
  the 280–360px list column matches `/characters`, NOT the wider `/inventory` 300–380px). When no
  bank is selected, the detail column shows a "Pick a bank" prompt (§I). On mobile the panes stack
  (§E).

### B. The valuation summary header (BANK-02 / D-02)

**ONE guild-wide summary header at the top of the tab**, spanning the content width above the
two-pane grid. It surfaces the Phase-29 compute — it does NOT recompute (33-CONTEXT carry-forward).

- **Data source:** `compute.BankValuationFor(ctx, store)` → `BankValuation{ GuildTotal Valuation,
  PerBank map[string]Valuation, TotalPlatinum int64 }` where `Valuation{ TotalValue float64,
  UnpricedCount int }`. The summary shows `GuildTotal.TotalValue` (rounded) + `TotalPlatinum`. (The
  per-bank slice powers §F.4.)
- **Copy (33-CONTEXT specifics, lightly normalized):** eyebrow "GUILD BANKS"; number line
  `{value} pp · {platinum} plat`. With the `UnpricedCount` annotation OPTIONAL: if the planner
  wants to honor the P29 "+N unpriced" posture, append a dimmed Label `· {N} unpriced` after the
  value (planner's discretion; the default is value + platinum only — the unpriced count is
  surfaced item-by-item in the window's examine).
- **Visual:** a `--panel` band, `border: 1px solid var(--border, var(--accent))`, `border-radius:
  6px`, padding `16px` (md), `margin-bottom: 24px` (lg) into the grid. Eyebrow (Label accent
  uppercase) on the first line; the number line (§Typography "summary header") below it. On a narrow
  viewport the two totals MAY wrap to two lines; keep both fully visible.
- **States:** the summary header renders whenever the page is `ready` (banks exist). With zero bank
  toons the whole tab is the §H empty state (no summary). With bank toons but zero priced items the
  value reads a clean `0 pp` (real sum, never "null"); with no recorded coin the platinum reads
  `0 plat` (the `TotalPlatinum` sum skips nil-Plat toons → a clean integer, never fabricated).

### C. The bank list (BANK-01 / D-01)

**One row per bank/bot character (D-01).** The list is `IsBankToon || IsGuildBot` characters only,
**plain A-Z** (NO viewer-first banding — banks aren't anyone's assigned characters; this is the
roadmap's "same ordering style as Characters" reduced to its banks-only case). Row = **bank name +
item count** (clean; NO per-row value/platinum — D-02).

- **Data source (Claude's-discretion, resolved for the contract):** the bank roster comes from
  `RosterFor` band-2 filtered to `IsBankToon || IsGuildBot` (the same store seam P31 uses); the
  per-bank **item count** is the count of inventory rows held by that bank toon (the flat
  bank-scoped `InventoryJoin`, or the `PerBank` row count). A pure node-tested helper `banks.ts`
  owns the A-Z sort + the count derivation + the item-search filter/grouping (the `roster.ts` /
  `items.ts` precedent), NOT inlined in the `.svelte`.
- **Build decision — RECOMMENDATION: a bespoke list, NOT `DataGrid`** (the same call P31/P32 made):
  a bespoke list of selectable rows reads as the master pane of a master-detail and matches the
  approved `/inventory` + `/characters` lists 1:1 so all three tabs feel identical. `DataGrid` is the
  consolidated guild-views idiom (faceted filters, Heavy parchment) — overkill for an ordered
  selectable list with no native "selected row → render detail" affordance. If the planner prefers
  `DataGrid` for consistency with legacy grids it is ALLOWED but must (a) seed the A-Z order, (b)
  make each row selection-capable (row click pins the detail), (c) keep name + item-count legible.
  Bespoke is the recommended default.

**Row treatment (bespoke — mirror `/inventory` `.row`):**
- A selectable `<button type="button">` per bank, `min-height: 44px`, `--panel` background,
  `padding: 8px 16px` (sm × md), a 1px `--border` bottom separator, a `3px transparent` left border
  that turns `--accent` when selected.
- Layout (mirror `/characters` `.row` — column body, no icon tile): the bank **name** + an optional
  `bank`/`bot` Label tag on the lead line; the `{n} items` count below or beside the name (Body, the
  `.num` + `.unit` idiom). No price, no platinum.
- **`bank`/`bot` tags:** a small accent uppercase Label where the row is a bank toon (`bank`) and/or
  a guild bot (`bot`) — identical to the `/characters` `.tag` treatment (a char can be both; show
  both tags). These mark *why* the row is in this banks-only list.
- **Selected state:** the accent left-border + accent bank-name + `aria-pressed="true"`. Exactly
  one row selected when a bank is shown.
- Hover: `background: color-mix(in srgb, var(--accent) 8%, transparent)`. Focus-visible: `outline:
  2px solid var(--accent); outline-offset: -2px`.
- **No band group-labels** (unlike `/characters`' YOUR/GUILD/BANKS bands) — the bank list is a
  single A-Z run (D-01).

### D. Search toggle: list ⇄ item-search (BANK-03 / D-03)

The search bar lives at the **top of the list column** (the P32/`/characters` placement), reusing
the search visual **VERBATIM** (`/inventory` `.search`: flex row, `--panel`, `border: 1px solid
var(--border, var(--accent))`, `border-radius: 4px`, `min-height: 44px`, `padding: 8px 12px`, a
leading `Search` lucide glyph 16px `aria-hidden`, Body 16px text; `:focus-within` →
`border-color: var(--accent)`; `:focus-visible` → `outline: 2px solid var(--accent)`).

**The search is ITEM-centric (D-03), not a bank-name filter.** This is the load-bearing
divergence from the bank list: typing a query searches **items held by the guild banks**, and the
**left column toggles** between two modes:

- **Empty query → BANK LIST mode (§C):** the left column shows the A-Z bank list.
- **Non-empty query → ITEM-SEARCH mode (§F):** the left column REPLACES the bank list with the
  **item-search results** (matched bank items → which bank(s) hold each, qty/slot). The bank list is
  hidden while a query is active; clearing the query returns to the bank list. (This is the cleanest
  reuse of the P32 pattern: the search OWNS the left column when active, exactly as a filtered list
  would — the user is never looking at both a bank list and item results at once.)
- **Search hint (one line, dimmed Body 13px below the bar):** "Search items held by the guild
  banks." (Distinct from the P32 "Items on your characters match first." — banks have no viewer-first
  notion, D-01.)
- The **right detail column is unaffected by the toggle**: a pinned bank window stays pinned while
  the user searches; selecting a holder in an item-search result (§F.3) PINS that bank's window in
  the right column (replace-on-click). So the search drives the LEFT column's content and can
  re-target the RIGHT column's pinned bank — it does not blank the detail.

> **Planner note (the one explicit D-03 contract):** "toggle between the bank list and the
> item-results view" is resolved HERE as a **mode switch on the left column keyed off query
> emptiness** (not two coexisting panes, not a tab control). This is the simplest path that matches
> the P32 scoped-search behavior (where a query filters the left list in place). If a future need
> arises to see the bank list AND item results together, that's deferred polish.

### E. Responsive / mobile (mirror `/inventory` §E)

- **Desktop (≥ ~900px):** the summary header spans full width; below it the two-pane — bank list
  (left, `minmax(280–360px)`) + the detail column (right, `1fr`), `gap: 24px`. The reused
  `InventoryWindow` manages its OWN inner two-pane (window + sticky examine) and its OWN ≤900px
  collapse — do not fight it; the Banks-tab outer grid just hands it the `1fr` detail column.
- **Tablet/narrow (~640–900px):** the outer panes MAY stay side-by-side if width allows, else the
  detail drops below the list. The window's internal examine collapses below per its own P31 rule.
- **Mobile (< 640px):** the summary header stacks its two totals if needed (both stay visible); the
  list + detail **stack** (list first; selecting a bank reveals/scrolls to the detail — or the list
  collapses to a compact selected-bank header with a "change bank" affordance — planner's
  discretion, simplest path wins, matching `/inventory`). The item-search results reflow like the
  P32 holders table (the four facts — character/where/qty/last-synced — wrap to a stacked line per
  holder). The two-pane grid collapses to one column at the SAME `@media (max-width: 640px)`
  breakpoint (`grid-template-columns: 1fr`). Gutters collapse to 16px (inherited).

### F. The selected-bank detail + the item-search results

This phase has TWO things that render in the right (detail) column / left (results) column:

#### F.1 — Selected-bank detail (BANK-01 / D-04) — the RIGHT column when a bank is pinned

Top-to-bottom, for the selected bank:

1. **Per-bank detail header (D-04):** a small header ABOVE the window — the bank NAME (Heading 20px
   accent) + a meta line `{bank's item value} pp · {bank's platinum} plat` (§Typography "per-bank
   detail header"). Source: the `PerBank[bankName]` slice of `BankValuation` (its `TotalValue`,
   rounded) + that bank toon's own `plat` (from `ListBankToons` — the per-bank platinum). This is
   the per-bank counterpart to the guild-wide §B summary; it lives HERE so the list rows stay clean
   (D-02/D-04). Visual idiom = `/inventory` `.detail-header` + `.detail-meta` (icon omitted — banks
   have no item icon; the header is name + meta only).
2. **The reused `InventoryWindow` (BANK-01 carry-forward):** `<InventoryWindow inventory={bankInv}
   />` — the P31 component, **UNCHANGED**. It renders that bank toon's paperdoll (mostly empty for a
   pure bank — fine, D-11 keeps empty slots) + general grid + the bank-window grid + inline bag
   expand + the hover-preview/click-to-pin examine (with real wiki icons + colored-tile fallback +
   the per-item PigParse price/value in the examine — all free with the reuse). The window is fed by
   the **existing P31 inventory route** for that bank toon (`fetchInventory(bankName)`); the detail
   column runs its own loading/error/no-inventory state machine exactly like `/characters`' window
   column (reuse that machine — `winStatus` + stale-response guard + `StateBlock`).

**Single pinned detail, replace-on-click (carry-forward):** one detail column; selecting a different
bank (list row OR an item-search holder) REPLACES the per-bank header + window. Exactly one bank
shown at a time.

#### F.2 — Item-search results (BANK-03 / D-03) — the LEFT column when a query is active

When the query is non-empty, the left column shows the **item-search results**: which bank(s) hold
each matched item, with qty/slot, scoped to bank holders. This is the **P32 item-rollup pattern
filtered to `is_bank` holders** (the P32 `ItemHolder` already carries `is_bank`).

- **Data source (Claude's-discretion, resolved):** reuse the **P32 `/api/v1/items` rollup** and
  **client-filter each rollup's `holders[]` to `is_bank === true`** (the holder rows already carry
  the flag), dropping any item with zero bank holders; OR a new bank-scoped read endpoint. The
  `banks.ts` pure helper owns the filter + the name-match + the holder grouping (node-tested). Group
  by normalized item name (D-01 / P29 name-join — never raw item_id).
- **Result shape (per matched item):** the item name (group heading — Heading 20px accent, OR a
  compact eyebrow per the planner's density choice) + a list of **holder rows**, one per holding:
  **Character (the bank) · Where (slot label) · Qty (`×{n}`) · Last synced**. This is the P32
  holders-table, reused, scoped to banks. The optional 32px item-icon tile (§Spacing) MAY lead the
  group heading (mirrors the P32 list row) — default is text-only for a tighter results panel.
- **The wiki / PigParse affordances** on each item group (accent wiki link + `↗`, PigParse price)
  carry over from the P32 holders/rollup idiom — OPTIONAL in the results list (the full price/value
  lives in the pinned window's examine once a holder is clicked); planner's discretion to keep them
  for parity.

#### F.3 — The deep-link: item-search holder → bank window (D-03 — the high-value interaction)

Each item-search **holder row** is the deep-link: clicking it **pins THAT bank's window** in the
right detail column (selects the bank = the holder's `char`). Because the holder's `char` IS a bank
toon (the results are `is_bank`-filtered), this stays **within the Banks tab** — it selects the bank
in §F.1, rendering the per-bank header + the reused window for that bank, scrolled/focusable. (This
is the P32 "holder → character window" jump, here kept in-tab as "holder → bank window".)

- **Implementation:** the holder row is a `<button type="button">` (or an `<a href="/banks?b=…">`)
  calling the same `select(bankName)` that the bank-list rows call — `min-height: 44px`, full
  focus-visible + hover treatment, `aria-label="Open {bank}'s window"`. It `encodeURIComponent`s the
  guildie-controlled bank name if it round-trips through a URL/`?b=`. (Unlike P32, which navigated
  cross-tab to `/characters?c=`, this deep-link is **in-tab** — it pins the same Banks-tab detail
  column, no route change.)
- Selecting a holder does NOT clear the query (the user can keep scanning results); it only re-pins
  the right detail. Clearing the query returns the left column to the bank list (§D) with the pinned
  bank still shown on the right.

#### F.4 — Item-search states

- **No matches** → reuse `StateBlock kind="no-results"` → `No matches for "{query}"` (query
  auto-escaped via `{}` — never `{@html}`). Shown in the left column in place of the results.
- **A matched item with zero bank holders** is excluded by construction (it only appears because a
  bank holds it).

### G. Missing / degenerate data

- **Per-bank value/platinum:** real sums, never nullable lookups → render `0 pp` / `0 plat` cleanly
  for a bank with no priced items / no recorded coin. Never "null"/"—".
- **A bank toon with zero inventory rows** (coin-only / freshly flagged / mid-upload) still appears
  in the list (the `PerBank` map is seeded from the bank-toon list — MR-02 in `buildBankValuation`)
  with `0 items`; selecting it shows its per-bank header (its coin still counts) + the reused
  window's "no inventory synced yet" state (D-11, reused from `/characters`).
- **Window-internal missing data** (no icon → colored tile; no wiki stats / no price → examine omits
  the line, never "null") is handled by the reused `InventoryWindow` per P31 D-09 — untouched.

### H. Loading / error / empty states (the data this tab fetches)

This phase fetches: (1) the **bank roster + counts + valuation totals** (the page-level load — one
or two reads composed by `banks.ts` / a bank-scoped endpoint), (2) the **item rollup** for search
(reuse P32 `fetchItems` or a bank-scoped twin), and (3) per selected bank, the **inventory window**
(reuse P31 `fetchInventory`). Reuse `StateBlock` verbatim; mirror the `/inventory` + `/characters`
state machine (`onMount` one-shot load; a 401/403 routes to the `AuthGate` guard via the typed
`Unauthenticated`/`Forbidden`; any other failure → the generic error `StateBlock` + Retry):

- **Page loading** → `StateBlock kind="loading"` ("Loading…").
- **Page empty (no bank/bot characters designated yet)** → `StateBlock kind="empty"` — see
  §Copywriting for the recommended re-word (the existing "No characters yet" copy is acceptable; a
  bank-flavored "No bank characters yet" reads better — there is already a `no-bank-toons` kind +
  copy in `StateBlock` from P15 that can be reused or adapted).
- **Page fetch error** → `StateBlock kind="error"` ("Couldn't load the data" + Retry).
- **Item-search no-results** → `StateBlock kind="no-results"` (`No matches for "{query}"`).
- **Per-bank window load** → the reused window-column state machine (its own loading/error/
  no-inventory `StateBlock`s — reuse `/characters`' `winStatus` logic verbatim).
- **No bank selected** → §I "Pick a bank" prompt (NOT an error).
- **401/403** → handed to the `AuthGate` guard (server-truth re-route) — never a stale view. All
  three reads are **session-gated** (`RequireSession`, login-only since P15 — NOT public, NOT
  officer-only).

### I. The "pick a bank" prompt (D-04 empty detail)

`/characters` `.prompt` block treatment (centered, dimmed, `48px 16px`, Heading + Body):

- **No bank selected (detail column, desktop):** Heading "Pick a bank" + Body "Choose a guild bank
  from the list to see its stored items and value." (≤44ch, `opacity: 0.85`).

## Accessibility Contract (load-bearing — mirror `/inventory` §G)

1. **Bank-list rows are buttons.** Each row is a `<button type="button">` with an accessible name =
   the bank name + the item count (e.g. `aria-label="Guildbank1, 312 items"`). `aria-pressed`
   reflects selection; exactly one pressed when a bank is shown.
2. **Item-search holder rows are buttons/links** with an accessible name naming the destination
   (e.g. `aria-label="Open Guildbank1's window"`); activating pins that bank's window (§F.3).
3. **Keyboard:** every bank-list row + item-search holder row + the search input + any inline
   wiki/PigParse links are Tab-reachable; Enter/Space activates (pin the detail / select the bank).
   The reused window's keyboard behavior (tile pin/open, examine) carries over from P31.
4. **Focus-visible:** every focusable affordance shows `outline: 2px solid var(--accent)` on
   `:focus-visible` (`outline-offset: 2px`, or `-2px` where it would clip a row edge). The
   already-shipped universal treatment; the reused window keeps its own.
5. **44px touch targets:** bank-list rows `min-height: 44px`; item-search holder rows `min-height:
   44px`; the search input `min-height: 44px`; the reused window's tiles already 44px+ (62px).
6. **Color is never the sole signal:** the item count is NUMBER + word (not color); the `bank`/`bot`
   markers are TEXT tags (not color); the selected row carries `aria-pressed` (not only the accent
   border); the summary/per-bank value+platinum are NUMBERS + unit words (not color); the
   `LastSyncedCell` freshness is a dot PLUS a date label.
7. **Selected bank announced:** the selected list row has `aria-pressed="true"`; the per-bank detail
   header's bank-name heading (`<h2>`/`<h3>`) gives screen-reader context for what's pinned.
8. **Reduced motion:** any row-hover/transition + the detail-swap honor the global `@media
   (prefers-reduced-motion: reduce)` rule in app.css (instant); the reused window/`StateBlock`
   shimmer already honors it.
9. **Theme-independence:** all of the above must hold under all 5 themes — verify the accent focus
   ring + selected border + summary/count/value numbers read on Heavy (`#f0d088` on `#1a0e05`) and
   Minimalist (`#b8915c`); both pass; spot-check at build.
10. **The single `{@html}` sink rule (carried, T-31-14 / T-32-07):** the ONLY raw-HTML in this tab
    is `ExaminePanel`'s `composeItemNote` wiki body (already escaped + scheme-allow-listed), reused
    UNCHANGED inside the window. Bank names, item names, and slot labels (all guildie-controllable)
    render via plain `{}` interpolation (Svelte auto-escapes) in the summary header, the bank-list
    rows, the per-bank detail header, and the item-search results. **This phase adds NO new
    `{@html}` sink.** Any bank name that round-trips through `?b=` / a deep-link is
    `encodeURIComponent`'d.
