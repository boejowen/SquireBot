<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| box (sqlite3 .backup) -> Object Storage | The snapshot crosses off-box; Instance Principal auth means no long-lived keys live on the box. |
| Object Storage -> clean box (restore) | The snapshot is trusted (own tenancy, encrypted at rest); restore places it as the live DB. |
| Internet (ship-gate curl) -> live ingest | The real end-to-end authenticated write path over TLS (all the boundaries from 11-05/11-06 combined). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.07-01 | Information Disclosure | Backups at rest expose guild data | mitigate | OCI Object Storage encrypts at rest by default; the bucket is scoped to the tenancy via the Dynamic Group policy; gzip + (optional) client-side encrypt noted as a stricter option (V6 / RESEARCH V-table). |
| T-11.07-02 | Spoofing | Stored API keys on the box leak and grant bucket access | mitigate | Instance Principal auth (`--auth instance_principal`) means NO stored keys/secrets on the box - the box authenticates as itself via the Dynamic Group; nothing to leak or rotate. |
| T-11.07-03 | Tampering / Data loss | A corrupt or incomplete backup (raw WAL copy) fails to restore | mitigate | `sqlite3 .backup` (online backup API) produces a single consistent file including WAL contents; NEVER `cp` the live .db (Pitfall 6); the restore drill PROVES the snapshot reconstitutes (tables + rows present). |
| T-11.07-04 | Repudiation / Data loss | Backups silently stop and no one notices until a disaster | accept | The cron logs to `/var/log/squirebot-backup.log`; at 12 users a weekly eyeball is sufficient. Automated backup-freshness alerting is deferred (Litestream/monitoring is a future upgrade per D-11). Low risk. |
| T-11.07-05 | Spoofing / Elevation | The ship-gate smoke proves an UNAUTHENTICATED write is blocked over the real wire | mitigate | The negative check (no Authorization header -> 401, writes nothing) is an explicit ship-gate step, validating BACKEND-04 / V2 end-to-end over TLS, not just in unit tests. |

ASVS L1 coverage in this plan: V6 (encrypted-at-rest backups, no stored keys), and an end-to-end validation of V2 (401-writes-nothing over the wire) via the ship-gate negative check. The full register lives across 11-03/04/05/06; this plan closes the loop on the real box.
