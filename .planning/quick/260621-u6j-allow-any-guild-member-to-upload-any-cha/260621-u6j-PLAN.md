# Quick Task 260621-u6j — Drop the cross-owner write reject

## Why (locked decision reversal — ratified by the user 2026-06-21)

SquireBot's backend enforced **one owner per character, first-uploader-wins, reject
everyone else** (`bindCharacter`, the v2 "tightened" D-07/V4 decision). This breaks a
guild that **shares characters** (shared P99 logins) and runs **guild banks with no real
owner**: the second guildie to upload a character someone else uploaded first gets a
409 `cross_owner_reject` (root cause of both the Kim/Aenriel and lern41/Findom incidents).

**User-ratified model (AskUserQuestion 2026-06-21):**
- **Q1 = "Any member can upload":** drop the cross-owner reject entirely. Any valid
  (non-revoked) guild code may upload ANY character. Keep the first uploader as a
  NON-binding `owner_id` record + a light audit trail. Accept the trade-off (no
  anti-overwrite guard) — this is a trusted ~12-person guild.
- **Q2 = "Defer" banks:** do NOT make banks owner-less now (no schema change); the
  relaxation already unblocks Findom. (Owner-less/eviction-safe banks = a later follow-up.)

This is **backend-only** and **migration-free** — deploying it fixes every guildie at
once (including those on watcher 2.1.1); no watcher release is required.

## Constraints

- NO migration (logic only). NO schema change. NO `v*` tag.
- `commit_docs:false` — commit ONLY code (`internal/`) in the task commits; the
  orchestrator commits `.planning/` docs afterward.
- Keep all V7 rules (never log token/content). Keep the single-tx bind+replace shape.
- Gates: `go build ./...` + `go test ./internal/backendsrv/... ./internal/app/...` green.
